# Pin8 prim arrival on two viewer circuits

Two local test accounts received the same eight parts from the [Q65b SQLite scene](../prim-updates/README.md). Each viewer recorded its own full and terse datagrams, and the throttle requests it sent. Before redaction, the harness matched every recorded datagram byte for byte and by direction against the C# socket capture, including how many copies the server sent. Two circuits can receive identical bytes and sequence numbers.

Both Pin8 runs delivered the linked root before its child. At 512,000 bit/s Task, the eight initial parts arrived in two datagrams of six and two. At 8,000 bit/s, the limited viewer received one part per datagram. After Task was restored, the outstanding parts arrived in about 20 ms. The six other channel requests stayed byte-identical, and both groups fit the default Pin8 client ceiling.

Part order and avatar terse grouping varied between runs. Q65c2 and Q65c3 should check link order and the observed throttle and batching behaviour without requiring the exact sequence in one recording. [arrival.txt](arrival.txt) describes run 26016-504649. Each line gives the time on the viewer's own monotonic clock, sequence, flags, redacted datagram length and SHA-256. Part entries show the Q65b alias, region local ID, parent local ID and whether this is a first or repeat delivery. The [control](control.cap) and [limited](limited.cap) recordings retain the packet boundaries.

## Reproduce

Run `cargo xtask live run prim-arrival grid --physics basicphysics` after the Pin8 live build. The home region reopens a copy of the scene with `SupportViewerObjectsCache=false`. The control account stays online and moves while the second account receives the same scene. The bot restores Task after observing partial delivery for at least 300 ms. Both sockets record full and terse updates, including resends, through the limited viewer's logout. The extractor accounts for every full and terse server send between the control viewer's UseCircuitCode and the limited viewer's LogoutRequest. The command reports the scratch output directory.

The reference is Tranquillity `c401bceecd1684832ae8ba86a31b5ee01a4ded7b`. `ScenePresence.SendInitialData` requests the initial objects. `SceneObjectGroup.SendFullAnimUpdateToClient` queues the root followed by its linked parts. In `LLClientView.ProcessEntityUpdates` (4996–5431), C# budgets the dequeue, splits on the zero encoder's position and sends the full datagrams on Task. `LLUDPClient.SetThrottles` reads Task from bytes 16–19 of the request and clamps its rate to at least 1,000 bytes/s.

The capture files preserve directions, relative times, headers and block membership. Each original datagram must also re-encode byte-for-byte before redaction. The extractor aliases prim and owner UUIDs with the Q65b map, retains only identity and parent fields for full avatars, clears terse texture entries, and removes the session UUID and circuit code from throttle requests. Local IDs are the region's actual counters for this run. Replay with `cargo test -p xtask grid::prim_arrival`. The replay tests detect a single changed CRC byte, a part moved across a packet boundary and a missing receipt for a repeated send.
