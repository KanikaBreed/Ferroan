# Avatars capture

`avatars.cap` is the home region's UDP from one `cargo xtask live run avatars grid` at pin `c401bceecd`, on a scratch build with the capture patch, re-recorded for Q47 when the scenario gained the walk. The run printed `avatars: pass (each bot saw the other's local id, appearance and minimap dot; the dot followed a walk; KillObject and no dot on leave)` and `minimap: the owner saw the second bot's dot at 131,128 132,128`. The raw file passed `ferroan-capture check` (258 records) and was then `ferroan-capture redact`ed: session and circuit ids are the placeholders, names are `Redacted`, and the sound `OwnerID` of each avatar block is the agent placeholder ([CAPTURES.md](../../docs/CAPTURES.md)). Redaction also puts the agent placeholder in each `CoarseLocationUpdate` `AgentID`, so the minimap lists keep their counts, `You` and `Prey` but not which account is which. The avatars' full ids and the appearance sender ids are the harness accounts' fixed ids (`ESTATE_OWNER` and `CHAT_USER` in `xtask/src/live.rs`). The raw file is not stored.

It holds, in order: the owner's arrival, its own full avatar `ObjectUpdate` (local id 1008931089), `AvatarAppearance` and `AvatarAnimation`; the second bot's arrival and its full update (local id 1008931090) and appearance on both circuits (`CompleteMovement`); the second bot's full update and appearance again on the owner's circuit, when the owner's `SendInitialData` ran after the second bot had arrived; the owner's full update and appearance on the second bot's circuit at its `SendInitialData`; the second bot walking east from 128,128 for 2.5 m under forward control and stopping, with its terse updates on both circuits; the two logouts; and `KillObject` for the second bot on the owner's circuit. C#'s kill to the leaving viewer after its `LogoutReply` (TB87) is in none of the four recordings made with the walk. Full updates and appearances are reliable and zero-coded. The kill is reliable and not zero-coded. The five `CoarseLocationUpdate` lists, one to each viewer every 50 frames (the shipped `UpdateCoarseLocationsEveryNFrames`), are unreliable and unencoded: both avatars to each viewer (`You` 0 and 1, `Prey` -1) with the owner at 127,128,6 and the walker at 131,128,6, the same at 132,128,6 after the stop, and the owner alone (`You` 0) after the second bot left. The owner's X is 127 because it was pushed 2 cm west (127.98) by the newcomer stacked on it. The second bot arrives about two metres above the owner: `MakeRootAgent`'s landing ray cast (`ScenePresence.cs` lines 1543–1602, with `PrimsNonPhantomAgents` on ubODE) hits the owner's capsule and stacks the newcomer on it. Ferroan's walking stand-in has no ray cast, so the compare masks Z: relative Z is that missing avatar ray cast (a physics gap), and absolute Z is the missing terrain row in the Ferroan home store. Once physics has landed an avatar, C# writes its collision plane into later full updates.

`cargo xtask live run avatars grid --region ferroan` compares the Ferroan run with this file (`xtask/src/avatars_capture.rs`), and `the_csharp_capture_has_both_avatars_and_the_kill` checks the file itself. The minimap compare requires the same headers, agent counts, `You` and `Prey` with the location bytes masked, every dot on row 128, the owner at X 127 or 128, and the walker's last cell at least two east of 128. The count of lists and their Z (0 on the Ferroan home store, which has no terrain row) are not compared.

## Names capture

`names.cap` is the home region's UDP from a later `cargo xtask live run avatars grid` at the same pin and with the same capture patch, after the scenario gained its `UUIDNameRequest` step (Q84). The run printed `avatars: pass (each bot saw the other's local id and appearance and got its name; the unknown id got no reply; KillObject on leave)`. The raw file passed `ferroan-capture check` (151 records) and was then redacted the same way: the names in each `UUIDNameReply` are `Redacted`, except the reply for the unknown id, whose `Unknown` and id the redactor keeps because they name nobody (TB89). It was recorded before Q47 added the walk, so it holds the Q48 run (arrivals, full updates, appearances, logouts, the kill) and, before the second bot leaves: one `UUIDNameRequest` from each bot for the other and for `UNKNOWN_NAME_ID` (`tools/bot/src/scenario.rs`); one `UUIDNameReply` naming each bot, reliable and not zero-coded, one block each; no reply for the unknown id; and, after the owner asks for the unknown id again, one reply for it (C# answers `Unknown` and the id from the miss it cached). Like the walk recordings, it has no kill to the leaving viewer after its `LogoutReply` (TB87 races the circuit's close). The avatar and minimap compares read `avatars.cap`; only the name compare reads this file. `the_csharp_capture_names_each_bot_and_the_cached_miss` checks this file. Record it the way `avatars.cap` is recorded, redacting into `fixtures/avatars/names.cap`.

To record it again, under the live lock with a free port base:

```
FERROAN_LIVE_PORT_BASE=24800 cargo xtask live run avatars grid
cargo run -p ferroan-capture -- check .scratch/live/runs/<base>-<pid>/grid/capture-udp.cap
cargo run -p ferroan-capture -- redact --in .scratch/live/runs/<base>-<pid>/grid/capture-udp.cap --out fixtures/avatars/avatars.cap
```

Read the redacted file before committing it.
