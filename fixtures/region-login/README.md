# Region login control-plane fixtures

These are request/reply exchanges captured from the local C# test grid at
Tranquillity revision `f67db54399c027fd74e5aefcb2193905b4dc1646`. They cover
GridService registration and deregistration, SimulationService QueryAccess and
CreateAgent. `exchanges.json` also retains the method, path, status, content types
and request and response compression headers. The individual files are used by the region
crate's byte and HTTP tests. JSON bodies are decoded and serialized as compact
JSON; XML response bytes and form field order are preserved.

[manifest.json](manifest.json) records the pin and the matching captured C#
arrival channel used to validate provenance before extraction. The four
normalized exchanges were recaptured for Pin3 and remain byte-identical to
their earlier versions.

Regenerate with the pinned reference and the .NET SDK available:

```sh
cargo xtask live run login grid
cargo xtask live login-fixtures .scratch/live/grid
```

The login scenario sets `[Map] GenerateMaptiles=false` and a nil
`MaptileStaticUUID` for both C# and Rust regions. This follows `Scene.cs`'s
existing static-map path; registration therefore advertises nil map asset UUIDs.
Other scenarios keep the normal map generation settings.

The generator substitutes the local test account and region names, agent and
region UUIDs, loopback endpoints and selected port. Generated region secrets,
session UUIDs, CAPS path UUIDs, circuit codes and wearable inventory item UUIDs
receive deterministic placeholders. Repeated wearable item IDs retain the same
placeholder. Fixed wearable **asset** UUIDs, map UUIDs, protocol versions,
coordinates, flags, appearance bytes and all other payload fields are retained.
The device hashes are the bot's fixed test values. No passwords or raw captures
are stored here. HTTP dates and transport headers are outside the compared
envelope; compression headers remain in it. The C# CreateAgent request
uses `X-Content-Encoding: gzip`.

The additional deregistration fixture comes from the neighbouring C# test
region. The home shutdown overlapped an unrelated HTTP request, so its response
could not be paired safely in the capture format. The neighbour uses the same
GridServicesConnector method and differs only in its normalized region UUID.
The generator selects only a request with no earlier outstanding request and an
immediately following response. The Rust live comparison requires its own home
region's unambiguous deregistration exchange.

The observed behavior comes from these files under `Source/` at the revision
above:

- `OpenSim.Services.Connectors/Grid/GridServicesConnector.cs`
- `OpenSim.Server.Handlers/Grid/GridServerPostHandler.cs`
- `OpenSim.Services.Connectors/Simulation/SimulationServiceConnector.cs`
- `OpenSim.Server.Handlers/Simulation/AgentHandlers.cs`
- `OpenSim.Region.Framework/Scenes/Scene.cs`
- `OpenSim.Framework/RegionInfo.cs`
- `OpenSim.Services.UserAccountService/UserAccountService.cs` (new account
  wearable inventory item UUIDs are generated with `UUID.Random()`)

Run the Rust comparison with:

```sh
cargo xtask live run login grid --region ferroan
```

That run requires a real `LogoutReply` and compares all four sanitized exchanges
against this baseline. Captures are generated by a C# server; they are not a
round trip through the Rust encoder. Viewer validation remains pending.
