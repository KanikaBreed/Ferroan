# ferroan-region

This first region process logs a bot in through C# Robust. It reads Tranquillity's region configuration using `ferroan-config`, registers with the grid service, accepts `QUERYACCESS` and `POST /agent/...` simulation requests, and serves one LLUDP circuit and its seed capability. Robust remains the viewer's login server. The HTTP listener sets `TCP_NODELAY` on every accepted socket. SIGTERM or Ctrl-C deregisters the region before closing its HTTP listener.

Each accepted circuit waits for its own agent’s previous generation to finish UDP, scene and grid cleanup. Per-agent lifecycle locks allow different agents to verify in parallel, a timing-only difference from Pin8's `m_newUserConnLock` around all `NewUserConnection` calls (`Scene.cs` 4316–4380). The dispatcher reaps completed tasks while idle and drains accepted generations on shutdown. Verification and serving share 122 slots, with at most 61 child places and at most 61 overlapping generations across agents. The UDP listener holds 61 early login endpoints and 128 queued datagrams per circuit. Refusals and drops are counted under the dispatch and UDP [limits](../../docs/LIMITS.md). Each avatar takes its local object ID from the region allocator before sending its first update.

For an outbound teleport, `SimulationClient` asks the neighbour for access with the circuit's `HomeURI`. It sends a gzip child `CreateAgent` POST with the service URLs, falling back to plain JSON on a transport failure, an unsuccessful HTTP status or a literal `false` reply. At simulation service 0.8 the subsequent `AgentData` PUT is gzip. It carries the frame's always-run setting and the avatar's default, implicit and additional animations from the arrival snapshot until P2.3b. A fresh login starts with STAND, sequence 1. Later arrivals use the animations from the last inbound `AgentData`. The connector can encode an active group for a crossing and the viewer god level when enabled. Pin8 ordinary teleports omit the group fields, and the current region leaves the viewer god UI off. A remote child is closed with `DELETE`. Request and reply bodies each have a 1 MiB limit. HTTP failure reasons include the response status and reason phrase. A transport failure gives the viewer a fixed reason (D74).

Full-region admission uses the configured `DefaultPermissionsModule`. By default, startup requires every name in `permissionmodules` to be available. Ferroan accepts `DefaultPermissionsModule` and `PrimLimitsModule` for this check (D75). A typo or a required module disabled by `[Modules] Setup_<name> = disabled` stops startup. Once started, an ordinary authenticated agent qualifies for one of the 21 extra places when `serverside_object_permissions = false` or when no default handler is attached. The latter occurs with `PrimLimitsModule` alone or with a missing default handler under `[Startup] SecurePermissionsLoading = false`. With normal checks enabled, estate staff and configured grid gods qualify. CreateAgent has one 25-second budget for the account lookup, lifecycle lock and Presence verification. Cached account levels last one hour for local users and 48 hours for foreign users, with five-minute expiry sweeps.

Local chat begins when the viewer opens its UDP circuit with a valid `UseCircuitCode`. On channel 0, whispers, says and shouts reach 10, 20 and 100 metres respectively. Avatar chat on `DEBUG_CHANNEL` (2147483647) reaches connected viewers across the region as chat type 6.

After a valid `CompleteAgentMovement`, the region sends one reliable `AgentMovementComplete` with the accepted agent/session IDs, `CreateAgent` start position clamped in X/Y as C# does, configured region handle, current Unix timestamp and `RegionConfig.channel_version` (initially `Ferroan` plus the package version). With no camera or velocity update yet, the look direction is C#'s `(0.99, 0.042, 0)` fallback. When a heightmap is loaded, Z is the terrain height. After that arrival the region sends one reliable avatar `ObjectUpdate` and one `AvatarAppearance` with no bake block. `[AvatarService] AvatarServerURI` supplies visual params and height through `getavatar`; an empty URI or a failed call uses the constructor defaults. Animations, parcel data, god state, attachment rez and friend notifications from the rest of `CompleteMovement` remain later tasks.

The heightmap comes from the region store that also holds the prims and region settings (`[SimulationDataStore]` over `[DatabaseService]`, as C#'s `SimulationDataService` picks it): SQLite, MySQL or PostgreSQL by `StorageProvider`. It is taken as `Scene.LoadWorldMap` takes it: the `terrain` row; with none, the `bakedterrain` row, stored back as `terrain`; with neither, `[Terrain] InitialTerrain` (`pinhead-island` unless the value is exactly `flat`), stored as `terrain`. When the store had no `bakedterrain` row, the heightmap is stored as that row too. Both rows are revision 23 (gzip), which C# loads on each backend. A SQLite file that does not exist runs the initial terrain without writing it, since Ferroan does not create or migrate a region store. No region store runs without a heightmap. On MySQL and PostgreSQL a NULL cell is no row, as C# reads it there, so the initial terrain replaces it. A damaged `terrain` or `bakedterrain` row stops startup and writes nothing (D72): C# loads a damaged blob as a zeroed or partial map (`TerrainData.cs` 496, 759–765, 822–828, 586–589), keeps the baked row, and copies it into `terrain` when that row is missing; only a NULL cell (SQLite; MySQL and PostgreSQL read it as no map), a NULL revision, an out-of-range revision or a truncated Compressed2D blob (671–713) throws, is logged and is overwritten (`Scene.cs` 2324–2328, 2380–2384) (TB88). A failed write stops startup too, on every backend (D72). On SQLite and PostgreSQL, C# swallows a failed `StoreTerrain` (inside the `try`, `Scene.cs` 2340 and 2353, caught at 2375–2379), but `StoreBakedTerrain` (2383) is outside it and fails region start, so only the case that copies the baked row into `terrain` differs. On MySQL both stores run in `Util.FireAndForget` (`MySQLSimulationData.cs` 506 and 554; the inner `try` logs at 542 and 590, and the wrapper catches everything, `Util.cs` 3397), so C# starts whatever the writes do.

Run the local compatibility check with:

```sh
cargo xtask live run login grid --region ferroan
```

The harness starts C# Robust and a C# neighbour, using the Ferroan process for the home region. Readiness requires the current circuit's handshake, seed and fresh reliable `AgentMovementComplete`; logout requires a real `LogoutReply`. It polls GridUser and Presence until both show the user offline, then repeats login/logout and the service-state checks. Registration and admission exchanges, six refusal/version probes, and captured logout service forms provide C# evidence. See [the harness guide](../../docs/LIVE.md).

The process accepts `--inimaster FILE`, `--inifile FILE`, `--inidirectory DIR` and `--background`. Paths and includes are resolved from its working directory as the region loader does. Every `*.ini` in `regionload_regionsdir` is read; exactly one region in total is required, and XML region files are refused. The harness supplies the normal `RegionServer.ini` and `Regions.ini` files and copies the reference defaults into the working directory. `[Startup]` takes precedence over `[Map]` for map-generation settings. Effective `AuthType` values other than `None` are refused at startup; Basic authentication is not implemented.

Current limits: the region size comes from the INI, and several roots can be logged in, up to the root-agent bound. A new login for the same agent replaces its old circuit and CAPS. Full or closed dispatch queues preserve the current login. The circuit has no fixed lifetime: C#'s inactivity rule applies to received traffic, with a default 60-second silence timeout or 300 seconds while paused. Simulation bodies are limited to 1 MiB before and after gzip decompression. Agent creation requires a trusted source, no viewer shard header, and a Presence session belonging to the agent. A source hop asks the neighbour `QueryAccess`, posts a child `CreateAgent` that carries the login viewer, channel, mac, id0 and appearance, puts `AgentData` whose region id is this region, and queues `TeleportFinish` with the destination origin handle. An in-view neighbour stays open until this root logs out. A hop outside the view waits for the destination release, then closes the agent here. `DELETE /agent/{id}/{region}/` with that session's auth closes the agent. A neighbour `serverIP` that is a DNS name is resolved for at most two seconds, and an IPv4 answer is preferred. Estate authorization remains planned. It does not serve `login_to_simulator`. Startup loads every stored object for the region id from the `SimulationDataStore` or `DatabaseService` connection chosen by `StorageProvider` (SQLite, MySQL or PostgreSQL), keeps the groups, and logs the object count, the prim count and the load time. MySQL and PostgreSQL region settings stay at the handshake defaults; their terrain rows are read and written as on SQLite. The caps are `region.objects`, `region.linkset-prims` and `object.task-items` in [docs/LIMITS.md](../../docs/LIMITS.md). Walking uses the stored movement intent. It does send terrain layers and the arriving avatar's `ObjectUpdate` and `AvatarAppearance`. The seed advertises `EventQueueGet`, and when the client asks for them, the inventory and asset fetch capabilities configured under `[ClientStack.LindenCaps]`. An empty poll waits 58 seconds before returning 502, as Tranquillity does. Leaving the region closes the queue.

Trust settings follow the fixed `ControlPlaneAccess.Authorize` at Pin3: loopback (including IPv4-mapped IPv6), both `ControlPlaneTrustedHosts` and `TrustedControlPlaneHosts` lists from both `[Security]` and `[Network]`, and `[Network] hostname`. Address literals are parsed first; URI parsing uses only a nonempty host, followed by bracketed addresses and host:port forms. IPv6 interface zones do not affect address comparison. Unusable entries produce warnings without exposing their text or resolving an empty name. Hostnames resolve before listening and refresh on an untrusted request at most once a minute, retaining each name's previous addresses when its lookup fails. Resource bounds and the proposed approval of this fixed behavior are recorded in [D20](../../docs/DECISIONS.md). This is the general simulation POST policy; mutation-only routes remain planned.

`[PresenceService] PresenceServerURI` and `[GridUserService] GridUserServerURI` are required. Startup calls GridUser `loggedoutregion`; an older Robust's refusal is nonfatal. Termination of a root that is still the root, including `CloseAgent` for that root, attempts both GridUser `loggedout` and Presence `logout`, with bounded requests and visible errors. A far hop, a demoted child and a fresh child that never became root leave Presence where it is. A failed notification does not stop the other handler, circuit removal or subsequent logins. Generation checks prevent stale cleanup from marking a replacement offline; the old session's Presence is removed unless the replacement reuses it. Root logout reports where the frame last had the avatar (walked, landed or the login position) and `Lookat`, the last camera at axis with Z dropped and normalised (zero before any camera update, or when the camera looks straight up or down); the arrival packet's look fallback does not represent persisted heading.

`[Startup] LoginConnectWaitSeconds` defaults to 120. A pending ViaLogin circuit must receive a valid `UseCircuitCode` before that deadline. Once connected, ordinary inactivity handling applies while the watcher waits for root arrival or removal. A ViaLogin session that never became root is a failed login when the wait is non-zero: it first checks the exact Presence session, then removes it and clears GridUser online state while preserving its previous last region, position and look direction. A child that is not ViaLogin is not a failed login. A later login's missing old session prevents stale GridUser cleanup. Zero disables this watcher, matching the legacy setting; an unopened login then has no connection deadline.

The first validated root transition calls Presence `ReportAgent(session, region)` and GridUser `SetLastPosition` before sending `AgentMovementComplete`, as C#'s root-event detectors do. Both bounded service calls are attempted once for that generation; failures remain visible and do not turn C#'s nonfatal detector notifications into a login refusal. UDP receives, ACKs, pings, retries and inactivity handling continue while the reports are pending. Replacement and shutdown wait for in-flight writes before cleanup so that stale reports cannot overwrite replacement or offline state. Duplicate movement requests do not repeat the notifications. The service position is the accepted region position; terrain-adjusted Z remains P2.0e. Stored look direction remains zero until scene movement exists, independently of the arrival packet's fallback direction.

The live login probe reads Robust while the bot is online. It checks Presence's region and GridUser's online state, last region and position against that client's observed arrival, for both C# and Ferroan. Captured C# request forms separately prove the connector fields and serialization. This distinguishes active location reporting from the existing offline and second-login checks.

`RegionHandshake` takes the name and `RegionType` from the region INI and the estate owner from the server configuration. SQLite settings supply maturity-based access, flags, terrain textures, elevations, water height and the persistent cache UUID. First open of a region in an existing SQLite store initializes its settings. An empty PBR set inherits all four classic textures. Other providers and a missing file use fresh-region handshake defaults. The region sends queued ACKs every 500 ms or after receiving over two MTUs of reliable data. Up to 256 reliable sends remain queued until acknowledged or the circuit times out, without a retry-count cutoff.

Retransmission checks run every 100 ms. The initial RTO is 1000 ms; server pings run every five seconds. A measured ping updates `p = int(0.8 * previous + 0.2 * elapsed_ms)`, initially 20 ms, and uses five times that value with C#'s 250 ms minimum and default 3000 ms maximum. No exponential backoff or ACK-based RTT sampling is added. `[ClientStack.LindenUDP] DefaultRTO` and `MaxRTO` are milliseconds (zero selects their defaults); `AckTimeout` and `PausedAckTimeout` are seconds. Invalid negative/zero inactivity or signed-millisecond-overflow values are refused. An unsolicited ping completion before any server ping has no measured RTT and leaves the initial estimate unchanged, rather than deriving an RTT from C#'s zero-initialized timestamp.

Ordinary logout does not add `KickUser` or `DisableSimulator`. Inactivity and a re-login send reliable `DisableSimulator` to the mapped endpoint. Region shutdown sends `KickUser` with target address 0, port 0 and the reason "The simulator is going down.", then `DisableSimulator`. The captured kick remains the historical shutdown notice; its loopback address is not what the pin writes. A root that leaves is killed with `KillObject` on every remaining viewer, not on its own (D70). Unacked “oldest” selection remains the smallest numeric sequence, matching the pinned C# `SortedDictionary` even across wraparound, and a ping keeps the last such value after the window empties. Ack timeout starts when `UseCircuitCode` maps the viewer, not when serving starts.

The event queue permits four simultaneous polls, 256 queued events and 1 MiB of queued XML. Individual events are limited to 64 KiB, 4096 values and 32 levels of nesting. Excess polls return 503; event producers receive a structured error when a bound is reached. Seed and poll request bodies are limited to 64 KiB. Region event producers remain planned; the generic queue can already deliver batches with the captured C# encoding.

For this login comparison, both C# and Rust disable map generation (`[Map] GenerateMaptiles = false`) and use a zero static map UUID, which is a supported C# configuration. Registration then advertises zero map image IDs without fabricating map assets. TLS listeners, variable-size regions and interactive configuration are refused. This is a local test region; viewer validation remains a separate maintainer gate.
