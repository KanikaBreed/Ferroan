# ferroan-services

Grid services. This crate holds the asset service and the user-account service, including user aliases. `ferroan-robust` mounts a service only when its ini section is present.

The avatar service exposes `get_appearance` and `set_appearance` over the configured avatar store. An empty record yields the constructor outfit. A nonempty record restores missing body parts, reads legacy item/asset pairs and applies indexed layers in numeric order. Malformed appearance rows return `Ok(None)`; store and size errors propagate to the caller. Attachment rows retain item order within each point and omit asset IDs. Heights are written with a decimal point and read with either decimal separator (TB44).

The XBakes file cache serves GET and POST at `/bakes/<id>`. It preserves the region's upload bytes at `BaseDirectory/id[0..2]/id[2..4]/id[4..6]/id[6..10]/id`. A missing file returns an empty 200. A replacement publishes one complete file, and `delete bakes <ID>` removes it. The cache is independent of the avatar database and the asset service. [Pin8 HTTP and file observations](../../fixtures/avatar/bakes.json)

The asset service is what a Tranquillity region calls on Robust.

The routes follow `Source/OpenSim.Server.Handlers/Asset/` at Tranquillity `713857f10b8e91a639a967d4354a4682b080793c`:

| Method and path | What it does | Content type |
| --- | --- | --- |
| `GET /assets/{id}` | `AssetBase` XML, or 404 | `text/xml` |
| `GET /assets/{id}/data` | raw bytes, or 404 | `application/octet-stream` |
| `GET /assets/{id}/metadata` | `AssetMetadata` XML, or 404 | the asset type's content type |
| `POST /assets` and `POST /assets/` | store, and return the id string | `application/xml` |
| `POST /assets/{id}` | `UpdateContent`, which returns false | `application/xml` |
| `DELETE /assets/{id}` | delete when the config allows it, and return a bool | `application/xml` |
| `POST /get_assets_exist` | one bool per id | `application/xml` |

`POST`, `DELETE` and exists keep the stream-handler default `application/xml`. GET of the whole asset sets `text/xml`. A missing asset is 404 with an empty `text/plain` body. `RedirectURL`, when set, turns that 404 into 302. The location is the configured text plus the request path, including a double slash when the configured text already ends in `/`.

XML bytes are `ServerUtils.SerializeResult`: UTF-8 BOM, LF, two-space indentation, no newline after the root. The comparisons are `fixtures/asset`, written by `cargo xtask asset`. Flag text is the `[Flags]` names (`Normal`, `Maptile Rewritable`). A value with a bit outside `Normal`, `Maptile`, `Rewritable` and `Collectable` makes `XmlSerializer` throw; Ferroan writes the decimal number so the row can still be fetched. `SHA1` is omitted. `CreationDate` is `0001-01-01T00:00:00`.

## Store

SQLite, MySQL and PostgreSQL, on a database Tranquillity already migrated: AssetStore version 6, 10 or 9. This crate does not create the schema and does not run migrations. The HTTP handler still calls `store_new`, which skips a row that already exists. `store_data` is the plugin `StoreAsset` success path: SQLite updates the row, MySQL `REPLACE`s it (and resets both timestamps), and PostgreSQL updates the mutable columns and leaves `asset_flags` and the timestamps alone. PostgreSQL stamps those times with the local clock read as UTC, which is what `PGSQLAssetData` does. Neither `Get` updates `access_time`.

`FetchAssetMetadataSet` is `metadata_set`. SQLite and MySQL return `count` rows from `start` with no `ORDER BY`. PostgreSQL orders by id and uses `LIMIT start+count-1` (TB19). A start past one million, or a count outside 0..=10_000, is refused. HTTP does not add a metadata route.

`AssetService.Store` skips the write when the id exists, so a second store does not change the row. Names and descriptions are cut to 64 UTF-16 code units on insert. A non-BMP character that would be split in half by `Substring` is dropped instead, because a Rust string cannot hold a lone surrogate. Existence checks are parameterised. The C# method concatenates ids after `UUID.Parse`. One id that does not parse makes the whole answer false. Plugin `Delete(string)` on a missing id is true for SQLite and MySQL and false for PostgreSQL. A value that is not a UUID is false for SQLite and PostgreSQL and true for MySQL. The HTTP delete handler still answers from `delete` after it has fetched the row.

`UpdateContent` returns false. Delete is off unless `AllowRemoteDelete` is true, and then only maptiles (`Flags` bit 0) unless `AllowRemoteDeleteAllTypes` is also true. A parsed id answers true after the delete statement even when the row was already gone.

A store document with no `Data` element is 400. C# would insert NULL, and the later get would throw. Region connectors send the bytes.

## Library loader

`DefaultAssetLoader = OpenSim.Framework.AssetLoader.Filesystem.dll` reads `AssetLoaderArgs`, an `AssetSets.xml` path, when the process opens the asset service. An empty name loads nothing. Any other plugin name refuses to start. `AssetLoaderEnabled = false` on the asset section skips the load. Each library asset is stored when its id is new or the SHA1 of its bytes differs. Matching bytes are left in place, including when the name in the set file differs. The library owner is `11111111-1111-0000-0000-000100bba000`, the description is empty, and local, temporary and flags are false, false and 0.

A repeated section name keeps the first section. Nini calls `Configs.Add` before it loads that section's keys, and `Add` leaves the existing `IConfig` in place, so the later section is dropped. `TexturesAssetSet.xml` repeats `Cypress 1` with the same id; one row is stored. A duplicate key is `ArgumentException` and fails the load before any row is written. A missing named file fails the same way: `FileInfo.Length` throws `FileNotFoundException` before the exists check, so the C# log line for a missing file does not run. An empty `fileName` stores empty bytes. A set file that is not XML is skipped. A control file that is missing or not XML loads nothing. A bad `assetID` or `assetType` fails the load before any row is written. `assetType` is the C# `(sbyte)` cast, so `128` is `-128` and surrounding whitespace and a leading `+` are accepted.

C# loads the sets once per process, on `m_RootInstance`. This process loads them on every open. A second open leaves rows whose SHA1 still matches.

The caps are `asset.loader-files` (10,000), `asset.loader-file-bytes` (2 MiB) and `asset.loader-total-bytes` (32 MiB). The library set at the pin is 455 files and about 13 MiB. The region library caps are a different loader.

`show_asset`, `dump_asset` and `delete_asset` return the connector's text, including the flag line, the five hex rows and the two spaces in the dump-already-exists message. Wiring them to the remote console is still pending.

## XAssetService

`LocalServiceModule` containing `XAssetService` selects `XAssetStore` on MySQL or PostgreSQL and serves the routes above. SQLite has no XAsset plugin. `Store` skips `StoreAsset` when `AssetsExist` is true and still returns the id. Both databases read the XAsset metadata table (TB28's C# query reads `assets`; nothing depends on that miss). A chained migrate therefore stores the XAsset row and then deletes the chain row, so the asset remains (TB33). A store that rolls back still returns success. The migrate reads the asset back first and leaves the chain row when that read misses, and this get still returns the chained asset (TB59, D43). Two stores of the same bytes both keep their ids: MySQL checks the hash before its write transaction and accepts only duplicate-key error 1062 on a plain data insert and PostgreSQL uses `ON CONFLICT (hash) DO NOTHING`. A hash-lookup error is returned (TB58, D43). `ChainedServiceModule` names `AssetService` on the same connection string. Any other designator refuses to start. `Delete` calls the chain first. PostgreSQL binds the id as `uuid` and deletes only the meta row (TB30). MySQL delete removes only the meta row. The data row stays on both databases. A plugin error is still HTTP 500 with an empty body. The stock asset service still answers 200 and a bool.

`DefaultAssetLoader` is consulted only when a chain is set. `ForEachDefaultXmlAsset` runs only when the loader is set and no chain is set, so this service does not seed the library and does not read `AssetLoaderArgs`. An unknown loader name fails only when a chain is set. PostgreSQL metadata uses `LIMIT` count `OFFSET` start and returns the page (TB29). MySQL store runs on the transaction (TB27). `cargo xtask live assets --backend xasset --db mysql` and `--db pgsql` print `assets: match`. Pin8 carries the C# fixes for TB27, TB28, TB29, TB30 and TB33, so that compare does not name them. The MySQL report lists TB58 as a separately tested database race. The HTTP sessions exercise neither this race nor a rolled-back migrate (TB59).

## Not in this pilot

`Migration.Update` is not run. HTTP `POST /assets/{id}` still returns false and does not write. `AuthType = BasicHttpAuthentication` and `https_main = true` refuse to start. `TrustedGridAuthentication` does not reject when no trust context is set, which is this process. `X-SecondLife-Shard` is 403 on get, post and delete unless `AllowllHTTPRequestIn` is true. Exists does not check that header. `POST /auth` and `POST /griduser` refuse the same header the same way. Authorization does not: that C# handler is built without the check.

Bodies larger than 50_000_000 bytes are refused. Tranquillity does not cap `XmlSerializer`.

Ordinary CI compares the committed asset XML and SQLite fixtures in Rust tests. The [Linux live workflow](../../.github/workflows/live.yml) runs the C# asset oracle, compares texture and inventory traffic against both services, and checks a persistent C# region using `ferroan-robust`. The maintainer's Firestorm asset check is recorded under G0 in [TASKS.md](../../TASKS.md).

## Pattern for a Robust service

P1.2 through P1.12 follow the user-account layout.

1. One module directory under `crates/ferroan-services/src/<service>/`: `mod.rs`, `model.rs`, `store.rs`, `service.rs`, `http.rs`, `open.rs`, and `commands.rs` when the C# service registers console commands.
2. The store speaks SQLite through `ferroan_db::Pool` and parameterised sqlx queries. It does not run migrations and it does not keep a shared column-name cache. The asset store and the authentication store also speak MySQL and PostgreSQL. The authentication live compare stays on SQLite. The grid-user store speaks SQLite, MySQL and PostgreSQL and has no HTTP handler. `cargo xtask griduser cross` compares its rows with the pinned plugins. The avatar service serves `getavatar`, `setavatar`, `resetavatar`, `setitems` and `removeitems` on `POST /avatar` over SQLite, MySQL or PostgreSQL. `setavatar` replaces stale appearance rows and keeps omitted names starting with the case-sensitive prefix `Bake`. A refused store clears the appearance while leaving the bake index in place. Explicit item operations address individual names and reset removes every row for the principal. `cargo xtask avatar cross` compares its rows with the pinned plugins. A later service still starts on SQLite.
3. HTTP is a POST of a ServerUtils form. Parse it with `ferroan_http::parse_query_string`. Reply with `ferroan_http::build_xml_response` and content type `application/xml`, except the fixed Failure bytes the handler uses.
4. `ferroan-robust` mounts that router only when the ini section is present. An asset-only ini still starts.
5. `cargo xtask live compare <service>` starts the C# connector and `ferroan-robust` against copies of the same SQLite fixture, sends the same forms, and compares the HTTP after folding fields that are the current time.
6. Add the grid connector mapping before the service is offered. Read the pin, then add one row to the harness: when `--rust` names the service, `ferroan-robust` opens its own SQLite file and C# Robust's consumers use `OpenSim.Services.Connectors` plus the server URI that connector reads. Drop the `ServiceList` entry that would load `LocalServiceModule` for that service. Rewrite the region's `GridCommon.ini` key to the same URI. Do not share the SQLite file with C# Robust, except authentication: `LLLoginService` cannot construct `AuthenticationServicesConnector`, so `--rust auth` shares `auth.db` with `PasswordAuthenticationService`. Record the consumers in the table below. `require_known_services` in `xtask/src/live_args.rs` is the list of names the harness accepts. Add the row's grid scenario to `.github/workflows/live.yml`.

User accounts are that pattern: `src/account/` for `POST /accounts`, `src/alias/` for `POST /useralias`, and `cargo xtask live compare accounts`. The alias table has no SQLite migration in the pin, so the compare covers accounts only. `--rust accounts` is the connector row: login's `[LoginService] UserAccountService` becomes `OpenSim.Services.Connectors.dll:UserAccountServicesConnector`, which reads `[UserAccountService] UserAccountServerURI`, and the harness omits `UserAccountServiceConnector`. The in-process `create user` command is registered by `UserAccountService`, so the harness creates the row with `POST /accounts`, stores the password with `POST /auth/plain` (`AllowSetPassword` on the C# service), and creates the inventory skeleton with `POST /xinventory`. The password is not logged. `--rust auth` is the same shape for `src/auth/`: `POST /auth/plain` and `POST /authorization`, and `cargo xtask live compare auth`. `AuthenticationServicesConnector.SetPassword` returns false at this pin, so the harness posts `setpassword` itself. When authentication is Rust, that post goes to `ferroan-robust`. C# Robust's `[AuthenticationService]` keeps `AuthenticationServerURI` plus a SQLite connection to the same `auth.db`, and `[LoginService] AuthenticationService` stays `PasswordAuthenticationService`. When only accounts are Rust, the post stays on C# Robust.

These are the C# consumers at pin `40432e0`. The harness grid loads only the Robust.ini and `Grid.ini` rows. The other rows are what a later service must retarget before `--rust` can name it. URI keys are the ones the remote connector reads.

## Presence rows

The Presence service loads the configured Null, MySQL or PostgreSQL provider. `[PresenceService]` overrides `[DatabaseService]` for the provider and connection. SQL providers use `[PresenceService] Realm` (default `Presence`). In-process callers use the same configured service as the HTTP handler. Login creates a fresh row with the secure session ID and the provider's default LastSeen. `AllowDuplicatePresences` defaults to false. With duplicates disabled, Ferroan serializes replacement logins for the same user and removes every cached session for that user. Pin8 can process those logins concurrently and clears only the session named by its user cache, so a replaced session can still appear online. Session and user lookups refresh the same cached row for 300 seconds with a 60-second sweep. Evicting a session also removes any user entry pointing to it. The cache mutex covers only in-memory operations. A concurrent report can complete during a GetAgents lookup, and a lookup started before a write cannot refill the cache with stale data. The HTTP login form always answers Failure. `getagents` returns at most one region for each requested user in list order, including repeated IDs.

`presence::PgPresenceData` opens `Presence` by default. Pass `[PresenceService] Realm` to `new` for a different PostgreSQL v4 table. PostgreSQL folds the validated identifier to lowercase as in Pin8. A store with an existing session ID updates the supplied fields. A new session defaults to a zero secure session ID and SQL NULL for LastSeen. The row exposes SQL NULL as an empty string. For a non-null timestamp, Ferroan's `Data["LastSeen"]` holds PostgreSQL ISO text with microsecond precision. Pin8 under Robust gives en-US text without fractional seconds. Q26d must accept the provider's representation and LoginAgent must store a fresh row without LastSeen. Ferroan preserves the fetched value on re-store (TB105, D84). A successful region report stamps the database clock in the session zone.

The service can use `dyn PresenceStore` for all seven asynchronous operations. A store returns `Ok(false)` when it writes nothing. Bound and database errors have distinct variants. After a successful region report the service can call `set_region_id` on its cached row, including a detached row fetched from SQL.

`presence::PresenceData` holds the user ID as text, session and region UUIDs, and the provider's named data fields. Each `NullPresenceData::default()` uses the same process-wide session map. A report updates a held row; storing a replacement by session ID leaves earlier references pointing to the old row. Field lookups and deletes compare user IDs and additional fields exactly. The Null provider accepts a report to the zero region and returns false from agent verification. The [Presence fixture](../../fixtures/presence/README.md) records the Pin8 calls.

`presence::MySqlPresenceData` opens the migrated v4 table `Presence` by default. Pass the validated `[PresenceService] Realm` to `new` for another table. Its field lookups use the table's collation. A report to a nonzero region stamps the database time. A new session can omit both SecureSessionID and LastSeen to use the column defaults. A fetched row carries LastSeen as UTC timestamp text, so replacing that session retains the stored second (TB104, D84).
