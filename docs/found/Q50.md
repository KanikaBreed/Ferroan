# Found while working: Q50

- 26 November 2026, Q50: C# handles `AgentAnimation` on the packet thread and never drops one. Ferroan posts it to the frame on the bounded inbound queue without an answer; a post refused when that queue is full is dropped with the `region.scene-inbound` readout, and the viewer's start or stop is lost. `AgentUpdate` and `SetAlwaysRun` keep their latest refused post on the circuit instead, because only the latest of those matters. Keeping a short queue of refused animation posts would close the gap.
- 26 November 2026, Q50: C# sends one animation pack per change at the moment it happens. The frame sends one pack for each avatar whose animator owes one after each inbound post, each answered call, the avatar step and the heartbeat. Two changes for the same avatar between two of those points (none is possible on the stand-in today) would go out as one pack with the later set.
- 26 November 2026, Q50: `ScenePresence.SendAnimPack` and the arrival loop skip viewers outside a parcel that hides the avatar (`ParcelHideThisAvatar`). Nothing in Ferroan hides an avatar by parcel yet, so every open viewer gets every pack. The same check also gates the full updates, appearances and hiding kills P2.3a sends (`ScenePresence.cs` at Pin8: `SendAnimPack` 4651, `SendAnimPackToAgent` 4613 and 4624, the arrival loop 2512, `SendOtherAgentsAvatarFullToMe` 4429, and the kills in `SendInitialAvatarDataToAllAgents` 4484 and `SendInitialAvatarDataToAgent` 4501). This matters today, not only later: Ferroan already loads each parcel's `SeeAVs` from the land table (`crates/ferroan-scene/src/parcels.rs` line 857) and serves it in the overlay (`crates/ferroan-scene/src/parcels/overlay.rs` line 143), so a region store converted from C# with a `SeeAVs`-off parcel shows every avatar to every viewer where C# hides them.
- 26 November 2026, Q50: the walk fixture (`fixtures/walk/walk.cap`) and the animations fixture hold only animations that name the agent or nothing, so no C# capture shows `SendAnimations`' own-viewer order and `AnimationSourceList` for an animation started by an object. That path is checked against the C# code only (`its_own_viewer_gets_the_object_animations_first_with_their_objects`); a scripted `llStartAnimation` capture would cover it once scripts run.
