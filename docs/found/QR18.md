# Found while working: QR18

- 2026-11-25, QR18 review: CI does not guard the MariaDB and restricted-login cases. `.github/workflows/ci.yml` runs only mysql:8.4 and postgres:16, and nothing sets `FERROAN_XASSET_LIMITED_MYSQL_URL`. The old store (hash lookup inside the transaction plus `INSERT IGNORE`) passes on MySQL 8.4 and fails only on MariaDB 11.8 with `innodb_snapshot_isolation=ON`, so CI would not catch a regression. A `mariadb:11.8` service in checks-linux, with the schema and the restricted login loaded, running `xasset_plugins_match_the_pin` and the restricted test, would.
- 2026-11-25, QR18 review: the PostgreSQL XAsset race test is still the `tokio::join` loop (`crates/ferroan-services/tests/xasset_tests.rs` ~242-268), which passed 23 of 24 runs with the R2 fix reverted. QR18 made only the MySQL race deterministic. A held-transaction race for PostgreSQL (hold a transaction that inserted the hash, wait until the other store shows `wait_event_type = 'Lock'` in `pg_stat_activity`, commit, assert both ids and one data row) would make R2's "both databases" evidence real.
