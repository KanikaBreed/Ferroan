# Found while working: QR13

- 2026-11-25, QR13: The original R13 description said the last duplicate `ID` wins. The Pin8 handler returns the first, including when it is empty. The [captured responses](../../fixtures/auth-edges/cases.json) and the corrected R13 evidence record this.

- 2026-11-25, QR13: The PostgreSQL password-token round trip fails at verification when the service runs in US/Eastern and the database session uses UTC. The same test passes with both in UTC. The web-key conditional update passes in both configurations. `pg_when` writes a local timestamp without a zone and `check_token` compares it with the database clock. Compare a mixed-zone deployment with Pin8 before changing token expiry.
- 2026-11-25, QR13: A concurrent password reset can write a stale web key back. `AuthService::set_password` reads an auth row, changes its password fields, and later stores all four fields. Check the interleaving with key consumption and consider updating just the password columns for an existing row.
