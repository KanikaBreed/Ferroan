# Found while working: Q61b

- 26 November 2026, Q61b: C# stores parcel bounding-box heights when land is loaded, after terrain exists. `LandManagementModule` calls `ForceUpdateLandInfo` at the end of adding a parcel (`LandManagementModule.cs` 818). That calls `UpdateGeometryValues` (`LandObject.cs` 1188–1191, 1203, 1306–1327), which samples `Heightmap[tx, ty]` and `Heightmap[tx - 1, ty - 1]` into the stored vectors. `SendLandProperties` sends those stored vectors (`LLClientView.cs` 6780) and does not sample again. Ferroan samples the heightmap on each encode. Q61c's live compare should use the heights from load time. A later terrain edit does not move the stored vectors until something calls `ForceUpdateLandInfo` again.
- 26 November 2026, Q61b: `CapsServer::enqueue_raw` (`crates/ferroan-client/src/caps.rs`) forwards to that server's queue and has no caller. `CapsRegistry::enqueue_raw` is covered by `enqueue_raw_queues_only_when_one_agent_is_registered`. The server method still needs a poll test, or a decision to drop it, when Q61c wires delivery.
