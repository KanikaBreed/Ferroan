# Found while working on Q65b

- TB93 records oversized binary fields in Pin8 full prim updates. D78 keeps the stored data intact and refuses to emit a malformed block.

- A reopened region store supplies world objects. Worn attachments need the avatar and source inventory item at runtime. `CreateSelected` is one-shot state for the rezzing owner and is cleared on restore. The PBR material-override message is sent separately from the full update block and belongs to Q65c delivery. The capture includes the material IDs that travel inside the full block.

- Q65c must check whether a full block fits in one datagram before batching it. Pin8's `LLUDPZeroEncoder.EnsureRoom` can throw for a texture entry of about 2.7 KB, depending on the current write position. Q65b accepts up to the field's 65,535-byte limit. Splitting a batch cannot make an oversized single block fit. Q65c needs a bounded, reported outcome for that block so later updates can proceed.

- The first extended-mesh seed had scale (0, 0, 0) in SQLite. Its BasicPhysics capture carried (0.001, 0.001, 0.001). At Pin8, `SceneGraph.AddSceneObject` (lines 472–487) applies the region's configured nonphysical scale limits on admission when clamping is enabled. Q65c should apply those settings before building initial blocks. The committed mesh has an explicit scale of 0.5 on each axis.
