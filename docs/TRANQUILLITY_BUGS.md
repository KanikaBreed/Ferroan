# Tranquillity bugs

Bugs found in the C# reference while porting or testing Ferroan. Each one gets a row here, so that a finding is not lost between a note, a fix in Tranquillity and a pin move.

## What happens to a bug

1. **Record it.** Whoever finds it, coder or maintainer, adds a row: the C# file and the pinned revision, what goes wrong, and how it was seen (a fixture, a harness run, a viewer). The coder also puts one line in its item's `docs/found/<item>.md` file, as rule 8 of [WORK_QUEUE.md](../WORK_QUEUE.md) says.
2. **Decide what Ferroan does** ([AGENTS.md](../AGENTS.md) §1). If viewers or other servers depend on the behavior, Ferroan matches it until it is fixed upstream, and says so in the row. Otherwise Ferroan does what the fixed C# would do, and that choice is recorded as a decision in [DECISIONS.md](DECISIONS.md). Ferroan never changes a protocol, schema or file format to work around a bug.
3. **Fix it upstream.** The fix goes to Tranquillity as its own C# change (D7: bug fixes go into both). Ferroan's GPL code is never copied into Tranquillity ([PORTING.md](PORTING.md)). The row records the Tranquillity PR.
4. **Move the pin, then regenerate.** Once the fix is on the recorded reference branch (`develop`, or the maintainer's `dev-build` under D21), a pin move brings it in ([REFERENCES.md](REFERENCES.md)), and every oracle and fixture that touches the fixed code is regenerated against the fixed behavior. A fixture that captured the bug is replaced, not kept beside the new one. Ferroan code that matched the buggy behavior changes to match the fix in the same pin move, and the row moves to **Fixed** with the revision.

## Not a bug

TB61 (24 November 2026, QR3; moved here by QR17). At pin `c401bceecd`, a second NewFileAgentInventory while an upload is still waiting leaves the previous uploader path registered. That path is removed when the upload is posted or when its 120 second timer fires. Each agent has its own uploader. Firestorm and the Linden viewer keep the uploader URL from the mesh fee request and POST it later, including after a texture, sound or snapshot upload. The path staying is the behaviour they depend on. Ferroan keeps every offered path until it is used or the timer fires (D45 withdrawn).
