## 1. What C# does that an operator can see

### 1.1 Processes

A grid is more than one process.

GridServer is one process. `[ServiceList]` in `Source/OpenSim.Server.GridServer/AppData/GridServer.ini.example` (116–160) names each connector as `port/assembly:class`. The lines that are not comments are AssetServiceConnector, XInventoryInConnector, GridServiceConnector, GridInfoServerInConnector, AuthenticationServiceConnector, AvatarServiceConnector, LLLoginServiceInConnector, PresenceServiceConnector, UserAccountServiceConnector, GridUserServiceConnector, AgentPreferencesServiceConnector, FriendsServiceConnector, MapAddServiceConnector, MapGetServiceConnector and MuteListServiceConnector. Commented, so off unless an operator enables them: FreeswitchServerConnector (120), OpenIdServerConnector (125), ExperienceServiceConnector (136), OfflineIMServiceRobustConnector (138), GroupsServiceRobustConnector (140), XBakesConnector (142), AppearanceServerConnector (147), UserProfilesConnector (150), EstateDataRobustConnector (153) and VoiceSessionServerConnector (160). `[Network] port` is the private port (165–166). `[Network] bind_ip_address` empty means every interface (168–171). `[Network] AllowllHTTPRequestIn` defaults false (205–210).

RegionServer is a second process, and a grid runs one or many of them. The shipped architecture include is `config-include/Standalone.ini` (`RegionServer.ini.example` 1607). Grid mode is `config-include/Grid.ini` (1609), which includes `GridCommon.ini` (`Grid.ini` 8) and points the region at remote connectors (`Grid.ini` 11–29): asset, inventory, grid, avatar, authentication, presence, accounts, agent preferences, grid user, simulation, land, map image, search, mute list and experiences. Estate data stays in-process unless `[EstateDataStore] LocalServiceModule` is the remote connector (`GridCommon.ini.example` 120–125). A region file is an INI whose section name is the region name (`Regions/Regions.ini.example` 9–18). `RegionUUID`, `Location`, `InternalAddress`, `InternalPort` and `ExternalHostName` are the identity a viewer and a neighbour see (18–24). Several regions may share one RegionServer process (8).

MoneyServer is a third process. It reads `MoneyServer.ini` (`Source/OpenSim.Server.MoneyServer/Program.cs` 40–45). With no `MoneyServer:AspNetUrls`, it listens on `MoneyServer:AspNetPort`, default 8009 (185–193).

Voice in the shipped grid file is the commented FreeSWITCH connector and the commented WebRTC session connector (GridServer.ini.example 119–120 and 157–160). Janus is the external server [PLAN.md](../PLAN.md) names for Phase 6. It is not a C# process in this tree.

### 1.2 Configuration an operator edits

GridServer's `[DatabaseService]` example enables MySQL (`GridServer.ini.example` 241–254). PostgreSQL is commented (242–246). Region grid mode comments MySQL, PostgreSQL, MSSQL and SQLite and leaves SQLite selected through `Include-Storage` (`GridCommon.ini.example` 4–38). The region defaults file, before that include, sets `[GridService] StorageProvider` to `OpenSim.Data.Null.dll:NullRegionData` (`RegionServerDefaults.ini` 2879–2894). `[AssetService] AssetServerURI`, `[InventoryService] InventoryServerURI` and `[GridService] GridServerURI` are the addresses a region calls, with no trailing slash on the asset URI (`GridCommon.ini.example` 82–108). The same file sets avatar, agent preferences, presence, accounts, aliases, grid user, authentication, friends and estate URIs (137–178). `[Hypergrid] GatekeeperURI` is commented; `HomeURI` is set (40–61). `[Modules] AssetCaching` is `FlotsamAssetCache` (69–74). That cache is not the asset store.

`[Startup] MaxPoolThreads` is 300 in the shipped region defaults (`RegionServerDefaults.ini` 74–76). The reader uses 25 when the key is absent (`OpenSim.cs` 129–130) and 2 for `MinPoolThreads` (129). `async_call_method` is `QueueUserWorkItem` (69–72). `[Startup] physics` is `ubODE` (313). `[Startup] meshing` is `ubODEMeshmerizer` (294). `[Startup] DefaultScriptEngine` is `InWorldz.Phlox` (325). `[Startup] shutdown_console_commands_file` is `shutdown_commands.txt` (55–56), and shutdown runs that file before the region close (`OpenSim.cs` 461–466).

`[ClientStack.LindenUDP]` leaves `scene_throttle_max_bps` commented, and the comment says the default is 0 (`RegionServerDefaults.ini` 815–821). The reader uses 6250000 when the key is absent (`LLUDPServer.cs` 414). `client_throttle_max_bps` is commented with an example of 187500 (823–828). The field starts at 640000 and, when the key is present, is clamped to 6250–1000000 (`ThrottleRates.cs` 69 and 82–86). Adaptive throttles are forced off (88–90).

`[RemoteAdmin] enabled` is false (`RegionServerDefaults.ini` 1863–1864). The example `access_password` is `unknown` (1873–1874). Remote console routes, when a console user is set, are `/StartSession`, `/CloseSession`, `/SessionCommand` and `/ReadResponses` (`RemoteConsole.cs` 186–190). GridServer leaves `ConsoleUser`, `ConsolePass` and `ConsolePort` commented (`GridServer.ini.example` 212–217). The region defaults set `[Network] ConsoleUser` to `Test` (`RegionServerDefaults.ini` 692).

`ferroan-config` already loads this INI shape: Nini, includes, and `${Section|key}` substitution, with the region and grid include orders kept apart ([ARCHITECTURE.md](../../ARCHITECTURE.md)). Phase 7 uses that loader. It does not invent a second configuration language.

### 1.3 Stores

`Migration.Update` creates or advances the `migrations` table and runs every later script (`Source/OpenSim.Data/Migration.cs` 172–220). A script that throws is logged as a warning, `ROLLBACK` is run, and the version is still recorded (197–220). That is [TB38](../TRANQUILLITY_BUGS.md). `ferroan-db` reads the recorded version and refuses to open a store whose version is not the one this build expects. It does not migrate ([ARCHITECTURE.md](../../ARCHITECTURE.md)). `cargo xtask schema verify` is the C# side of that check ([TESTING.md](../TESTING.md)).

The region store is selected by `[DatabaseService]` or `[SimulationDataStore]` (`Grid.ini` 36–37) and holds prims, land, region settings and terrain. Estate rows use `[EstateDataStore]` (`Grid.ini` 39–40) or, when the operator sets it, `EstateConnectionString` on another database (`GridCommon.ini.example` 21–24). GridServer holds accounts, inventory, assets, the `regions` table and the other service tables on `[DatabaseService]`.

Region settings carry `agent_limit`. A new `RegionSettings` object uses 40 (`RegionSettings.cs` 183–187). The region INI key `MaxAgents` defaults to 100 when absent (`RegionInfo.cs` 698), and the example leaves `; MaxAgents = 100` commented (`Regions.ini.example` 59). Admission uses the settings value: after a recount, a non-god, non-estate-manager root is refused when the root count, excluding NPCs, is at least `AgentLimit`, with reason `The region is full` (`Scene.cs` 6445–6472). Gods return before that check (6445–6446). Estate managers return before it (6454–6456). The console `region set agent-limit` refuses a value above `MaxAgents` and then saves (`RegionCommandsModule.cs` 208–229). `region set max-agent-limit` lowers `agent_limit` when the new ceiling is smaller (231–251).

### 1.4 Shutdown, the grid row, and rollback

The console command `restart` answers that it is disabled (`OpenSim.cs` 811–813). Cutover is a process stop.

`quit` and `shutdown` request a host stop (`OpenSimBase.cs` 948–976) and `ShutdownSpecific` closes scenes (`992–1018`). `Scene.Close` (`Scene.cs` 1558–1615) does the following, in this order. It deregisters with the grid (1580–1581). It kicks each root with `The simulator is going down.` and sends `DisableSimulator` (1584–1597, `LLClientView.cs` 6114–6116). It sleeps 500 ms (1606). It closes agents (1609). It runs backup with `forced` true (1614–1615). Backup stores a group that has changed (`SceneObjectGroup.cs` 3231–3252) and does not delete the region's objects.

`remove-region` is a different command. It calls `RemoveRegion(scene, false)` (`OpenSim.cs` 791–796), which calls `DeleteAllSceneObjects` before `CloseScene` (`OpenSimBase.cs` 692–703). `DeleteAllSceneObjects` deletes each unattached group (`Scene.cs` 2876–2890). The delete path removes the object from the store (`UnlinkSceneObject` with `softDelete` false, `Scene.cs` 2983–2996). `delete-region` uses the same object delete and then removes the region file when asked (`OpenSim.cs` 801–806, `OpenSimBase.cs` 706–737). The migration path is `quit` or `shutdown`. It is not `remove-region` or `delete-region`.

`backup` on the console forces the current scene's pending object writes (`OpenSim.cs` 405–408 and 786–788).

Deregister reads `[GridService] DeleteOnUnregister`, default true (`GridService.cs` 48 and 71). The shipped `GridServer.ini.example` does not set the key. When the default holds, and the region's flags do not include `Persistent` (value 16, `RegionFlags.cs` 44), deregister deletes the `regions` row (`GridService.cs` 414–443). When `DeleteOnUnregister` is false, or the Persistent flag is set, deregister clears `RegionOnline` (value 4, `RegionFlags.cs` 42), writes `last_seen`, and leaves the row (426–440). The example documents Persistent as "signalled as offline but left registered" (`GridServer.ini.example` 335–353). Register then sets `RegionOnline` again and returns an empty string on success (`GridService.cs` 379–397). A duplicate name returns `Duplicate region name` (309–320). `Can't move this region` and `Region locked out` refuse a coordinate change when those flags are set (330–334). A failed register throws on the region (`Scene.cs` 2407–2416).

A login whose destination is missing logs out the presence session and returns `GridProblem` (`LLLoginService.cs` 607–614). The viewer text is `Error connecting to the desired location. Try connecting to another region.` (`LLLoginResponse.cs` 65–67). A launch that fails returns the connector's reason as the login message (`LLLoginService.cs` 641–649). `CreateAgent` uses that reason from the region, or the HTTP message, or `error`, or the exception text (`SimulationServiceConnector.cs` 132–171), with a 30000 ms post (132). `QueryAccess` starts from `Failed to contact destination` (`SimulationServiceConnector.cs` 300–304). When the first launch fails, login tries online regions flagged `FallbackRegion` (`LLLoginService.cs` 995–1010, `GridService.cs` 819–838). An inventory service that is not configured returns `The inventory service is not responding.  Please notify your login region operator.` (`LLLoginService.cs` 527–532, `LLLoginResponse.cs` 68–69). A presence login failure returns `GridProblem` (`LLLoginService.cs` 551–560).

`LLFailedLoginResponse.DeadRegionProblem` is built with `The region you are attempting to log into is not responding. Please select another region and try again.` (`LLLoginResponse.cs` 71–73). No caller returns it.

Rollback a step is: stop the process that was writing the store, then start the C# process on that same stopped store. Two writers on one store are the failure this plan guards. The Flotsam cache can be discarded. The `migrations` version and the service tables cannot.

### 1.5 What a viewer, a script, a neighbour or a grid service sees

A viewer on the way down sees the kick text and then `DisableSimulator`. A viewer logging in during the gap sees `GridProblem`, a fallback region, or the `CreateAgent` reason, as section 1.4 says. A viewer that fills the region sees `The region is full`. A neighbour sees the region leave the online set when `RegionOnline` is cleared or the row is deleted, and sees it return when register succeeds. A script on C# can read `agent_limit` (`LSLSystemAPI.cs` 16922) and, under the OSSL gate, `osGetSimulatorMemory` as the process working set (`LSLSystemAPI.cs` 11846–11851, `Util.cs` 3654–3657). Script execution itself is Phase 4. This phase only reports that a store contains scripts.

`SimStats` on the circuit carries the viewer ids in `StatsIndexID` (`SimStats.cs` 189–228), including `VirtualSizeKb` and `ResidentSizeKb` (214–215). The reporter fills time dilation, FPS, agent counts, prim counts, frame times, packet rates and script counters (`SimStatsReporter.cs` 368–401) and sets `SimPhysicsStepMs` to 20 (390). It does not assign `ResidentSizeKb` or `VirtualSizeKb`, so those two packet fields stay at the array's initial 0. Operator memory on the monitor page is `ProcMem`, the working set in kilobytes (`SimExtraStatsCollector.cs` 167–175 and 241), plus the thread counts beside it (239–240). The console memory report prints the same working set in megabytes (`StatsManager.cs` 208–219). `/monitorstats/<region id>` and `/monitorstats/<region name>` are the pages (`MonitorModule.cs` 97–99). P0.12 already matches those routes.

### 1.6 Numbers this phase measures, and does not set

Memory is the harness line from P0.10n11: `VmRSS` and `VmHWM` at idle, after each bot login and after logout, for the region processes and for Robust, plus the four-region C# process and the 500-part store. `ProcMem` is the C# page a viewer-side operator already has. CPU, for this plan, is process processor time sampled over the same run, beside `SimFPS`, `FrameMS`, `PhysicsMS`, `ScriptMS` and `AgentMS` from the packet the reporter sends. Latency is the harness sample that already records one localhost request with `TCP_NODELAY` off and one with it on (P0.10n3), plus the login XML-RPC, one asset fetch and one seed capability on that same run. Region capacity is `agent_limit` and `MaxAgents` as section 1.3 states them. Concurrency is `MaxPoolThreads`, `MinPoolThreads` and the two UDP throttle keys as section 1.2 states them.

No row in this plan picks a numeric bar for any of those. Section 6 asks the maintainer.

## 3. Proving it against C#

Every close is a C# observation: a packet, a login or service body, a console line, a `migrations` or `regions` row, or a process the harness started from the pin. The C# oracle, the capture rig and the live harness are the producers. A Ferroan result is accepted when it matches that observation. Two Ferroan processes agreeing with each other is not the close.

The patterns already in the tree, and what this phase adds:

- **Config.** `cargo xtask config` runs Nini on the pin's files. P7.1 adds the operator inventory on top of that parse.
- **Store version.** `cargo xtask schema verify` runs `Migration.Update` on an empty database. P7.6 compares a stopped operator database with that version and does not run the update.
- **Service swap.** `live run … grid --rust assets`, `--rust accounts` and `--rust auth` are the existing mixed processes. P7.4 and P7.5 turn those into an ini the operator can read, plus the ini that points the URIs back.
- **Region swap.** P7.11 records a C# stop and a C# start on one store. P7.12 starts Ferroan on that stopped store and compares the login and the arrival with the C# recording. P7.14 stops Ferroan and starts C# again. The object the viewer sees is the one the C# baseline stored.
- **Shutdown.** P7.8 captures the kick, `DisableSimulator`, the deregister and the backup order from a C# `quit`.
- **Capacity and stats.** A C# region with `agent_limit` 2, a C# `SimStats` packet, and a C# `/monitorstats` body are the baselines. The harness `VmRSS` lines stay beside them.

Live runs take the live lock. Ordinary CI does not start Tranquillity except where the live job already does.

## 4. Risks

A second writer on a store that C# still has open loses rows. SQLite in particular. P7.7 is the guard, and the guide's rollback is stop, then start, on a stopped store.

`DeleteOnUnregister` default true deletes the `regions` row on a clean shutdown. A neighbour and a login both see the region gone until the next process registers. Persistent, or `DeleteOnUnregister` false, leaves an offline row. The tool prints which of the two the current flags will do. It does not change the C# default.

`remove-region` and `delete-region` delete stored objects. An operator who uses them as the cutover loses the region contents before Ferroan starts.

`Migration.Update` can record a version whose script threw ([TB38](../TRANQUILLITY_BUGS.md)). The version check then passes and a later reader fails on a missing column. The guide tells the operator to read the C# log for the warning `failed and is recorded as done` before trusting the version. The version table has no separate failure bit.

Deregister runs before backup (`Scene.cs` 1580, then 1614). The grid row changes while the last object write is still ahead. The next process starts after the first process has exited, so that write has finished.

The authentication connector caveat in section 2 means a C# login and a Ferroan authentication service can both open the auth store. P7.5 records that and does not claim a single writer for that file until login itself has moved (P7.27).

`ResidentSizeKb` on the circuit stays 0, as section 1.5 says. A comparison that treats that field as the process size will report Ferroan and C# equal at zero. The comparison uses `ProcMem` and the harness `VmRSS`.

The scene-throttle comment and the reader default disagree (section 1.2). P7.38 prints the value the reader used. It does not retune Ferroan to the comment.

Phase 5 and Phase 6 plans are not in this tree. A hand-off named by [PLAN.md](../PLAN.md) scope can move when those plans assign their own ids. This file will not guess the ids.

MSSQL appears in `GridCommon.ini.example` (26–32). `ferroan-db` has SQLite, MySQL and PostgreSQL. Question 6.

## 6. Questions

These are not decided. Each recommendation is the one the rows assume until the maintainer says otherwise. Where a row says the report does not block a move, that is this section, not a silent default written into the tool as policy.

1. **Numeric bars.** Memory, CPU, latency, region capacity and concurrency. Recommendation: keep measuring against the C# run of the same scenario, and add a bar only when the maintainer names one. P7.36, P7.37 and P7.38 record and do not fail a grid for a number this plan did not set. Capacity already has C#'s own refusal at `agent_limit`. That refusal is the capacity check. A throughput target is separate.

2. **A region that still contains scripts.** Recommendation: the P7.31 report blocks the region move until the Phase 4 gate has passed for that build. A viewer on the Ferroan region would otherwise see a silent script. The row stays a report until this is answered.

3. **A region that contains physical prims, before P3.28.** Recommendation: the P7.32 report blocks the region move until P3.28. The D38 walking stand-in remains the Phase 2 gate for a region whose content does not need physics. A BasicPhysics trace is not the substitute for P3.28.

4. **What stays C#.** Recommendation: no local C# process remains after P7.30, the region rollback drill, and the money row, except a region or a service the operator lists as `remaining`. Foreign grids stay on their own servers. Janus stays the external voice server. MSSQL grids stay on C# until question 6 is answered the other way.

5. **How many regions in one Ferroan process.** C# hosts many regions in one RegionServer (`Regions.ini.example` 8). Ferroan today is one region per process. Recommendation: Phase 7 does not add a multi-region process. The operator runs one Ferroan process per region. P7.36 measures that against the four-region C# process. A later multi-region process is a separate decision.

6. **MSSQL.** `GridCommon.ini.example` offers it (26–32). Ferroan has SQLite, MySQL and PostgreSQL. Recommendation: MSSQL grids stay on C#. Phase 7 does not add a driver.

7. **`DeleteOnUnregister`.** The code default is true, and the example omits the key, so a shutdown deletes the `regions` row unless Persistent is set. Recommendation: the guide documents both outcomes and P7.9 prints which one the flags will produce. The C# default stays. Operators who want the row to remain set Persistent, as the example's comment already describes.

8. **Remote admin during a move.** The shipped value is `enabled = false`, and the example password is `unknown`. Recommendation: Phase 7 leaves the module off. Enabling it, and replacing that password, belongs to Phase 5's remote-admin work. P7.33 prints the flag and does not print the password.

9. **Beta entry and exit.** Recommendation: a grid is a beta when the P7.35 manifest's Ferroan processes each name a done phase id, the version check and the single-writer guard have passed, and the remaining processes are C#. It exits when the P7.39 record marks every local C# process `off` or explicitly `remaining`, and the P7.14 rollback has been run on each moved region. No performance bar is required for exit until question 1 sets one.

10. **G3 and an operator-facing region.** P2.12 is the automated gate. G3 is the maintainer's viewer check after it. Recommendation: the operator guide says a region move for people with viewers follows G3. P7.12's automated close stays the bot comparison and does not mark G3 done.

11. **Scene throttle when the key is absent.** The comment says 0 (`RegionServerDefaults.ini` 815–821). The reader uses 6250000 (`LLUDPServer.cs` 414). Recommendation: the measured C# value is the reader default, and Ferroan keeps whatever Phase 2 already matched to that reader. P7.38 does not retune. The comment is finding 2 below.

## 7. Estimate

39 coder-days, one per row. That is the work of producing a C# baseline and a matching rollback for each process an operator can move, plus the reports for content that belongs to a later phase, plus the measurements. It is not a second copy of Phases 1 to 6. Those phases remain on their own estimates. A row here that waits on one of them is a day of cutover proof after that phase, not a day of the phase itself.

What drives the count is one observation per step. The service swaps cannot share a row: a login body, a `regions` flag, a tile, a friendship row, an IM, a group notice, a profile, an estate read, a hypergrid hop and a money payment fail in different places. The region drill is four rows because the C# baseline, the Ferroan start, the neighbour teleport and the rollback are four captures. The measurements are three rows because memory, latency and the capacity knobs are three different C# surfaces.

About 16 of the 39 can start from C# and from the services Ferroan already serves: P7.1 through P7.11, P7.15, P7.16, P7.35, P7.36's harness lines, P7.37's localhost sample and P7.38's C# knobs. P7.4 and P7.5 can start as well, because assets, accounts and authentication are already in the harness. The rest wait on the phase id in the depends column. P7.12 waits on P2.12. P7.30 waits on P1.16. P7.32's pass, if question 3 says so, waits on P3.28. P7.31's pass, if question 2 says so, waits on the Phase 4 gate. Calendar time is that chain. The 39 days are not 39 days from the day this file lands.

Queue rule 10 still seats two coders. Nothing in this file splits a row into separately assignable leaves.
