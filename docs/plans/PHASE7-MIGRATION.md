## 1. What C# does that an operator can see

### 1.1 Processes

A grid is more than one process. The shipped region file starts in standalone mode. Grid mode and the hypergrid files are selections an operator makes.

GridServer is one process. `[ServiceList]` in `Source/OpenSim.Server.GridServer/AppData/GridServer.ini.example` (116–160) names each connector as `port/assembly:class`. The lines that are not comments are AssetServiceConnector, XInventoryInConnector, GridServiceConnector, GridInfoServerInConnector, AuthenticationServiceConnector, AvatarServiceConnector, LLLoginServiceInConnector, PresenceServiceConnector, UserAccountServiceConnector, GridUserServiceConnector, AgentPreferencesServiceConnector, FriendsServiceConnector, MapAddServiceConnector, MapGetServiceConnector and MuteListServiceConnector. Commented, so off unless an operator enables them: FreeswitchServerConnector (120), OpenIdServerConnector (125), ExperienceServiceConnector (136), OfflineIMServiceRobustConnector (138), GroupsServiceRobustConnector (140), XBakesConnector (142), AppearanceServerConnector (147), UserProfilesConnector (150), EstateDataRobustConnector (153) and VoiceSessionServerConnector (160). `[Network] port` is the private port (165–166). `[Network] bind_ip_address` empty means every interface (168–171). `[Network] AllowllHTTPRequestIn` defaults false (205–210). `[LoginService]` wires the modules login calls, including `FriendsService` (560–573).

A hypergrid grid uses `GridServer.HG.ini.example` instead. Its `[ServiceList]` (124–170) keeps the private-port connectors and adds, on the public port, GatekeeperServiceInConnector, UserAgentServerConnector, HeloServiceInConnector, HGFriendsServerConnector, InstantMessageServerConnector, an inventory connector under the name `HGInventoryService`, and an asset connector under the name `HGAssetService` (162–168). HGGroupsServiceRobustConnector is commented (169–170). The same file has `[Hypergrid]` (232), `[TrustedHypergrid]` (261), `[GatekeeperService]` (843), `[UserAgentService]` (887), `[HGInventoryService]` (995), `[HGAssetService]` (1021), `[HGFriendsService]` (1050) and `[HGInstantMessageService]` (1059). On the region side, `config-include/GridHypergrid.ini` replaces `Grid.ini`. It sets `[Startup] WorldMapModule` to `HGWorldMap` (11) and the modules `HGInventoryBroker`, `RemoteUserAliasServicesConnector`, `HGEntityTransferModule`, `HGInventoryAccessModule`, `HGFriendsModule` and `HGUserManagementModule` (15–32).

RegionServer is a second process, and a grid runs one or many of them. The shipped architecture include is `config-include/Standalone.ini` (`RegionServer.ini.example` 1596–1607). The same key lists `StandaloneHypergrid.ini`, `Grid.ini` and `GridHypergrid.ini` as the other choices (1596, 1608–1610). `Standalone.ini` loads local inventory, authentication, presence, accounts, grid user and login in the region process (8–32). Its stores come through `Include-Common = "config-include/StandaloneCommon.ini"` (138–139). `StandaloneCommon.ini.example` then includes `SQLiteStandalone.ini` (3–9). `StandaloneHypergrid.ini` keeps those local services and switches inventory, entity transfer, friends and user management to the hypergrid modules (11–28), and it uses the same `Include-Common` (214–215). Grid mode is `config-include/Grid.ini` (1609), which includes `GridCommon.ini` (`Grid.ini` 8) and points the region at remote connectors (`Grid.ini` 11–29): asset, inventory, grid, avatar, neighbour, authentication, presence, accounts, agent preferences, grid user, simulation, land, map image, search, mute list and experiences. `Grid.ini` does not load user aliases. `GridHypergrid.ini` loads `RemoteUserAliasServicesConnector` (23). Estate data stays in-process unless `[EstateDataStore] LocalServiceModule` is the remote connector (`GridCommon.ini.example` 120–125). A region file is an INI whose section name is the region name (`Regions/Regions.ini.example` 9–18). Files ending in `.ini` and `.xml` in that directory are both loaded (6). `RegionUUID`, `Location`, `InternalAddress`, `InternalPort` and `ExternalHostName` are the identity a viewer and a neighbour see (18–24). `Addresses` and `LocalAddress` override the viewer address for that region (32–33). `SizeX` and `SizeY` are the variable-region size, commented at 256-metre multiples (44–45). Several regions may share one RegionServer process (8). Where the region list is read from is `[Startup] region_info_source`, `regionload_regionsdir` and `regionload_webserver_url` (`RegionServer.ini.example` 175–194).

`[Network] http_listener_port` is the region HTTP port (`RegionServerDefaults.ini` 694). It is the port in the grid row's server URI. It is not the UDP `InternalPort`. Moving one region out of a multi-region process gives that region its own listener port, so the server URI neighbours and login already stored changes.

MoneyServer is a third process. It reads `MoneyServer.ini` (`Source/OpenSim.Server.MoneyServer/Program.cs` 40–45). Regions call `[MoneyServer] ServerPort`, default 8008 (`Source/OpenSim.Server.MoneyServer/AppData/MoneyServer.ini.example` 31–33, `MoneyServerRuntime.cs` 42 and 105–123, `RegionServer.ini.example` 1282–1285, `CurrencyServer`). `AspNetPort` 8009 is the ASP.NET XML-RPC listener beside that port (35–38 of that same example). It is not the port a region calls. With no `AspNetUrls`, that listener uses 8009.

Voice in the shipped grid file is the commented FreeSWITCH connector and the commented WebRTC session connector (`GridServer.ini.example` 119–120 and 157–160). The region addon file is `Addons/os-webrtc-janus/os-webrtc-janus.ini`, and `Gloebit.ini.example` is the economy addon. Janus is the external server [PLAN.md](../PLAN.md) names for Phase 6. It is not a C# process in this tree. Neither addon is started by the shipped architecture include.

OpenIdServerConnector and AppearanceServerConnector are commented and have no Phase 1 row. While they stay commented they are not local processes, and they are not retirement blockers. An operator who enables one before a service exists blocks production retirement until that connector is replaced or turned back off. A beta may still list it as `remaining`. P7.39 is that record.

### 1.2 Configuration an operator edits

GridServer's `[DatabaseService]` example enables MySQL (`GridServer.ini.example` 241–254). PostgreSQL is commented (242–246). Region grid mode comments MySQL, PostgreSQL and MSSQL and leaves SQLite selected through `Include-Storage` (`GridCommon.ini.example` 4–38). The SQLite file names live in `config-include/storage/SQLiteStandalone.ini` (5–44): `OpenSim.db`, `Asset.db`, `inventory.db`, `avatars.db`, `auth.db`, `userprofiles.db`, `griduser.db`, `friends.db` and `groups.db`, plus the hypergrid asset string. The region defaults file, before the architecture include, sets `[GridService] StorageProvider` to `OpenSim.Data.Null.dll:NullRegionData` (`RegionServerDefaults.ini` 2879–2894). `[AssetService] AssetServerURI`, `[InventoryService] InventoryServerURI` and `[GridService] GridServerURI` are the addresses a region calls, with no trailing slash on the asset URI (`GridCommon.ini.example` 82–108). Estate is `[EstateService] EstateServerURI` (127–128). Avatar, agent preferences, presence, accounts, aliases, grid user and authentication follow (137–177). Friends is `[FriendsService] FriendsServerURI` (179–183). `[Hypergrid] GatekeeperURI` is commented; `HomeURI` is set (40–61). `[Modules] AssetCaching` is `FlotsamAssetCache` (69–74). That cache is not the asset store. The map service's tile files are `[MapImageService] TilesStoragePath` (`GridServer.ini.example` 651–656, `MapImageService.cs` 55 and 83, default `maptiles`). `MapTileDirectory` (`GridCommon.ini.example` 111–112) is the cache of tiles for hypergrid-linked regions. `HypergridLinker.cs` 91 reads it and uses `maptiles` when the key is unset.

`[Startup] PIDFile` is commented in the region defaults (`RegionServerDefaults.ini` 49–50) and in the grid file (`GridServer.ini.example` 54–56). No pid file is written unless the key is set. `ServerBase.CreatePIDFile` runs only for that path (`OpenSim.Framework.Servers/ServerBase.cs` 112–149).

`[Startup] MaxPoolThreads` is 300 in the shipped region defaults, under a SmartThreadPool comment (`RegionServerDefaults.ini` 74–76). `OpenSim.cs` reads `MinPoolThreads` and `MaxPoolThreads` into the locals `stpMinThreads` and `stpMaxThreads` (102–103 and 129–130) and never uses those locals. `FireAndForgetMethod` has no SmartThreadPool member (`Util.cs` 101–107). The keys have no effect at this pin. The concurrency knobs an operator can still set are the .NET thread-pool environment variables named in the grid file (`GridServer.ini.example` 46–52) and `[ScriptsHttpRequestModule] MaxPoolThreads` (`HttpRequestModule.cs` 121–126, default 8 when the section is absent). `async_call_method` is `QueueUserWorkItem` (`RegionServerDefaults.ini` 69–72) and that value is used (`OpenSim.cs` 124–127). `[Startup] physics` is `ubODE` (`RegionServerDefaults.ini` 313). `[Startup] meshing` is `ubODEMeshmerizer` (294). `[Startup] DefaultScriptEngine` is `InWorldz.Phlox` (325). `[Startup] shutdown_console_commands_file` is `shutdown_commands.txt` (55–56), and shutdown runs that file before the region close (`OpenSim.cs` 461–466). `[Startup] InworldRestartShutsDown` is false (185). `[Startup] UseSceneBackup` is read at scene setup (`Scene.cs` 997) from a default of true (1266).

`[ClientStack.LindenUDP]` leaves `scene_throttle_max_bps` commented, and the comment says the default is 0 (`RegionServerDefaults.ini` 815–821). The reader uses 6250000 when the key is absent and the section exists (`LLUDPServer.cs` 407–414). With no section the local stays 0 (407). The shipped file has the section. `client_throttle_max_bps` is commented, and that comment also says the default is 0 (823–826), with an example of 187500 (828). The field starts at 640000 (`ThrottleRates.cs` 68) and, when the key is present, is clamped to 6250–1000000 (82–86). Adaptive throttles are forced off (88–90).

`[RemoteAdmin] enabled` is false (`RegionServerDefaults.ini` 1863–1864). The example `access_password` is a placeholder (1873–1874). Remote console routes, when a console user is set, are `/StartSession`, `/CloseSession`, `/SessionCommand` and `/ReadResponses` (`RemoteConsole.cs` 186–190). GridServer leaves `ConsoleUser`, `ConsolePass` and `ConsolePort` commented (`GridServer.ini.example` 212–217). The region defaults set `[Network] ConsoleUser` and `ConsolePass` (692–693). Those two matter for the rest console. P7.1 redacts both.

`ferroan-config` already loads this INI shape: Nini, includes, and `${Section|key}` substitution, with the region and grid include orders kept apart ([ARCHITECTURE.md](../../ARCHITECTURE.md)). Phase 7 uses that loader. It does not invent a second configuration language.

### 1.3 Stores

`Migration.Update` creates or advances the `migrations` table and runs every later script (`Source/OpenSim.Data/Migration.cs` 172–220). A script that throws is logged as a warning, `ROLLBACK` is run, and the version is still recorded (197–220). That is [TB38](../TRANQUILLITY_BUGS.md). `ferroan-db` reads the recorded version and refuses to open a store whose version is not the one this build expects. It does not migrate ([ARCHITECTURE.md](../../ARCHITECTURE.md)). `cargo xtask schema verify` is the C# side of that check ([TESTING.md](../TESTING.md)).

The money tables do not use `migrations`. `MySQLMoneyManager` opens the connection, reads `TABLE_COMMENT` from `INFORMATION_SCHEMA.TABLES`, parses `Rev.N`, and runs the matching `ALTER` before it returns (`Source/OpenSim.Data.MySQL.MoneyData/MySQLMoneyManager.cs` 88–115, 293–305 and 910–930). Opening the money database with that class is a write. A version check for those tables is a `SELECT` of the comment, not a call to that open.

The region store is selected by `[DatabaseService]` or `[SimulationDataStore]` (`Grid.ini` 36–37) and holds prims, land, region settings and terrain. Estate rows use `[EstateDataStore]` (`Grid.ini` 39–40) or, when the operator sets it, `EstateConnectionString` on another database (`GridCommon.ini.example` 21–24). GridServer holds accounts, inventory, assets, the `regions` table and the other service tables on `[DatabaseService]`. Several region processes and GridServer routinely share one MySQL or PostgreSQL database. Both examples use the database name `opensim`.

Other files move with a region, or stay behind when they are shared:

- Phlox script state is one SQLite file, `script_state.db`, under `<ScriptEnginesPath>/Phlox/state/` (`PhloxEngine.cs` 156 and 2356, `StateManager.cs` 79–82 and 221). The directory is not per region (`RegionServerDefaults.ini` 2500–2512). Every region in the process shares it (`StateManager.cs` 91–101). The format is the Phlox-state section of [PHASE4-SCRIPTING.md](PHASE4-SCRIPTING.md). Phase 7 names the file. It does not read the protobuf.
- YEngine keeps its files under `ScriptEngines/Yengine/<region id>` (`XMREngine.cs` 293–301). That directory is per region.
- Bot persistence is off unless `[BotPersistence]` exists and `Enabled` is true. The default is false (`BotPersistenceManager.cs` 121–136). `DatabaseFile` defaults to `botpersistence.db` (136). The path inserts the region UUID between the stem and the extension (146–152), so the file is `botpersistence_<region id>.db`. The behaviour is P5.45a in [PHASE5-REGION-FEATURES.md](PHASE5-REGION-FEATURES.md). Phase 7 names the file when persistence is enabled. It does not implement the bot module.
- FSAssets, when selected, stores bytes in `BaseDirectory` and `SpoolDirectory` (`GridServer.ini.example` 265–270). Those directories are the asset service's, not a region's.
- Map tiles the map service writes are `[MapImageService] TilesStoragePath`, default `maptiles` (`GridServer.ini.example` 651–656, `MapImageService.cs` 55 and 83). They are P1.7. `MapTileDirectory` (`GridCommon.ini.example` 111–112, `HypergridLinker.cs` 91) is the cache of tiles for hypergrid-linked regions, and it defaults to `maptiles` when the key is unset. The XBakes files are P1.4c.

A rollback that restores only the region database leaves script state, tile files, bake files and, when bot persistence is enabled, that region's bot database where they were. Moving one region out of a multi-region process leaves the shared Phlox file on disk with the process that stays. P7.31a is the handover that shows the moving region's saved script result comes with it, and that the region which stayed keeps its own saved result.

Region settings carry `agent_limit`. A new `RegionSettings` object uses 40 (`RegionSettings.cs` 183–187). The region INI key `MaxAgents` defaults to 100 when absent (`RegionInfo.cs` 698), and the example leaves `; MaxAgents = 100` commented (`Regions.ini.example` 59). Admission uses the settings value: after a recount, a non-god, non-estate-manager root is refused when the root count already present, excluding NPCs, is at least `AgentLimit`, with reason `The region is full` (`Scene.cs` 6445–6472). With `agent_limit` 2, two roots are admitted and the third is refused. Gods return before that check (6445–6446). Estate managers return before it (6454–6456). The console `region set agent-limit` refuses a value above `MaxAgents` and then saves (`RegionCommandsModule.cs` 208–229). `region set max-agent-limit` lowers `agent_limit` when the new ceiling is smaller (231–251).

### 1.4 Shutdown, the grid row, and rollback

The console command `restart` answers that it is disabled (`OpenSim.cs` 811–813). That command is not a cutover.

`region restart <seconds>` and `region restart abort` are a different command (`RestartModule.cs` 78–90). The viewer's estate restart uses the same path. Both call `Scene.RestartNow` (`Scene.cs` 1497–1514). Unless `[Startup] InworldRestartShutsDown` is true, that closes the scene and opens it again in the same process, so the store is reopened under C#. The shipped default is false (`RegionServerDefaults.ini` 185). Cutover of a region is a process stop, `quit` or `shutdown`. An in-world restart during a move puts the region back on C#.

`quit` and `shutdown` request a host stop (`OpenSimBase.cs` 948–976) and `ShutdownSpecific` closes scenes (992–1018). `Scene.Close` (`Scene.cs` 1558–1615) does the following, in this order. It deregisters with the grid (1580–1581). It kicks each root with `The simulator is going down.` and sends `DisableSimulator` (1584–1597, `LLClientView.cs` 6114–6116). It sleeps 500 ms (1606). It closes agents (1609). It logs `TriggerSceneShuttingDown`, then `Persisting changed objects`, then `Closing scene` (1611–1617, Debug), and the persist is `Backup(true)` (1615). Backup stores a group that has changed only when `UseBackup` is true (`SceneObjectGroup.cs` 3231–3252). It does not delete the region's objects. `UseSceneBackup` false logs that backup is disabled (`Scene.cs` 997–999) and the persist writes nothing.

`remove-region` is a different command. It calls `RemoveRegion(scene, false)` (`OpenSim.cs` 791–796), which calls `DeleteAllSceneObjects` before `CloseScene` (`OpenSimBase.cs` 692–703). `DeleteAllSceneObjects` deletes each unattached group (`Scene.cs` 2876–2890). The delete path removes the object from the store (`UnlinkSceneObject` with `softDelete` false, `Scene.cs` 2983–2996). `delete-region` uses the same object delete and then removes the region file when asked (`OpenSim.cs` 801–806, `OpenSimBase.cs` 706–737). The migration path is `quit` or `shutdown`. It is not `remove-region` or `delete-region`.

`backup` on the console forces the current scene's pending object writes (`OpenSim.cs` 405–408 and 786–788).

Deregister reads `[GridService] DeleteOnUnregister`, default true (`OpenSim.Services.GridService/GridService.cs` 48 and 71). The shipped `GridServer.ini.example` does not set the key. When the default holds, and the region's flags do not include `Persistent` (value 16, `RegionFlags.cs` 44), deregister deletes the `regions` row (`GridService.cs` 414–443). When `DeleteOnUnregister` is false, or the Persistent flag is set, deregister clears `RegionOnline` (value 4, `RegionFlags.cs` 42), writes `last_seen`, and leaves the row (426–440). The example documents Persistent as "signalled as offline but left registered" (`GridServer.ini.example` 335–353).

Flags are not only what the last register stored. At register, stored flags are kept, `Reservation` is cleared, and `[GridService] DefaultRegionFlags`, then `Region_<name>` or `Region_<id>`, are parsed on top (`GridService.cs` 361–377). The example documents the `Region_<name>` form (333–338) and does not set `DefaultRegionFlags`. Register then sets `RegionOnline` and returns an empty string on success (379–397). `Duplicate region name` is returned only when `AllowDuplicateNames` is false (field default false at 54, read at 80; the example leaves the key commented at 333) and the other row has a different UUID (308–320). The same UUID is not that error: the second register stores over the one row (326–385). `Can't move this region` and `Region locked out` refuse a coordinate change when those flags are set (330–334). A failed register throws on the region (`Scene.cs` 2407–2416). The Robust console commands an operator uses on that row are `deregister region id`, `set region flags` and `show regions` (`GridService.cs` 94–131).

A login whose destination is missing logs out the presence session and returns `GridProblem` when no default and no alternative region is found (`LLLoginService.cs` 607–614). Before that, `FindDestination` tries `GetDefaultRegions`, then `FindAlternativeRegion` (`LLLoginService.cs` 734–751 for home, 763–781 for last, 900–914). `FindAlternativeRegion` returns the first fallback region, and, when `AllowLoginFallbackToAnyRegion` is true, any online region (900–911). The field default is true (97) and the key's default is that field (140). The shipped grid file sets the key false (`GridServer.ini.example` 624–629). The `DefaultRegion` flag and that key decide whether the gap is `GridProblem` or a placed login. The viewer text for `GridProblem` is `Error connecting to the desired location. Try connecting to another region.` (`LLLoginResponse.cs` 65–67).

A launch calls `QueryAccess` first and returns immediately when that call fails, with that call's reason (`LLLoginService.cs` 1153–1159). `QueryAccess` starts from `Failed to contact destination` (`SimulationServiceConnector.cs` 300–304). For an unreachable region the reason becomes the request's `Message`, or `Communications failure` when there is no message (384–400). When `QueryAccess` succeeds, the same method calls `CreateAgent` and returns that call's reason (`LLLoginService.cs` 1161). `CreateAgent` fills the reason from the result data, or from `Message`, or from the exception text (`SimulationServiceConnector.cs` 132–171), with a 30000 ms post (132). A failed launch is one of those two stages. P7.2 captures them separately. The missing-destination `GridProblem` (607–614) is a third case, and it is not a launch. An inventory service that is not configured returns `The inventory service is not responding.  Please notify your login region operator.` (`LLLoginService.cs` 527–532, `LLLoginResponse.cs` 68–69). An empty skeleton from the remote connector takes the same text through the later check (539–545). A presence login failure returns `GridProblem` (`LLLoginService.cs` 551–560).

`LLFailedLoginResponse.DeadRegionProblem` is built with `The region you are attempting to log into is not responding. Please select another region and try again.` (`LLLoginResponse.cs` 71–73). No caller returns it. That unused response is a note until some caller shows an observable consequence.

Rollback of a region database is: stop the process that was writing that region's rows, then start the C# process on that stopped store. Before the move, the operator keeps a forked copy of that stopped store. One post-move user change is what the C# reopen shows. Two processes registering one region UUID, or two processes serving one service's tables, are the failure this plan guards. A second RegionServer on the same MySQL database, with a different region UUID, is how C# grids already run and is not that failure. The Flotsam cache can be discarded. The `migrations` version, the service tables, the Phlox file, the YEngine directory, the bot database when persistence is enabled, the FSAssets directories, the map service's `TilesStoragePath`, the linked-region `MapTileDirectory` and the bake files cannot be discarded by a database restore. Asset rollback after the new backend has stopped writing through is the export in [ASSET_SYSTEM.md](../ASSET_SYSTEM.md) section 10, not an INI that points at tables nothing writes any more. That export is a separate recovery option. Question 12 asks how long a rollback is offered. Question 16 asks whether the operator can produce the stopped snapshot of each shared side store inside the maintenance window.

### 1.5 What a viewer, a script, a neighbour or a grid service sees

A viewer on the way down sees the kick text and then `DisableSimulator`. A viewer logging in during the gap sees `GridProblem`, a default or fallback region, the `QueryAccess` reason, or the `CreateAgent` reason when access succeeded, as section 1.4 says. A viewer that fills the region sees `The region is full` on the arrival that crosses `agent_limit`. A neighbour sees the region leave the online set when `RegionOnline` is cleared or the row is deleted, and sees it return when register succeeds. A neighbour also sees a new server URI when a region moves to its own `http_listener_port`. A script on C# can read `agent_limit` (`LSLSystemAPI.cs` 16922) and, under the OSSL gate, `osGetSimulatorMemory` as the process working set (`LSLSystemAPI.cs` 11846–11851, `Util.cs` 3654–3657). Script execution itself is Phase 4. This phase reports that a store contains scripts, and it reports `ActiveScripts` after a restart that kept Phlox state.

`SimStats` on the circuit carries the viewer ids in `StatsIndexID` (`SimStats.cs` 189–228), including `VirtualSizeKb` and `ResidentSizeKb` (214–215) and `ActiveScripts` (210). The reporter fills time dilation, FPS, agent counts, prim counts, frame times, packet rates and script counters (`SimStatsReporter.cs` 368–401), sets `ActiveScripts` from the scene (387) and sets `SimPhysicsStepMs` to 20 (390). It does not assign `ResidentSizeKb` or `VirtualSizeKb`, so those two packet fields stay at the fresh array's 0. Operator memory on the monitor page is `ProcMem`, the working set in kilobytes (`SimExtraStatsCollector.cs` 167–175 and 241), plus the thread counts beside it (239–240). The console memory report prints the same working set in megabytes (`StatsManager.cs` 208–219). `/monitorstats/<region id>` and `/monitorstats/<region name>` are the pages (`MonitorModule.cs` 97–99). P0.12 already matches those routes.

### 1.6 Numbers this phase measures, and does not set

Memory is the harness line from P0.10n11: `VmRSS` and `VmHWM` at idle, after each bot login and after logout, for the region processes and for Robust, plus the four-region C# process and the 500-part store. `ProcMem` is the C# page a viewer-side operator already has. That harness line also prints the machine CPU count and the C# GC mode (`xtask/src/memory.rs` 316–332). It does not record a process's processor time. CPU, for this plan, is that processor time sampled over the same run as the memory line, beside `SimFPS`, `FrameMS`, `PhysicsMS`, `ScriptMS` and `AgentMS` from the packet the reporter sends. P7.36 adds the processor-time sample. Those packet counters are P5.78. They are a different observable from the process working set. `ResidentSizeKb` and `VirtualSizeKb` stay 0 on the packet, and they are not the comparison. Latency is the harness sample that already records one localhost request with `TCP_NODELAY` off and one with it on (P0.10n3), plus the login XML-RPC, one asset fetch and one seed capability on that same run. Region capacity is `agent_limit` and `MaxAgents` as section 1.3 states them. The startup pool-thread keys are not concurrency knobs. ## 3. Proving it against C#

Every close is a C# observation: a packet, a login or service body, a console line, a `migrations` row, a `regions` row, a `TABLE_COMMENT`, or a process the harness started from the pin. The C# oracle, the capture rig and the live harness are the producers. A Ferroan result is accepted when it matches that observation. Two Ferroan processes agreeing with each other is not the close.

The service rows do not re-run the Phase 1 suite. Each one produces the INI pair and then shows C# reading a row the Ferroan process wrote under that INI. The Phase 1 id in the depends column is the behaviour being reused.

The patterns already in the tree, and what this phase adds:

- **Config.** `cargo xtask config` runs Nini on the pin's files. P7.1 adds the operator inventory on top of that parse, including the hypergrid file, the standalone architecture and the SQLite file names.

## 4. Risks

Several RegionServers and GridServer share one MySQL or PostgreSQL database. A guard that treats "the database is listening" or "a pid file exists" as the lock refuses a layout C# already runs, and the pid file is off unless the operator sets it. SQLite does not fail a second open. The conflicts show up later as busy or locked errors, and as one `regions` row being stored over. P7.7 locks a region UUID, a shared Phlox file, or a service's table set. A reachable port observed before `Scene.Close` does not by itself give two cooperating starters exclusive ownership of that UUID. P7.7a and P7.7b serialize the guard with the acquisition.

`DeleteOnUnregister` default true deletes the `regions` row on a clean shutdown. A neighbour and a login both see the region gone until the next process registers. Persistent, `DefaultRegionFlags`, or `Region_<name>`, can leave an offline row instead. The tool prints which of the two the current flags and the config keys will do. It does not change the C# default.

`remove-region` and `delete-region` delete stored objects. An operator who uses them as the cutover loses the region contents before Ferroan starts. `region restart` with the shipped `InworldRestartShutsDown` false reopens the store under C#. `UseSceneBackup` false means the `quit` does not persist the last changes.

`Migration.Update` can record a version whose script threw ([TB38](../TRANQUILLITY_BUGS.md), `Migration.cs` 197–220). The version check then passes and a later reader fails on a missing column. A historic log of the warning `failed and is recorded as done` can tell an operator why. It cannot establish the state of the store being moved. P7.6a refuses a stopped copy whose recorded version matches and one required column is absent. The version table has no separate failure bit. The money manager's open can `ALTER` a table whose comment is old. The money check is a `SELECT` of `TABLE_COMMENT` and does not perform that open.

Deregister runs before the final backup (`Scene.cs` 1580, the 500 ms sleep at 1606, then `Backup(true)` at 1615). `SceneObjectGroup.cs` 3231–3252 can still store a changed object after the grid row has changed. A region leaving a multi-region process waits for acknowledged close and backup completion. A whole-process move waits for confirmed process exit. P7.7a and P7.7b are those two handoffs. With `UseSceneBackup` false the final backup writes nothing, and the guide says so.

Question 6 is the authentication window. Until it is answered the other way, the guide does not start a Ferroan authentication service while C# login still opens the auth store. P7.40 is that swap, and it runs after P7.27 has stopped C# login.

`ResidentSizeKb` on the circuit stays 0, as section 1.5 says. A comparison that treats that field as the process size will report Ferroan and C# equal at zero. The comparison uses `ProcMem` and the harness `VmRSS`.

The scene-throttle comment and the reader disagree when the section exists (section 1.2). With no section the value stays 0. P7.38 prints the value the reader used for the file it was given. It does not retune. The startup pool-thread keys are printed as unused. Tuning them would not change the process.

A region database restore does not restore `script_state.db`, a YEngine directory, a bot database when persistence is enabled, an FSAssets tree, the map service's `TilesStoragePath`, the linked-region `MapTileDirectory` or bake files. The guide names each of those beside the database it does restore. Each store under test has a forked, known-good copy taken while it was stopped, before the move, and one post-move user change. Question 16 asks whether that stopped snapshot fits the maintenance window.

Phase 5 and Phase 6 ids are the ones [PHASE5-LAND-ESTATES-GROUPS.md](PHASE5-LAND-ESTATES-GROUPS.md), [PHASE5-REGION-FEATURES.md](PHASE5-REGION-FEATURES.md) and [PHASE6-VOICE-SEARCH-IM.md](PHASE6-VOICE-SEARCH-IM.md) assign. A hand-off names that id. A component the inventory shows disabled is not required for the last local C# process to stop. An installation that never enabled the optional money server does not migrate a money database in order to turn that process off. The compatibility drills stay on SQLite, MySQL and PostgreSQL.

`GridCommon.ini.example` 26–32 names `OpenSim.Data.MSSQL.dll`. The tree has MySQL, PostgreSQL, SQLite, Null and the money MySQL assembly, and no MSSQL project. No grid at this pin is on MSSQL. The example is a finding, not a provider to support.

After AS8 stops write-through, an asset rollback loses classes, history and tombstones. Question 12 asks how long any rollback is offered. The rows do not promise a return once Ferroan has stored a row C# cannot represent.

## 6. Questions

These are not decided. Each recommendation is the one the rows assume until the maintainer says otherwise. Where a row says the report does not block a move, that is this section, not a silent default written into the tool as policy.

1. **Numeric bars.** Memory, CPU, latency, region capacity and the throttle and thread-pool knobs. Recommendation: keep measuring against the C# run of the same scenario, and add a bar only when the maintainer names one. P7.36, P7.37 and P7.38 record and do not fail a grid for a number this plan did not set. Capacity already has C#'s own refusal at `agent_limit`. That refusal is the capacity check. A throughput target is separate.

2. **A region that still contains scripts.** Recommendation: the P7.31 report blocks the region move until P4.28a1 through P4.28a5 and P4.28b have passed for that build, and until the Phlox-state section of the Phase 4 plan has a reader for `script_state.db`. A viewer on the Ferroan region would otherwise see a script that does not run, and a restart would drop saved state. The row stays a report until this is answered. There is no single Phase 4 gate row. Naming those conformance rows is the hand-off this plan can make. P7.31a still proves the operational handover of saved state, and it does not decide this block. An unsupported script stays D125: Ferroan refuses it, names the object and the script, and the operator keeps that object on a C# region.

3. **A region that contains physical prims, before P3.28.** Recommendation: the P7.32 report blocks the region move until P3.28. The D38 walking stand-in remains the Phase 2 gate for a region whose content does not need physics. The rest observation until that gate is the shipped `ubODE`, and it is not a substitute for P3.28. A BasicPhysics trace is not either.

4. **What stays C# on a beta, and what production retirement requires.** Recommendation: a beta may keep local C# processes, and the P7.35 manifest names them. Production retirement requires every enabled local component to have a replacement, every old local process stopped, and a fresh login plus the enabled service probes and the neighbour probes to succeed. An enabled connector with no replacement is a blocker. A commented connector is not. OpenId and Appearance block retirement only when an operator has enabled them. Foreign grids stay on their own servers. Janus stays the external voice server. Neither is a local C# process. An installation that never enabled the optional money server does not migrate a money database in order to turn its last local C# process off.

5. **How many regions in one Ferroan process.** C# hosts many regions in one RegionServer (`Regions.ini.example` 8). Ferroan today is one region per process. Recommendation: Phase 7 does not add a multi-region process. The operator runs one Ferroan process per region. P7.36 measures that against the four-region C# process. Moving one region out of a multi-region C# process gives it a new `http_listener_port`, so the grid row's server URI changes, and neighbours and login see that change. The guide says so. A later multi-region process is a separate decision.

6. **Two writers on the auth store.** C# login opens the auth store while it still runs `PasswordAuthenticationService`, including when a Ferroan authentication service is also up. `LLLoginService` passes the config and the user-account service (243–244), and `AuthenticationServicesConnector` has no matching constructor. Authentication moves on P7.40, after P7.27 has stopped C# login, so the auth store has one writer. Rolling the login back to C# while P7.40 is in force opens the window again, and the guide rolls the auth swap back with it. The harness layout that already passes `--rust auth` stays a development layout, recorded and not offered as the cutover, until the maintainer accepts the window.

7. **`DeleteOnUnregister` and the config flags.** The code default is true, and the example omits the key, so a shutdown deletes the `regions` row unless Persistent is set. Persistent arrives through `DefaultRegionFlags` or `Region_<name>` as well as through the stored row. Recommendation: the guide documents both outcomes and P7.9 prints which one the flags and those keys will produce. The C# default stays. Operators who want the row to remain set Persistent, as the example's comment already describes.

8. **Remote admin during a move.** The shipped value is `enabled = false`, and the example password is a placeholder. Recommendation: Phase 7 leaves the module off. Enabling it, and replacing that password, belongs to Phase 5's remote-admin work. P7.33 prints the flag and does not print the password. The same redaction covers `[Network] ConsolePass`.

9. **Beta entry and exit, distinct from production retirement.** Recommendation: a grid is a beta when the P7.35 manifest's Ferroan processes each name a done phase id, the version check and the schema-shape check have passed for each backend in use, the single-writer guard and the close-window handoff have passed, and the remaining processes are C#.
