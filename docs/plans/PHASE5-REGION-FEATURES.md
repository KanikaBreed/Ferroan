Planning note for the manager. This file is the map. It does not add rows to [TASKS.md](../../TASKS.md) or [WORK_QUEUE.md](../../WORK_QUEUE.md). The ids below are proposals. Queue ids are allocated when the rows are accepted.

**Gate** ([PLAN.md](../PLAN.md)): OAR and IAR round trips match the C# server, and the feature checklist reaches parity. The estimate there for the whole of Phase 5 is 24 to 47 person-days. This file is the second half of the Phase 5 sentence. Land, parcels, estates, groups in the region, inventory transfer and the money module are the other half and use other ids.

**Scope here:** NPCs and bots (the NPC module and the region side of its `os` functions), linkset data, Experiences, map tiles (generation, the map-service upload, the world-map blocks), dynamic textures, OAR and IAR beyond Phase 2's load (save oar, load and save iar, the archive formats and options, assets in archives), media (parcel and prim media, the region side of media on a prim), sound (attached sounds, preloads, collision sounds), remote admin (the XML-RPC plugin and its methods), and monitoring (the stats, the monitor module, sim stats sent to viewers, the status endpoints Phase 0 already serves).

- [D39](../DECISIONS.md), amended 26 November 2026. A Phase 2 OAR load persists parcels, restored objects, and region and estate settings. Saving an archive, and IAR round trips, stay in this phase. Starting scripts after a load stays in Phase 4. [plans/PHASE2-GATE.md](PHASE2-GATE.md) records the same split.
- [D42](../DECISIONS.md). A region holds 100,000 prims and a linkset holds 10,000. An archive save walks that scene. It does not raise either cap.
- [D59](../DECISIONS.md) and [TB75](../TRANQUILLITY_BUGS.md). A media element that is not escaped XML must not discard the rest of the part. The object reader already follows that. Prim media in this plan reads the media list the reader kept.

## 1. What Tranquillity does today

### NPCs and bots

An NPC is a root presence with `PresenceType.Npc` and an in-memory circuit. `NPCModule` turns on only when a `[NPC]` section exists and `Enabled` is true, and the default of that key is true (`NPCModule.cs` 54–58). The shipped `RegionServerDefaults.ini` has the section and leaves `Enabled` commented (2810–2812), so both the NPC module and `BotManager` are on. A missing section leaves both off. `BotManager` uses the same test (`BotManager.cs` 184–189). With the module on, `AllowNotOwned`, `AllowSenseAsAvatar`, `AllowCloneOtherAvatars` and `NoNPCGroup` default true, and `MaxNumberNPCsPerScene` defaults to the field's 40 (`NPCModule.cs` 48, 60–74). A negative cap means unlimited. `NoNPCGroup` true means the module does not force the title `- NPC -`.

`BotManager` starts a navigation poll of 500 ms when it is enabled (`BotManager.cs` 162, 191–195) and registers `IBotManager`. It disables itself when `INPCModule` is missing. Persistent bots need a `[BotPersistence]` section. The section is absent from the shipped defaults, and a missing section leaves persistence off (`BotPersistenceManager.cs` 121–126). When the section exists, `Enabled` defaults false (129). The file name defaults to `botpersistence.db`, with `MaxPerParcel` 10, `MaxPerOwner` 15, `MaxPerRegion` 50 and `DefaultTTL` 604800 seconds (136–141). A create that does not ask for persistence does not survive a restart. Console commands on the bot module are `list persistent bots` and `clear persistent bots`.

What another viewer sees is the ordinary avatar path: an `ObjectUpdate` for the presence, `AvatarAppearance`, `AvatarAnimation`, and `ChatFromSimulator` when the NPC speaks. The NPC client does not open a UDP session and does not receive caps. `SendChatMessage` and `SendInstantMessage` on that client raise events for scripts. Coarse locations include the NPC. World-map green dots skip `IsNPC` (`WorldMapModule.cs` 431–432). The shipped `[Map]` comments `ShowNPCs` and does not set the key (544–545).

`MoveToTarget` on the NPC module returns false when the presence is seated or sitting on the ground, and otherwise calls the presence move. Sit calls the agent sit path with a zero offset. Say, shout and whisper inject client chat from the NPC's position, so channel 0 reaches viewers at the normal distances and every channel reaches a script listen. Owner and the sense-as-agent flag are fixed at creation. `CheckPermissions` allows a zero caller, an unowned NPC, the owner, or a caller id equal to the NPC id.

YEngine's `osNpc*` calls `INPCModule`. Phlox's `osNpc*` and `bot*` call `IBotManager`, which then calls `INPCModule`. The 4-argument create differs by door: YEngine follows `AllowNotOwned`, and the Phlox `osNpc` form passes owned. That difference is a script body. P4.S17 and P4.S26 own the bodies. This plan owns the two modules those bodies call, the presence, the packets and the persistence file.

### Linkset data

The store is on the root prim. There is no packet and no capability. The only limit is `LINKSETDATA_MAX`, 131072 (`LinksetData.cs` 16). Cost is the UTF-8 length of the key, plus the value when the value is not whitespace, plus `max(password length, 32)` when a password is set (`LinksetData.cs` 440–457).

`AddOrUpdateLinksetDataKey` (127–157) returns 1 when `BytesFree` is already 0, 2 for a blank key, −1 for a bad password, and 2 when the value is unchanged. Otherwise it subtracts the old cost, stores the new entry and adds the new cost, and returns 0. The limit test runs before the old cost is removed. `LinksetDataAccountingDelta` (385–391) lets `BytesUsed` pass 131072 and then clamps `BytesFree` at 0. `DeleteLinksetDataKey` (170–194) returns −1 for a blank or missing key, 1 for a bad password and 0 on success. `CheckPassword` (417–421) accepts any supplied pass when the stored password is empty. The comment above that line describes the opposite. The code is what a script observes, and [plans/PHASE4-SCRIPTING.md](PHASE4-SCRIPTING.md) already tells the function row to match the code.

The region store column is `prims.linksetdata`, one JSON blob. Empty is SQL NULL. `SerializeLinksetData` returns null when the store is empty. Object XML writes a `LinksetData` element from that same JSON when it is non-empty. Ferroan already parses that JSON on the part (`crates/ferroan-scene/src/payloads.rs`, `LINKSET_MAX`). The live key-value calls, the `linkset_data` event and the merge on link are not that parser.

A link copies the incoming root's keys into the destination. Destination keys win, and the source store is cleared. No `linkset_data` event is posted for that merge. The script event and the LSL status integers are P4.S4. This plan is the store those calls read and write, including the password, the byte account and the prim column.

`LinksetData.cs` has no licence header. The existing parser keeps the BSD and MPL notices already recorded on that port.

### Experiences

The region module is off unless `[Experience]` exists and `Enabled` is the string `true`. The default of that key is `false` (`ExperienceModule.cs` 47–57). `ExperienceCreators` defaults to `EstateManagersAndRegionOwners` (61). The module is shared and keeps one `Scene` (`ExperienceModule.cs` 33, 68–73).

When it is on, login loads that agent's permission rows, and the module registers these caps (`ExperienceModule.cs` 131–165): `GetExperiences`, `GetAdminExperiences`, `GetCreatorExperiences`, `AgentExperiences` (GET and POST on one URL), `GetExperienceInfo`, `IsExperienceAdmin`, `IsExperienceContributor`, `RegionExperiences`, `UpdateExperience`, `GetMetadata`, `GroupExperiences`, `FindExperienceByName`, `ExperienceQuery` and `ExperiencePreferences`. There is no viewer key-value cap. Key-value is a script call that reaches the service.

The grid route is `POST /experience` with a form field `METHOD` (`ExperienceServerPostHandler.cs` 21–66): `getpermissions`, `updatepermission`, `getexperienceinfos`, `getagentexperiences`, `updateexperienceinfo`, `findexperiences`, `getgroupexperiences`, `getexperiencesforgroups` and `accesskvdatabase`. The key-value actions are `GET`, `CREATE`, `UPDATE`, `DELETE`, `COUNT`, `GETKEYS` and `SIZE` (310–397). `GET` answers `success` plus `value`, or `missing`. `CREATE` of a key that exists answers `exists`. The service quota constant is 128 MiB (`ExperienceService.cs` 21). The store is MySQL only. [P1.12](../../TASKS.md) is that connector and that store, and it is blocked on P1.0 and P1.1. Tranquillity has no SQLite experience store. Both the connector and the service are off in the shipped grid config.

Estate allow, key and block lists are estate rows, not experience-service rows. A parcel allows an experience with a land-access entry whose flags are 8 and whose id is the experience. Those lists are the other half of Phase 5. This plan's region module reads them. It does not create a second experience store.

The permission dialog is `ScriptQuestion` with an experience block, and a grant is the key the script event sees. The script methods that request it are P4.S5. This plan is the cap, the cache, the dialog packet and the service call.

### Map tiles and the world map

Three surfaces. A viewer asks for blocks and items over UDP. The region stores a terrain JPEG and a parcel JPEG as texture assets and copies their ids onto the grid region. A separate map-image service stores zoomed JPEG files.

`WorldMapModule` enables when `WorldMapModule` equals `WorldMap`, and that key defaults to `WorldMap` (`WorldMapModule.cs` 142–144). `BlacklistTimeout` defaults to 600 seconds, stored as milliseconds (146–147). Console commands are `export-map` and `generate map` (173–181). `MapImageModule` enables when `MapImageModule` equals `MapImageModule`, and that key defaults to `MapImageModule` (`MapImageModule.cs` 174–176). `Warp3DImageModule` enables only when the same key equals `Warp3DImageModule`. The shipped `[Map]` comments both names and leaves the legacy module selected (503–508). It sets `DrawPrimOnMapTile`, `TextureOnMapTile` and `TexturePrims` true, `TexturePrimSize` 48 and `RenderMeshes` false (521–532).

`GenerateMaptiles` defaults true. `OnlyGenerateIfMissing` defaults false. `MaptileRefresh` defaults to 0, which starts no timer (`Scene.cs` 1086–1100). When generation is off, a non-zero `MaptileStaticUUID` becomes `TerrainImageID` (1103–1116).

`AddRegion` copies `RegionSizeX` into the field that later code reads as the region's Y size (`WorldMapModule.cs` 167–168). On a square region the two sizes are equal. Ferroan's regions are 256 m square. Section 6 records the copy.

The map-image upload module loads when `[Modules] MapImageService` is `MapImageServiceModule` and `[MapImageService]` exists. `RefreshTime` is read with no default (`MapImageServiceModule.cs` 69–83). A missing key throws while the module loads. The service `POST` is `/map` with form fields `X`, `Y`, optional `SCOPE`, `TYPE` and `DATA`. Omitting `DATA` deletes the tile. A missing tile on `GET /map` is still HTTP 200 and is an ocean JPEG. The region's `MapBlockReply` for a neighbour is a different packet from the offline hop block Phase 2 already sends for a teleport.

`export-map` draws with the same bitmap library as the tile generator. Hypergrid `HGWorldMapModule` replaces `WorldMapModule` when the config name is `HGWorldMap`, and it is the question in section 5. The ordinary module is this plan.

### Dynamic textures

`DynamicTextureModule` registers `IDynamicTextureManager` on every scene (`DynamicTextureModule.cs` 349–355). `[Textures] ReuseDynamicTextures` and `ReuseDynamicLowDataTextures` default false (334–335). When reuse is on, the cache is in memory with a TTL of 24 hours (337–340). There is no `MaxDynamicTextures` key.

The face stores a new texture UUID. The asset is local. A vector drawing is a JPEG2000 codestream. The URL image path and the blend path store JPEG. `osSetDynamicTextureData` and the draw helpers that build the command string are P4.S16. This plan is the module those calls enter: the data and URL entry points, the command parser, the bitmap, the asset id on the face and the texture update a viewer fetches. `GetDrawStringSize` is the size query on the same module (the public method above `Initialise`).

### OAR save and IAR

Phase 2 loads an OAR. The save path is `save oar`. Options (`ArchiverModule.cs` 274–303): `-profile` warns and does nothing, `-home` sets `home`, `--noassets` skips assets, `--publish` sets `wipe-owners`, `--perm=` sets `checkPermissions`, `--all` saves every region. The path defaults to `region.oar`. The overwrite check is commented out (298–301).

`ArchiveWriteRequest` writes major version at most 1 (`ArchiveWriteRequest.cs` 53–58). Defaults are `SaveAssets` true, no permission filter, and a single region (123–125, 132–145). The control file `archive.xml` is the first member (`ArchiveConstants.cs` 40, `ArchiveWriteRequest.cs` 168–169). Then each region, then assets unless `--noassets` (178–200). A region member skips an object that is deleted, an attachment, temporary, or in transit (`ArchiveWriteRequest.cs` 238). `--perm` also skips an object the estate owner may not archive. `Save` writes region settings, each parcel, a `.r32` terrain member and each object's XML2 (579–627). Paths are `settings/`, `landdata/`, `terrains/` and `objects/` (`ArchiveConstants.cs` 59–75).

[TB198](../TRANQUILLITY_BUGS.md) is a terrain member of length zero when a cell is at or above 4095 m, and that archive then fails to load. The save row owns that gate. [TB164](../TRANQUILLITY_BUGS.md) is an IAR load that rewrites the object asset and drops `GroupScriptStates`. P4.22 writes no `GroupScriptStates` into object XML. A compare of an archive load does not expect script state the archive carried.

IAR console usage (`InventoryArchiverModule.cs` 111–142): `load iar` takes `-m|--merge`, the user's first and last name, an inventory path, a password and an optional path. `save iar` takes `-h|--home`, `--noassets` or `--skipbadassets`, the same identity fields, an optional path, `-c|--creators`, `-e|--exclude`, `-f|--excludefolder` and `-v|--verbose`. The default file is `user-inventory.iar` (59). `--home` writes control-file version 1.2. Without it the version is 0.3 (`InventoryArchiveWriteRequest.cs` 591–598). A single-region OAR control file is version 0.8. `--all` writes version 1.0 (`ArchiveWriteRequest.cs` 432–442). The `userprofiles/` path exists (`ArchiveConstants.cs` 80) and `SaveUsers` would write it (`InventoryArchiveWriteRequest.cs` 501–515), but the call is commented out (463–464), so a save writes no user-profile member. Asset members use the same `assets/` path as an OAR.

### Media

Prim media is on when `[MediaOnAPrim]` is absent, because the field starts true (`MoapModule.cs` 55). When the section exists, `Enabled` defaults false, and a false value turns the module off (62–67). The shipped file has the section and sets `Enabled = true` (`RegionServerDefaults.ini` 2805–2807), so the module is on. It registers caps `ObjectMedia` and `ObjectMediaNavigate`, each on a random path (`MoapModule.cs` 107–117). A copy duplicates each `MediaEntry` through OSD (120–137). `HandleObjectMediaMessage` reads LLSD XML (232–258) and answers a get or applies an update. The texture face gains `MediaFlags`, the part is marked changed, and viewers receive a texture update.

Parcel media is `ParcelMediaUpdate` and `ParcelMediaCommandMessage` (`LLClientView.cs` 13072–13097). The update carries the URL, the texture id, autoscale, type, description, width, height and loop. The land store already has `MediaURL`. The script calls that send these packets are P4.S10. This plan is the packet and the cap.

### Sound

With no `[Sounds]` section the module is on and `MaxDistance` is 100 (`SoundModule.cs` 68–71). With the section, `Enabled` is true when `Module` equals the assembly file name plus `:SoundModule`, and `MaxDistance` defaults to 100 (75–78). The shipped file sets that module name and `MaxDistance = 100.0` (`RegionServerDefaults.ini` 2902–2907).

`PlayAttachedSound` (122–160) writes the sound onto the part, adds the queue flag when the part queues, and sends `AttachedSound`. A private attachment goes only to the wearer. Any other attachment is skipped unless the wearer is allowed avatar sounds on the parcel. A null parent group throws, because the deleted test uses a non-short-circuit or (136). Section 6 records that.

`TriggerSound` and `TriggerCollisionSound` (163–257) test radius squared. A radius of 0 becomes `MaxDistance` and is written back onto the part. Collision also skips a presence with `MuteCollisions`. `StopSound` zeros the sound, sets the stop flag and gain 0, and sends a full update (266–272). `PreloadSound` (275 onward) uses the same radius and sends the preload to presences inside it. The collision event that reaches this module waits on the physics plan's collision dispatch. The `ll` and `os` sound calls are P4.S10 and P4.S20.

### Remote admin

The plugin loads only when `[RemoteAdmin]` exists and `enabled` is true. The default of that key is false (`RemoteAdminPlugin.cs` 91–95). The shipped file sets `enabled = false`, `port = 0` and `access_password = unknown`, and leaves `access_ip_addresses` unset (`RegionServerDefaults.ini` 1863–1879). Port 0 uses the region's HTTP server. A non-zero port opens that port. An empty `bind_ip_address` uses the network bind address (118–121).

Every method is an XML-RPC call whose first struct contains `password`. `FailIfRemoteAdminNotAllowed` (244–258) rejects an address outside `access_ip_addresses` when that set is non-empty, and rejects a password that differs from `access_password` when the configured password is non-empty. An empty configured password skips the password test. An empty address list accepts every address.

Methods registered when the plugin is on (`RemoteAdminPlugin.cs` 124–167): `admin_alert_user`, `admin_broadcast`, `admin_create_region`, `admin_delete_region`, `admin_close_region`, `admin_modify_region`, `admin_region_query`, `admin_shutdown`, `admin_dialog`, `admin_restart`, `admin_load_heightmap`, `admin_save_heightmap`, `admin_reset_land`, `admin_get_agents`, `admin_teleport_agent`, `admin_create_user`, `admin_create_user_email`, `admin_exists_user`, `admin_update_user`, `admin_authenticate_user`, `admin_load_xml`, `admin_save_xml`, `admin_load_oar`, `admin_save_oar`, `admin_acl_clear`, `admin_acl_add`, `admin_acl_remove`, `admin_acl_list`, `admin_estate_reload`, `admin_refresh_search`, `admin_refresh_map`, `admin_get_opensim_version` and `admin_get_agent_count`. `enabled_methods` defaults to `all` (170). `admin_console_command` is added whenever that string is non-empty (176–177), which the default `all` is. A whitelist registers only the named methods (188–193).

`create_region_enable_voice` defaults false in the shipped file. `create_region_public` is set false there as well. The comment on that key says the code default is true. The file's value is what a stock config loads.

## 3. Proving equivalence with C#

A row closes on a C# recording, a compiled C# method, a capture, or a store compare. The expected bytes come from that run. Copying a number out of the lines cited above and checking Rust against that copy does not close the row. A Ferroan save loaded by Ferroan does not close an archive row. Pin9 loads the Ferroan archive, and Pin9's own save of the same scene is the other file. Ordinary CI does not start Tranquillity unless an existing tool already does. A live run takes the live lock and uses the bot named in [LIVE.md](../LIVE.md).

What compares exactly: NPC create and delete (presence type, owner, group title, the appearance packet, no grid-user row), chat channel and distance, linkset return codes and the JSON column, experience cap LLSD and the `/experience` form, map-block fields, archive member names and the control file, media cap LLSD, sound packet fields and the radius test, remote-admin success and error structs, and the sim-stats words whose inputs are fixed. A stat that C# leaves at a constant, including `SimPhysicsStepMs` 20 and a `PendingUploads` C# has not filled, matches that constant.

What needs a tolerance, and only after section 5 names it: a map JPEG or a dynamic-texture image where text or filtering differs from Skia. A shaded height colour and an inverted prim colour are formulas and compare exactly once the drawer is the one the maintainer allows. NPC positions that physics integrates use the Phase 3 envelope. The packet identity, the sit refusal and the chat do not use that envelope.

### Risks

- The experience rows stay blocked until P1.12 has a service to call. A region cap proven against a stub is not the store.
- Map pixels and dynamic textures wait on the drawer question. A row that starts before that choice can record the command parser and the asset id, and it cannot close on pixels.
- `save oar` of a tall region is [TB198](../TRANQUILLITY_BUGS.md). The save row's evidence includes a region whose highest cell is at or above 4095 m, and Pin9 must load the member Ferroan wrote.
- Remote admin can create a region, create a user and run a console command. The rows cover the XML-RPC forms. Binding policy is a question. The evidence uses a local listener and a password set for the test.
- Bot navigation is a 500 ms poll with a 60 s teleport fallback. One day covers the poll and the arrival rule. Path events for every `bot*` name stay on P5.47, and that row splits if the method list does not fit.
- An NPC walk that is only the Phase 2 stand-in will not match a Pin9 capture taken with Jolt. P5.42 proves the module's refusals and the movement call. Position samples wait on the Phase 3 character.

## 5. Questions

Each item has a recommendation. None of them is decided.

1. **What draws map tiles, the world-map export and dynamic textures.** C# uses Skia. [D8](../DECISIONS.md) does not allow that library. Recommendation: pick a drawer D8 allows, and prove a tile by loading Pin9's stored JPEG for a scene whose colours are formulas (shaded height, inverted prim colour, the water colour the renderer uses). Where the image is text or a filtered sample, the maintainer names the tolerance in the same decision. This plan does not name a tolerance and does not name a library. Rows: P5.57, P5.61, P5.62.

2. **Which map generator ships.** The name key defaults to `MapImageModule`, and the shipped file leaves that default in place. `Warp3DImageModule` enables only when the key is set to that name. Recommendation: ship the legacy generator. A Warp3D row is added later, inside this id range with a letter suffix, only if the maintainer wants those images. Rows: P5.57.

3. **Experience storage.** The region module is a client of the service [P1.12](../../TASKS.md) already names. Tranquillity's store is MySQL, and both the connector and the service are off in the shipped grid config. Recommendation: do not build a second store in the region, and do not add a SQLite experience store that the pin does not have. P5.51 through P5.54 stay blocked on P1.12. Rows: P5.51, P5.53, P5.54.

4. **Remote admin exposure.** The shipped file leaves the plugin off, sets the password to a well-known word, and leaves the address list unset. The code skips the password test when the configured password is empty, and an empty address list accepts every caller (`RemoteAdminPlugin.cs` 244–258). Recommendation: stay off unless `enabled` is true, and refuse to bind while the password is empty or still that shipped word. `admin_console_command` is part of the default `all` set. Include it only when remote admin is on, behind the same check, and log the command. Rows: P5.74, P5.77. Section 6.

5. **Hypergrid world map.** `HGWorldMapModule` replaces the ordinary module when the config name is `HGWorldMap`, and it adds the seen-block reset and the map-server URL. Recommendation: this plan ports `WorldMapModule` only. The hypergrid module waits on the hypergrid visitor path and is not given a row in this range. Rows: P5.55.

6. **Linkset account past 131072.** A write is accepted when `BytesFree` is above 0, and the account is then clamped, so one write can pass 131072 and return success. A later shrinking update of that key is refused because the limit is tested first (`LinksetData.cs` 131–156, 385–391). A script can see the return code. Recommendation: match the pin's return codes, so a script that fills the store sees the same success and the same later refusal. The defect is recorded in section 6. A corrected account, which subtracts the old cost first and refuses a write that would pass 131072, is the alternative. Rows: P5.48.

7. **World-map Y size.** `WorldMapModule.cs` 168 copies `RegionSizeX` into the Y size. Recommendation: use `RegionSizeY`. A 256 m square region hides the copy. Rows: P5.55. Section 6.

8. **NPC enablement.** The shipped section turns the modules on, with a cap of 40. Recommendation: match that. The cap becomes a [LIMITS.md](../LIMITS.md) id when P5.40 lands. This plan does not name the id. Rows: P5.40.

9. **Where the code lives.** [ARCHITECTURE.md](../../ARCHITECTURE.md) puts map and dynamic textures in `ferroan-modules`. The other modules in this file have no crate named. Recommendation: map and dynamic textures go in `ferroan-modules`. NPCs, linkset data, Experiences, archives, media, sound, remote admin and the stat values stay in the region and scene crates that already hold presence, archives and status. No new crate. Rows: all of section 4.

10. **Map image service process.** P5.59 is the region's upload and the files the service stores. The service process is a separate HTTP server. Recommendation: prove the upload against Pin9's service, and leave a Ferroan service process out of this range until the maintainer asks for it. Rows: P5.59.

11. **Save-oar terrain at or above 4095 m.** [TB198](../TRANQUILLITY_BUGS.md) already assigns this gate to the save row. Recommendation: P5.64 writes a terrain member Pin9 can load, and the load is the evidence. The bug is not refiled. Rows: P5.64.
