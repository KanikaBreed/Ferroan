## 1. Voice

Janus is external. The region is a client of its HTTP API. The addon is `Addons/os-webrtc-janus`, about 30,081 lines. The module name the region returns is `RegionVoiceModule` (`WebRtcVoiceRegionModule.cs` 145–148).

### What a viewer can observe

`[WebRtcVoice] Enabled` defaults to false (`WebRtcVoiceServiceModule.cs` 75, and `os-webrtc-janus.ini` line 2). While it is false, `RegionLoaded` does not register CAPS and does not set a voice feature (`WebRtcVoiceRegionModule.cs` 116–133). While it is true:

- The simulator feature `VoiceServerType` is the string `webrtc` (`WebRtcVoiceRegionModule.cs` 128). The CAP that carries it is P6.47. Nothing in `crates/` serves `SimulatorFeatures` today, and no earlier plan owns `SimulatorFeaturesModule.cs`.
- `StunServers` defaults to the empty string (`WebRtcVoiceRegionModule.Stun.cs` 57). A whitespace value is omitted. A non-empty value is one feature, `stun-servers`, whose LLSD value is that string (`OSD.FromString`, `WebRtcVoiceRegionModule.Stun.cs` 46–50). It is an LLSD string. The comment on that file says a viewer that reads `SimulatorFeatures["stun-servers"]` needs a non-empty valid entry or peer-connection setup fails with an empty ICE URI.
- Login and a region crossing register three CAPS (`WebRtcVoiceRegionModule.cs` 180–196): `ProvisionVoiceAccountRequest`, `VoiceSignalingRequest`, `ChatSessionRequest`. `RegisterModerationCapability` runs on the same path (198). It registers `SpatialVoiceModerationRequest` only when `VoiceModerationEnabled` is true (`WebRtcVoiceRegionModule.Moderation.cs` 193–200). That switch defaults to false (`DefaultVoiceModerationEnabled`, 54–59). `CallModerationEnabled` is a different switch and does not gate this CAP. `ParcelVoiceInfoRequest` is absent from this registration. P6.2 compares the seed with a C# seed capture.

`ProvisionVoiceAccountRequest` (`ProvisionVoiceAccountRequestCore`, 211–423) reaches the service only after admission:

| Request | Answer |
| --- | --- |
| No `IWebRtcVoiceService` | HTTP 404, no body (215–220) |
| Method other than POST | HTTP 404 (223–227) |
| Body that is not an OSD map | HTTP 204 (231–236) |
| `voice_server_type` present and not `webrtc`, case-insensitive | HTTP 200 and the bytes `<llsd><undef /></llsd>` (65, 240–248). The comment names Firestorm's Vivox probe. FreeSwitch uses the same bytes for a type other than `vivox` (`FreeSwitchVoiceModule.cs` 333–339) |

Admission is `TryAdmitProvision` (`WebRtcVoiceRegionModule.NonSpatial.cs` 297–350) and `A2AProvisionAdmission` (112–155). `NonSpatialVoiceFeatureOn` is avatar-to-avatar, usable group voice, or ad-hoc (353). Those default off. While they are off:

- A body that is not a logout, and whose `channel_type` is `multiagent` or absent, is `IsPassthroughBody`. It is handed to the voice service unexamined (`Passthrough`). The comment at `WebRtcJanusService.cs` 271–275 says the same thing: the region admits `local`, admits a call it knows, or passes the body through while no call feature is on.
- `local` and logout are admitted by `Decide` (139–140). A `local` body then takes the parcel and estate checks below.
- Every other channel type is HTTP 403 and the undef bytes (340–347).

Together with the stock `start p2p voice` answer, that passthrough is how peer-to-peer voice works on a stock region.

The parcel and estate checks run for an admitted `local` body (263–392):

- Estate `AllowVoice` false is HTTP 501 and the undef bytes (270–275). `AllowVoice` defaults to true (`EstateSettings.cs` 141).
- No land channel, or a resolved parcel with no land data, is HTTP 501 (277–281) or HTTP 404 (340–347).
- A missing avatar is HTTP 404 and the undef bytes (285–290).
- Parcel voice off, or the avatar barred, is HTTP 403 and the undef bytes (365–377).

The parcel for a root agent comes from the avatar's position, not from the viewer's `parcel_local_id` (293–309). A mismatch is logged and the server parcel wins (350–352). A child agent's client id is a hint, accepted only when `ChildParcelProximity.IsNear`. Otherwise the id is dropped and the service uses the estate room (311–323). `ParcelFlags.UseEstateVoiceChan` removes `parcel_local_id` (380–382). The server-position path writes the server local id into the map before the service call (384–388).

`ProvisionParcelAccess.Check` (`ProvisionParcelAccess.cs` 38–52, MPL-2.0) returns `VoiceOff` when `ParcelFlags.AllowVoiceChat` is unset, `Barred` when the simulator bars the avatar or `LandBan.IsBanned`, and `Allowed` otherwise. The check runs on every estate, including TaxFree (354–356). Parcel flags and estate `AllowVoice` already arrive with Phase 2 parcel and estate data (P2.6b, [D39](../DECISIONS.md)). The access list is stored by P2.0e4.w1. `IsBannedFromLand` and `IsRestrictedFromLand` are Phase 5 logic. Until that evaluation exists, P6.4a's barred case supplies the boolean the check reads. The stored flag and the stored access list are the Phase 2 data.

The service map is serialised as LLSD XML (404–406). `error_code` equal to `JANUS_ROOM_FULL_ERROR_CODE` (495, `WebRtcJanusService.Hardening.cs` 49) becomes HTTP 409 (407–412). Every other failure map stays HTTP 200. A null service map is HTTP 200 with no body (418–421).

The three maps are pure (`Janus/ProvisionResponseBuilder.cs`, MPL-2.0, 23–59). Success keys, in order: `jsep`, `viewer_session`, `room`. Failure keys: `response` = `failed`, `error`, and `error_code` only when non-zero. Logout: `response` = `closed`. The comment says `ProvisionResponseShapeTests` pins the shape.

### What the voice service does before Janus

The region CAP calls `IWebRtcVoiceService.ProvisionVoiceAccountRequest(map, agent, scene)` (`WebRtcVoiceRegionModule.cs` 397). `WebRtcVoiceServiceModule` registers that interface (172) and hooks `OnClientClosed` (180). Its provision dispatch is 207–329.

- A provision first re-drives any closing sessions still parked for that agent (209–221).
- A logout whose `viewer_session` is absent, the zero UUID, or unknown returns `{response: closed}` without calling Janus (226–254). A logout whose session belongs to the caller falls through to the session's own logout, which is P6.8a.
- A `viewer_session` must belong to the caller. Another agent's id resolves to nothing (234–238). A logout then answers `closed`. Any other request leaves the response null, so the CAP is HTTP 200 with no body.
- An NPC provision returns null (`RefuseNpcProvision`, 257–258, `WebRtcVoiceServiceModule.NpcVoice.cs`, MPL-2.0). The CAP is HTTP 200 with no body.
- The service holds a refusal cache of failure maps (`m_refusalCache`, 263–264 and 304–309), beside the region's cache of HTTP 403, 404 and 501.
- A body with no `channel_type` logs `no channel_type in request` and leaves the session null (286–289). The CAP is HTTP 200 with no body (418–421). On the default passthrough, an untyped body takes this path. A `multiagent` body creates a session on the non-spatial service (277–284).
- A session this call created is removed and shut down when `createdHere && IsFailedProvision` (295–327). The success path is `createdHere && !IsFailedProvision` (300), which logs that the agent was admitted. A session the viewer already holds is left in place.

`VoiceSignalingRequest` on the service (333–355) returns null when `viewer_session` is missing or belongs to someone else. The CAP still writes HTTP 200 and the undef bytes.

Service selection (`WebRtcVoiceServiceModule.cs` 84–132):

- Both `SpatialVoiceService` and `NonSpatialVoiceService` empty logs `No VoiceService specified in configuration` and disables the module (89–94).
- An empty non-spatial name is copied from the spatial name (96–100).
- An empty spatial name fails the plugin load and disables the module (105–110). That is a different log from the both-empty path.
- Identical DLL names share one instance (124–131). Two different names load two plugins.

### Close teardown

`Event_OnClientClosed` (`WebRtcVoiceServiceModule.CloseTeardown.cs` 66–135) runs inside client removal. A missing presence or a child presence returns immediately and captures nothing (69–70). `CaptureForClientClose` returns an empty list for a child (140–144). A root close captures by login generation: the closing client's `SessionId` (75) is passed to `CaptureForClientClose` (104). It captures the agent's voice sessions in every region of the process except regions where the agent is still root (93–109), then shuts those sessions down asynchronously (134, 175–195). A test that reuses an agent across logins needs that generation. A failed shutdown stays parked and records the failure. The console command `show voice closing` is registered at 200–208. The handler (210–218) prints `No voice sessions in closing state.` when the set is empty.

### Signaling and chat

`VoiceSignalingRequest` on the region (426–471) uses the same 404, 204 and non-webrtc gates as provision. It then calls the service and discards the map. The CAP always writes the undef bytes and HTTP 200 (467–470). The comment at 467 is a TODO to check errors and package the response. The service itself builds a map (`WebRtcJanusService.cs` 380–466): no Janus session yields `response` = `error` and `error` = `no voice session`; a completed candidate, one candidate line, or a `candidates` array become trickle operations; anything else is an error map. The CAP does not return that map. Reproducing the CAP bytes is question 10. The service returning null for a missing or foreign session is part of P6.9, and it is the same viewer-visible answer.

`ChatSessionRequest` (483–573). Non-POST is 404. A missing or deleted presence is 404. `RefuseChildChatSession` refuses a child only when a call feature is on (`WebRtcVoiceRegionModule.NonSpatial.cs` 355–357). At the defaults the request is answered by the stock switch. A body that is not a map is 204. `TryHandleNonSpatialChatSession` returns false when A2A voice is off (410–411), so the stock switch answers. A missing `method` or `session-id` is 404. `decline p2p voice`, `decline invitation`, `start conference` and `fetch history` are HTTP 200 with an empty body (533–538). `start p2p voice` builds a session id as the XOR of the other agent's UUID and the caller when `params` is a UUID, otherwise a random UUID (541–546), posts `ChatterBoxSessionStartReply`, and returns HTTP 200. No event queue is HTTP 500 (548–552). Any other method is HTTP 400 (570–571).

The event signature is `(sessionID, sessionName, type, voiceEnabled, voiceModerated, tmpSessionID, sucess, error, toAgent)` (`IEventQueue.cs` 93–96). The parameter is spelled `sucess`. The call passes `newSessionID`, the presence name, type 2, `false`, `true`, the viewer's session id, success true, an empty error, and the agent id (`WebRtcVoiceRegionModule.cs` 556–565). On the wire `voice_enabled` is false and `moderated_mode.voice` is true. The event also carries `session_id`, `temp_session_id`, `success`, and on success a `session_info` map (`EventQueueGetHandlers.cs` 272–295). The comment at `WebRtcVoiceRegionModule.NonSpatial.cs` 451–452 says the viewer reads neither voice field. That swap is not proposed as a TB. `ChatSessionRequestLogic.cs` is MPL-2.0 and is the non-spatial chat path question 1 leaves off. The stock switch this gate ports is the BSD region module.

### What the region sends to Janus

`[JanusWebRtcVoice]` supplies `JanusGatewayURI`, `APIToken`, `JanusGatewayAdminURI` and `AdminAPIToken`. All four are required. Any empty value disables the service (`WebRtcJanusService.cs` 99–104). A missing section disables it (119–123). When the four are set, `StartConnectionToJanus` runs at startup. Failure disables the service and returns (106–116). `MixerOnlySwitches.DisableOnStockPlugin` runs at 91 (`WebRtcVoiceRegionModule.cs` 85–86). A token shorter than 32 characters logs a warning (`WebRtcJanusService.Hardening.cs` 61–71, `MinSecretLength`). `RequestTimeoutMs` defaults to 5000 (`JanusSession.RequestTimeouts.cs` 43–44). The plugin name defaults to `janus.plugin.audiobridge` (`WebRtcJanusService.PluginName.cs` 38). `RemoveEmptyRooms` defaults to true and `EmptyRoomGraceSeconds` to 60 (`EmptyRoomReaper.cs` 31–33). `StartRoomReaper` runs at startup (115). The reaper is built in `WebRtcJanusService.RoomReaper.cs` 39–50: the key can turn it off, and a plugin other than the stock AudioBridge does not get a second remover. `janus info` is a console command (`WebRtcJanusService.cs` 497–527). P6.6a compares its text from fixed state, with wall-clock fields masked, the same rule as the physics console rows.

The session overload does the join (227–377). A connect failure returns `BuildFailure("janus unavailable", 0)` (243–250). `logout` true leaves the room and returns `BuildClosed` (255–268). A missing `parcel_local_id` becomes `JanusAudioBridge.REGION_ROOM_ID`, which is −999 (`JanusAudioBridge.cs` 134, used at 276). The room key reads `channel`, then `channel_id` (277–282). A JSEP whose type is not `offer` fails with `jsep type not offer` (353). No JSEP fails with `no jsep` (359). Room selection failure is `room selection failed` (303–304). A successful join is `BuildSuccess` with the room id (320). Room full sets the text `room is full` and `error_code` 495 (322–328), which the CAP turns into HTTP 409. Error 485, the room gone between create and join, is `JoinRoom failed` with no `error_code` (332–341).

`CalcRoomNumber` (`JanusAudioBridge.cs` 142–172) uses `BHasherMdjb2`. A `local` room hashes the region id, the type and the parcel local id, and ignores the grid id. A `multiagent` room folds a non-empty grid id, then the channel id, then the type. An empty grid id adds nothing. Any other type throws `Unknown channel type`. The grid id is `ReadGridId` (`JanusAudioBridge.GridId.cs` 52–66): `GatekeeperURI` through `[Const]`, `[Startup]` and `[Hypergrid]`, then `[GatekeeperService] ExternalName`, then `[GridService] Gatekeeper`. The value is trimmed, the trailing slash is stripped, and the rest is lower-cased. There is no DNS lookup. An unconfigured grid id is empty. `FoldHashToRoom` (`JanusAudioBridge.RoomGate.cs` 130–131) maps `int.MinValue` to `int.MaxValue` and takes the absolute value of every other code, because `Math.Abs(int.MinValue)` throws and a Janus room number is positive. `SelectRoom` (177–185) always asks the mixer to create the room. "Already exists" (486) is success (`JanusAudioBridge.RoomGate.cs` 71–83). `CreateWithRecheck` runs the create once more when the first attempt returns null (43–53). The room description is `region/type/parcel/channel`.

`WebRtcJanusService`'s three-argument `ProvisionVoiceAccountRequest` throws `NotImplementedException` (470–472). The grid path does not call that method. See question 8.

`[WebRtcVoice] SpatialVoiceService` defaults, in the example ini, to `WebRtcJanusService.dll:WebRtcJanusService` (in-process). The alternative `WebRtcVoice.dll:WebRtcVoiceServiceConnector` talks to a grid URI.

## 2. Search

Two region modules exist. The shipped includes set `[Modules] SearchModule = "BasicSearchModule"` in `config-include/Standalone.ini` (24), `Grid.ini` (27), `StandaloneHypergrid.ini` (29) and `GridHypergrid.ini` (33). There is no Robust search service in the tree. The XML-RPC search server is in the tree at `Addons/OpenSimSearch/php/`: `query.php` (682 lines), `parser.php` and `register.php`. `query.php` is a PHP PDO MySQL client. Its header comment names `DirFindFlags`. It is the reply-shape reference the stub replays. OpenSearch is the region's XML-RPC client of that server, or of whatever URL `SearchURL` names. UserProfiles (P1.11) stores profiles, picks, classifieds and notes, and speaks JSON-RPC. Its `classifieds_info_query` is a different service from OpenSearch's XML-RPC method of the same name (question 9).

`InstantMessageMuteCheck.IsMutedByRecipient` is called from `MessageTransferModule.cs` 147 and `HGMessageTransferModule.cs` 132. The call site is P4.30's hook. The callee is P6.38. Only `MessageFromAgent` and `MessageFromObject` are considered (`InstantMessageMuteCheck.cs` 162–166). A zero recipient, or a sender equal to the recipient, is not muted (168–171). An object message uses `imSessionID` as the prim; when a part is found, the id becomes the root and the object flag is cleared (175–191). A row matches the sender id or the object id (212). Flag `0x1` (`MuteFlagTextChat`, 68) skips that row (215–217). A name is split on the first two spaces, then the last vertical bar in the remainder is the flags (209–215). Length 0 or 1 mutes nothing (204–205). No mute service mutes nothing (193–194). The cache lifetime is 60,000 ms (71). The read timeout is 3 seconds (74). A failed or slow read lets the message through and caches the miss, with at most one warning per cache lifetime (59–63, 126–134). `Remember` ignores null and the one-byte token. `Forget` runs on a local mute change. A change on another simulator appears after the cache expires. Because the hook returns before `OnUndeliveredMessage`, a muted IM is not stored by P6.30.

### How a row is proved

The region logic is a scripted `IMuteListService` returning the byte arrays the pin's service returns: empty, the one-byte token, and a multi-line file. The mute-file bytes and the three reply packets are compared with captures. The transfer that carries a file longer than one packet is the Phase 5 Xfer row. TB231 is recorded and fixed in Ferroan unless a viewer depends on the empty list (question 7). The SQLite primary key stays on P1.8. The IM check is a table of dialogs, ids, the `0x1` flag, an empty body and the one-byte token, and a muted IM produces no offline store. A live run, under the shared live lock with a free port base and `UseSharedCompilation=false`, stores a mute through the pin's service or through P1.8, compares the list file, and checks that an IM from the muted agent is not delivered and an IM from anyone else is. A Ferroan-to-Ferroan round trip is not the pass.

### Risks

The module stays off until Xfer and a mute service exist, so the Phase 5 Xfer row, P6.35a, P6.35b and P6.51 land before a live mute can pass. The file line is parsed by splitting on a space and a vertical bar. A mute name that contains a newline or a vertical bar changes how that line splits. That is a behaviour note in section 8, not a TB candidate. The OpenSimMutelist addon is a second module behind a different config string. The shipped core default is `None`, so a region that never sets `MuteListModule` has no mute list.

## 6. Estimate

The table has 48 rows. The gate figure is about 70 to 120 coder-days. The band stays at that figure with map-name search on P5.56a, because review and the rows that overrun a day still sit inside it. A row that overruns a day splits before the next one starts.

What drives the band is review, the voice surface the first cut missed, and the rows that were already more than a day. The service-module dispatch, close teardown, the default passthrough, the Janus startup and the reaper, SimulatorFeatures, the mute-file slice, and the two region connectors are all in the 48. Search, offline IM and the mute list each have outside-size caps.

[PLAN.md](../PLAN.md) still says 7 to 14 person-months, at 3,000 to 6,000 lines of C# a person-month. The WebRTC addon is about 30,081 lines, which is about 5 to 10 person-months before search, offline IM and the mute list. The gate slice is a spatial local room, the default peer-to-peer passthrough, the region search modules against a captured search server, the V2 offline region module, and the core mute list. It leaves most of the PLAN range. What remains is the rest of the WebRTC addon (non-spatial calls, group voice, moderation, visibility, the position feed, NPC connectors, and hosting the Robust voice service), a Rust search service, and DataSnapshot if question 3 defers the publisher.

## 7. Questions

Each item is open. The recommendation is a recommendation. The maintainer decides.

1. **How much of the WebRTC addon is in this gate.** At the defaults, a `multiagent` body and a body with no `channel_type` reach the voice service unexamined, `local` and logout are admitted, and every other channel type is HTTP 403 with the undef bytes (P6.42). The stock `start p2p voice` answer is P6.12b. Together those are peer-to-peer voice on a stock region. Recommendation: the gate includes spatial local rooms. Non-spatial features, group voice, moderation, visibility, the position feed, NPC connectors beyond the refusal, and hosting the Robust voice service wait for a later id block. They are most of the 30,081 lines. This question makes no recommendation on reproducing the default passthrough until the sentence in section 8 is filed. Rows: P6.1 through P6.18, P6.40, P6.41 and P6.42.

2. **Vivox and FreeSwitch, including `ParcelVoiceInfoRequest`.** Recommendation: leave them unported. A WebRTC region does not register `ParcelVoiceInfoRequest` (the seed check is P6.2). FreeSwitch answers a `voice_server_type` other than `vivox` with the same `<llsd><undef /></llsd>` bytes WebRTC uses for a non-webrtc type. `<llsd>undef</llsd>` is FreeSwitch's missing-avatar answer and its exception answer. Do not publish the FreeSwitch password value.

3. **Where search is served, and whether a Rust region has to publish a snapshot to be findable.** Recommendation: port the region modules and treat the XML-RPC search server as external. `query.php` is the reply-shape reference. Proof is a captured XML-RPC reply, including a success with no `data` member. The gate sentence "search works" for queries against that server does not require the Rust region to be in the index. Findability of the region's own parcels needs DataSnapshot (`index_sims` defaults to false, `m_enabled = false` at `DataSnapshotManager.cs` 47). Recommendation: that publisher waits, and the gate says so. A Rust search service waits with it. P1.11 keeps profiles, picks, classifieds storage and notes. `MapNameRequest` is P5.56a. Rows: P6.19 through P6.25, P6.27, P6.28, P6.46 and P6.53.

4. **Which search module a Ferroan region enables.** Recommendation: `BasicSearchModule`, matching the four shipped config-include files and the `GetString` default. OpenSearch runs when `[Search] Module` is `OpenSimSearch` and `SearchURL` is set. When both are on, both subscriptions stay: OpenSearch answers places, popular, land, events, classifieds and map items, and BasicSearch answers people and groups. Rows: P6.19 and P6.21.

5. **Which offline module.** Recommendation: `Offline Message Module V2`, because P1.9 names that addon and an empty `OfflineMessageURL` constructs a local service. The core `OfflineMessageModule` (`OfflineMessageModule.cs`) enables only when the config string equals that name. The `GetString` default is `None`, so an unset key stays off. It requires a non-empty `OfflineMessageURL` and constructs no local service. An empty URL logs an error and disables the module. Retrieve POSTs `{url}/RetrieveMessages/` with the agent UUID (`OfflineMessageModule.cs` 196). The start path logs `Diabling offline messages` and then dereferences the null transfer module (102–114), the same failure as TB230. This plan records that module here and does not port it. Rows: P6.29 through P6.31 and P6.50.

6. **Which mute module.** Recommendation: the core `MuteListModule`, config value `MuteListModule`. The OpenSimMutelist addon, config value `OpenSimMutelist`, stays unported in this range. Row: P6.35a.

7. **What Ferroan does about TB229, TB230, TB231 and TB232.** [TRANQUILLITY_BUGS.md](../TRANQUILLITY_BUGS.md) step 2: Ferroan reproduces a C# bug only where a viewer or another server depends on it. Otherwise Ferroan does what the fixed C# would do, and records a TB and a decision. Ferroan never changes a protocol, schema or file format to work around a bug. Recommendation, one bug at a time. TB229's double reply is bytes a viewer can receive. No viewer or other server is named that depends on receiving two replies. Send one reply, and record the TB and a decision. TB230 is a null dereference at region start and in `RemoveRegion`. Nothing on the wire depends on the crash. Fix it, record the TB, and record a decision. TB231 is an empty mute list about once in 2^32. Recommendation: fix it and record the TB and a decision, unless a viewer turns out to depend on that empty list. TB232 is P1.8's SQLite store, one mute row per agent. P1.8 already lists TB34 as a store bug not to copy. Phase 6 does not copy TB232. The first-scene scope of people and group search is a behaviour note. Map-name search carries the same note on P5.56a. It is not a fifth TB id. The zero-valued group blocks and the land-for-sale placement are listed in section 8 for the manager. They are not given ids here.

8. **Whether Ferroan hosts the Robust voice JSON-RPC service.** The grid connector works at Pin9. `WebRtcVoiceServiceConnector`'s three-argument `ProvisionVoiceAccountRequest` returns null (92–96). The session overload (99–118) sends JSON-RPC `provision_voice_account_request` with keys `request`, `userID` and `scene`, then synchronises `viewer_session`. `EnsureSpatialRoom` returns null (81). `WebRtcVoiceServerConnector` loads `LocalServiceModule` defaulting to `WebRtcVoiceServiceModule.dll:WebRtcVoiceServiceModule` (71–75), registers the JSON-RPC handlers (89–90), and calls the service module's three-argument method (110–114), which is the dispatch P6.40 ports. `WebRtcJanusService`'s three-argument method throws, and this path does not call it. Recommendation: leave the Robust service unhosted. In-process Janus is the gate. Hosting the service remains open for a later block. There is no row that closes by writing down the throw.

9. **Who answers `ClassifiedInfoRequest` and `MapItemRequest`.** Recommendation: the directory packet stays on OpenSearch XML-RPC (P6.25). The UserProfiles JSON-RPC method of the same name stays on P1.11. `UserProfileModule` also answers the region `ClassifiedInfoRequest` packet, and with both modules on the viewer can receive two replies. Those two answers stay until the maintainer says otherwise. `MapItemRequest` is answered by OpenSearch and by `WorldMapModule`, which is Phase 5. The service map, and the null the service returns for a missing or foreign session, are recorded on P6.9 and are not returned. This is not one of TB229–TB232. Row: P6.9.

## 8. Bugs

TB229 through TB232 are proposed here. They are not yet rows in [TRANQUILLITY_BUGS.md](../TRANQUILLITY_BUGS.md). The manager files them. Each is at problem level. Question 7 is what Ferroan does about each one. The author's range has no free id past TB232, so the two further candidates are listed and not numbered.

**TB229.** `BasicSearchModule.OnDirFindQuery` (`Source/OpenSim.Region.CoreModules/Framework/Search/BasicSearchModule.cs` 152–165 and 208–221) at `41f18f983b`. An empty query text sends an empty people or groups reply and does not return, so the lookup still runs and a second reply can be sent. This row is that double reply.

**TB230.** `Addons/OpenSim.Addons.OfflineIM/OfflineIMRegionModule.cs` 85–96 and `RemoveRegion` at 107, and `Source/OpenSim.Region.CoreModules/Avatar/InstantMessage/OfflineMessageModule.cs` 102–114, at `41f18f983b`. When no `IMessageTransferModule` is loaded, each module logs and then dereferences the null transfer module. Region start fails at that line. The core module's log text is `Diabling offline messages`.

**TB231.** `MuteListService.MuteListRequest` (`Source/OpenSim.Services.MuteListService/MuteListService.cs` 93–101) at `41f18f983b`. When the stored file's CRC equals the requested CRC and that CRC is 0, the service returns an empty array. The region treats an empty array as an empty mute list (`MuteListModule.cs` 178–181, `SendEmpytMuteList`). That needs a non-empty list whose CRC32 is 0 and a client CRC of 0, about once in 2^32.

**TB232.** `Source/OpenSim.Data.SQLite/Resources/MuteListStore.migrations` version 1, at `41f18f983b`, declares `PRIMARY KEY(AgentID)` on `MuteList`, with `UNIQUE (AgentID, MuteID, MuteName)` as well. The primary key admits one mute row per agent. MySQL uses a non-unique key on `AgentID` plus the triple unique key. PostgreSQL version 2 drops the agent primary key (TB34, already fixed, and P1.8 already says not to copy it). SQLite is still version 1. P1.8 owns this store. Phase 6 references the schema.

Two further viewer-visible behaviours, for the manager to number if the range has room:

- Zero-member groups leave zero-valued blocks in `DirGroupsReply`. `BasicSearchModule.cs` 223–251 sizes the array to `answer.Count` and copies only groups whose `members` count is greater than 0. The unfilled tail, zero id, empty name, 0 members, is sent when `queryStart` is 0 and at most 101 groups are kept, and when `queryStart` is greater than 0 but not less than the kept count. The second case falls through to the `else if (count > 101)` test with the full array (234–251). `DirGroupsReplyData` is a struct (`IClientAPI.cs` 549).
- OpenSearch places land for sale on a region that is not one of this process's scenes at grid 0, 0 (`OpenSearch.cs` 609–643). `located` starts true, and the 101 cap computed at 594–596 is never applied. The events map path does not cap its item count either.

Behaviour note, not a candidate for a new TB id: a mute name is written into the list file as stored, and a newline or a vertical bar changes how the line splits.

For the manager: with the call features at their defaults, a multiagent voice provision reaches the voice service without a check that the caller belongs to the call.
