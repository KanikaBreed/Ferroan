## 1. What Tranquillity does today

Tranquillity runs two engines in one region. The shipped ini selects Phlox. The code default, when the key is absent, is YEngine. They never both run one script. Neither is Linden's VM.

### Which engine runs a script

`Scene.DefaultScriptEngine` reads `[Startup] DefaultScriptEngine` and falls back to `"YEngine"` (`Scene.cs` 1076). The shipped file sets `DefaultScriptEngine = "InWorldz.Phlox"` (`RegionServerDefaults.ini` 319–325) and `ScriptEngineChoice = true` (334–336). `[YEngine] Enabled = true` (2409–2418). `[InWorldz.Phlox] Enabled` defaults to false in code (`PhloxEngine.cs` 252–258) and the shipped ini sets it true (2495–2505). Both engines are loaded. The ini default is the one a shipped region uses.

`Scene.ResolveScriptEngine` (`Scene.Inventory.cs` 108–202) places a script in this order:

1. A viewer compile target stored on the item, when some loaded engine's `AcceptsCompileTarget` returns true and no other engine holds saved state for that item and asset (111–128). The interface default is false (`IScriptEngineSelection.cs` 41). Phlox does not override it. YEngine does not implement the interface (`XMREngine.cs` 61). With no accepting engine, step 1 is skipped and the later steps apply. `GetDefaultScriptAsset` then drops the Lua subtype and serves the LSL default (`Scene.Inventory.cs` 211–231). `SetScriptEngine` with a Lua target returns `NotSwitched` (418–425).
2. An engine name saved on the item. `ScriptEngineChoices` uses 1 for YEngine and 2 for `InWorldz.Phlox` (the alias `Phlox` counts as the same engine).
3. A first line `//Name:` with a newline past index 5 and a colon at index 3 or later (146–164). `//YEngine:` selects YEngine when that engine is loaded. It is not a Phlox rule. Phlox also accepts the alias `//Phlox:` (`PhloxEngine.cs` 134–137, `PhloxEngineHeader.cs` 69–75). `ClaimsScript` on Phlox returns false (`PhloxEngine.cs` 139), so a body with no header is not claimed by content.
4. Saved state, the default engine first, then any other engine that has a row for the item and asset (177–188).
5. `ClaimsScript` (191–199).
6. Otherwise the default engine (201).

`EventManager.TriggerRezScript` tells every handler and skips an engine that is not an `IScriptEngineSelection` when the item carries a choice and the engine name is not the chosen one (`EventManager.cs` 1812–1849). Phlox's own `OnRezScript` (`PhloxEngine.cs` 789–830) runs the script when the region's chosen engine is Phlox, or, when the item carries no compile or engine choice, when the header resolves to Phlox. Otherwise it disowns the item.

The text a new LSL script gets is `Constants.DefaultScriptText` (`Constants.cs` 74): `llSay(0, "Script running")` inside `state_entry`. The same string is the asset `ScriptsAssetSet/DefaultScript.lsl` line 5, and the Lua default `DefaultLuaScript.Text` (`DefaultLuaScript.cs` 22–26) under `--!slua` as `ll.Say(0, "Script running")`. `Docs/PhloxSLua.md` shows `ll.Say(0, "Hello from SLua")` as an illustration. That string is not the shipped default. The first slice matches `"Script running"`.

### Threads, and how the region frame reaches scripts

The region heartbeat does not run script opcodes.

Phlox has one scheduler thread per region, `"PhloxMasterScheduler"`, priority from `[InWorldz.Phlox] SchedulerThreadPriority`, default `Lowest` (`PhloxEngine.cs` 69–78, 337–339; `PhloxMasterScheduler.cs` 46–72). The loop calls `PhloxExecutionScheduler.DoWork`, then `PhloxScriptLoader.DoWork`, then waits until the next sleep or timer wake (`Clock.Now`) or a signal (`PhloxMasterScheduler.cs` 105–160). `Clock.Now` is `(ulong)Environment.TickCount64` (`InWorldz.Phlox/Util/Clock.cs` 45–53). `EventManager.OnFrame` is subscribed only when the physics throttle is on, and only to sample physics milliseconds (`PhloxEngine.cs` 224–229, 486).

Beside that thread, Phlox starts:

- `"Phlox compile"`, one per engine, above.
- A service lane of up to `ServiceCallThreads` (default 4), idle exit `ServiceThreadIdleMs` 30000, deadline `ServiceCallTimeoutMs` 35000 (`PhloxExecutionScheduler.cs` 189–211, 248–253). `ServiceCallDeferral` defaults to `auto` in code (`PhloxEngine.cs` 328: inline when the answer is local or cached, deferred otherwise). The shipped ini leaves `ServiceCallDeferral = auto` commented out (`RegionServerDefaults.ini` 2571), so that code default stands.
- Long calls drained by `Task.Run`, cap `MAX_ASYNC_WORKERS = 6` (206–209, 3489–3493). Workers exit when the queue is empty.
- One process-wide `"PhloxAsyncCmdHandlerThread"` that sleeps 100 ms and polls HTTP, XML-RPC and sensor repeats (`AsyncCommand/AsyncCommandManager.cs` 61–62, 154–180, 203–226).
- `"PhloxStateManager"`, the SQLite flush thread (`StateManager.cs` around 229).

A deferred call is matched by `SyscallContext` sequence (`SyscallContext.cs` 65–75). The deadline wins or the worker wins. Both do not complete the same call.

YEngine's scripts are not OS threads. `NumThreadScriptWorkers` defaults to 2 (`XMREngine.cs` 207). Each worker is an OS thread running `RunScriptThread` (`XMRScriptThread.cs` 45–53, 100–206). One more thread, `"Yengine sleep"`, waits the sleep queue (`XMREngine.cs` 317, 1865–1916). `StartEx` and `ResumeEx` run the script on a worker (`XMRScriptUThread.cs` 42–81). `OnFrame` (`XMREngine.cs` 1665–1677, subscribed at 739) runs one-shot thunks only. Workers block on a wake lock. Each pass takes up to six start-queue scripts, then one yield-queue script. Lock order is the run lock, then the queue lock (`XMRInstMain.cs` 128–136).

Events arrive on scene subscriptions, not from the frame tick. Phlox subscribes in `PhloxEngine.cs`: chat from world, client and broadcast (1042–1072), `IWorldComm.OnMessageDelivered` (1100–1106), grab (1115–1156), `changed` (1216–1224), collider start, colliding and end (1229–1247), land collision (1292–1310), attach (1315–1322), moving start and end (1544–1555), at-target and not-at-target including rotation (1560–1585), money (1588–1613), `on_death` (1835–1850), damage (1871–1911), control (1958–1965). `PostObjectEvent` (1968–2043) queues for one prim and posts to every script in it. `PostScriptEvent` (1777–1797) maps the name through `SupportedEventList` and copies detect data. The timer wake is the scheduler, not `EventManager`: `CheckSleepingScripts` posts `timer` (`PhloxExecutionScheduler.cs` 1591–1596). `EventManager.TriggerTimerEvent` throws `NotImplementedException` (`EventManager.cs` 2924–2926). YEngine subscribes in `XMREvents.cs` 48–76.

`SupportedEventList.Events` (`InWorldz.Phlox/Types/SupportedEventList.cs` 22–71, signatures 73–405) is the Phlox event set, including touch, collision, land collision, listen, sensor, timer, link message, money, HTTP, dataserver, path update, damage and linkset data. `game_control` is compile-only (395–403). The enum value is the saved event's index, so appended names stay at the end. YEngine's names are `ScriptEventCode` (`MMRScriptEventCode.cs` 43–92), size 44, with gaps. Startup checks those names against the scene's event list and disables the engine on a mismatch (`XMREngine.cs` 224–240).

### Time slices

Phlox limits a slice by opcode count. `INSTRUCTION_FREQUENCY` is 48 `Tick` calls per `DoWork` pass. `SCRIPT_TIMESLICE` is 8 ticks per script (`PhloxExecutionScheduler.cs` 66–71, `DoTimeslices` 1406–1482). A `Stopwatch` records the slice for a decaying average and warns at `SLOW_THRESH_MS` 250. Those three constants are not config keys. The limit is the tick count. When 8 ticks finish, the cursor moves to the next run-queue node. `CheckRunstateChange` (1486–1512): `Sleeping` goes to the sleep heap, `Waiting` starts the next queued event or leaves the queue, `Syscall` and `Killed` leave the queue. Every timeslice calls `StateManager.ScriptChanged`.

YEngine limits a slice by wall time. `RunOne` stores `m_SliceStart` (`XMRInstRun.cs` 263–264). `CheckRunWork` returns at once when less than 60.0 ms has elapsed and throws `StackHibernateException` at the end of the slice (932–955). The 60 ms is a literal. There is no slice config key. The instance then goes on the tail of the yield queue. Most `ll*` calls are followed by a compiler-inserted `CheckRun` unless the name is in `noCheckRuns` or starts with `xmr` (`MMRScriptInlines.cs` 63–109, 199–204, 695–699).

Linden's executor limits a slice with a quanta clock. `QuantaClock` is monotonic seconds (`Executor/include/Luau/Executor.h` 83–87). `InterruptInstaller` (111–168) installs a safepoint interrupt by a deadline. The policy is `Resident` (the handler stays and checks the clock), `Threaded` (a watchdog thread inside the library, 156–171), or `Signal` (a POSIX timer signal, Linux only, else `Threaded`). `Default` becomes `Threaded` under an fflag. `HostCallbacks.interruptInstallPolicy` must be `Resident` when the quanta clock is not wall time (178–194). P4.3 uses `Resident`. `Threaded` starts a thread the library owns, and `Signal` installs a signal handler. Both conflict with [D6](../DECISIONS.md), which puts the SLua engine on its own thread and leaves signals to the process. P4.1b's shim calls `Executor`, and P4.3 uses its `Resident` policy, so the script thread checks the clock at the safepoint `Executor` installs. The engine rows do not rebuild that interrupt. Eight opcodes, 60 ms, and a quanta deadline are three different clocks. Section 4 treats slice length as a tolerance.

### Memory

Phlox's script account is `MemoryInfo.MAX_MEMORY` `0x20000` (128 KiB), not a config key (`InWorldz.Phlox/VM/MemoryInfo.cs` 26). `UseMemory`, an operand push, a stored replace and `AddCall` throw `VMException("Out of memory")` past that. The scheduler's tick catch calls `TerminateWithError` and takes the script off the run queue (`PhloxExecutionScheduler.cs` 1441–1452). `MemoryCalc.CalcSizeOf` (`Util/MemoryCalc.cs` 30–64) counts an int as 4, a float as 4, a string as 4 plus 2 per character, a vector as 12, a rotation as 16, and a list as its own size. Anything else counts as 0. The base charge is the bytecode length plus the constant pool (`CompiledScript.cs` 94–100), applied in the interpreter constructor (`Interpreter.cs` 105–109). This is the account `llGetUsedMemory` reads. It is not the .NET heap. `LSLTable` and `LSLList` each throw on their own size past `0x20000` (`LSLTable.cs` 176–200, `LSLList.cs` 88–95). `MemoryCalc` does not add a table into `MemInfo`. `llSetMemoryLimit` returns 1 only for 131072, otherwise 0. `llGetMemoryLimit` always returns 131072 (`LSLSystemAPI.cs` 3136–3142). `llScriptProfiler` and `llGetSPMaxMemory` are a peak field (3143–3159).

YEngine's heap defaults to `ScriptHeapSize` 1024 shifted left by 10, so 1,048,576 bytes, and the stack to 2048 shifted the same way (`XMREngine.cs` 218–219). Both are floored at 16384 (`XMRInstCtor.cs` 68–71). The counted bytes are locals plus array use (`XMRInstAbstract.cs` 493–523). Strings count `Length * 2`. An empty array costs 64 plus its keys and values. `UpdateLocalsHeapUse` throws `OutOfHeapException` over the limit. The handler sends an error that includes `OutOfHeap:` and `"Script must be Reset to re-enable."`, then sets the sleep-until to `DateTime.MaxValue` (`XMRInstRun.cs` 537–540, 554–613). Compiled `llGetFreeMemory` and `llGetUsedMemory` are `xmrHeapLeft` and `xmrHeapUsed` (`MMRScriptInlines.cs` 152–153, 588–618). The `LSL_Api` stubs that return the constant 65536 (`LSL_Api.cs` 7842–7846, 17968–17971) are not what a compiled YEngine script calls. `llSetMemoryLimit` on that API returns false (17956–17959).

Linden's default is the same 128 KiB figure and a different counter: `kDefaultMemoryLimit = 1024 * 128` (`Executor/include/Luau/Executor.h` 23–24). `Script::setMemoryLimit` is `Script.h` 182–183. `llGetFreeMemory` cannot be bit-identical across these three accounts. [SLUA_TRANQUILLITY.md](../SLUA_TRANQUILLITY.md) already leaves that open. [D10](../DECISIONS.md) runs Linden's VM, so the script-visible number is Linden's counter. Section 4 compares the other two as tolerances.

### Sleeps and delays

Phlox's `ScriptSleep` (`LSLSystemAPI.cs` 241–249) sets `NextWakeup` to `Clock.Now` plus the milliseconds and sets `RunState` to `Sleeping`, unless the call is inside a `SyscallContext`, in which case it adds the milliseconds to that context and does not change run state. `CheckSleepingScripts` (scheduler 1564–1589) moves due scripts back to the run queue. The master thread waits until the heap's earliest wake. Off-thread, `ProcessSyscallReturns` (3068–3077) sleeps `Clock.Now + Delay`, or, when the delay is 0, puts the script back on the run queue. There is no single delay table. Each method calls `ScriptSleep` itself.

### Events and the queue

Both engines cap a queue at 64. They count differently.

Phlox: `RuntimeState.MAX_EVENT_QUEUE_SIZE` is 64 (`RuntimeState.cs` 23). `QueueEvent` drops when `Count` is at 64, except `on_rez`, `state_entry`, `state_exit` and `timer`, which may pass the cap (477–501). The scheduler uses the same 64 as `MAX_EVENT_QUEUE_DEPTH` (`PhloxExecutionScheduler.cs` 74–75) and drops at 1815–1832. No handler means the event is dropped (1811–1813). A disabled script drops events except `state_entry` and `state_exit`, which stay queued (1767–1775). Order is FIFO. A duplicate no-change `control` is not queued while one already waits (1860–1864). An answer meant for another script (`AnswersOtherScript`) is dropped when the queue is at half, 32 (`OTHER_ANSWER_LIMIT` at 1877, checks at 1787 and 1822). `http_response` is dropped unless the HTTP plugin still owns the request key (`PhloxEngine.cs` 1973–1977). `TOUCH_INTERVAL` is 100 ms (scheduler 73).

`llMinEventDelay` (`LSLSystemAPI.cs` 2825–2832) is a floor between handler starts. Events inside the window are queued, not dropped. A heap wake delivers them (scheduler 3154–3185). A state change clears the queue, pending events and listens, then posts `state_exit` and `state_entry` (3082–3113). A timer is re-armed when the new state has `timer()`.

YEngine: `MAXEVENTQUEUE` is 64 (`XMRInstMain.cs` 81), counted per event code in `m_EventCounts`. `PostEvent` (`XMRInstRun.cs` 54–223): an unknown name returns false. `m_HaveEventHandlers` covers a handler in any state, not only the current one, and a missing handler returns false (59–60). A script that is not running returns true without queueing, except a suspended script with an empty queue accepts one `state_entry` at the front (70–82). While `llMinEventDelay` is above 0.001 s (`XMRInstMisc.cs` 307–320), these are dropped until the next event time: collision, land collision, listen, not-at-target, not-at-rot-target, no_sensor, sensor, timer, touch (86–105). `changed` whose mask is only scale, only position, or both is dropped inside that window (`return false`, 107–120). A second `timer` is dropped (127–132). Any other code is dropped when its own count is already 64 (136–137). `state_entry` goes to the front. An `attach` of `NULL_KEY` is inserted after existing `state_entry` and `attach` events and sets `m_DetachQuantum` to 100 (157–177).

The viewer event queue (`event.queue`, 256) and the viewer chat queue (`client.chat-queue`, 64) in [LIMITS.md](../LIMITS.md) are different caps. They are not the script queue.

### Detect parameters

`DetectParams` is `ScriptEngine.Shared/Helpers.cs` 95. Type flags: `AGENT` 1, `ACTIVE` 2, `PASSIVE` 4, `SCRIPTED` 8, `OS_NPC` `0x01000000` (97–101). Fields run through the touch face. Defaults are face −1 and touch ST and UV of (−1, −1, 0). `EventParams` is the same file at 323. Phlox stores `DetectVariables[]` on the posted event (`PostedEvent.cs` 22). `DetectVariables.cs` 46–312 adds `BotID` and a non-serialized `AdjustDamage`. `GetDetect` (`LSLSystemAPI.cs` 5196–5211) requires `0 <= n < DetectVars.Length`. Out of range, touch face is −1 and touch ST and UV are (−1, −1, 0). Other fields stay at their defaults. `iwDetectedBot` reads index 0 only (5254–5262).

Land collision, `changed`, attach, moving, targets, control, link message and email pass an empty array. A prim listen has null detect. A bot listen has one entry whose `BotID` is the bot (`PhloxListenManager.cs` 741–761).

YEngine sets `m_DetectParams` from the dequeued event and clears it when the handler returns (`XMRInstRun.cs` 392, 412–414). Filled: touch, one record (`XMREvents.cs` 164–180); `changed`, only when the parameter is a UUID, and then only the key (194–200); money, one record (90–93, 220–227); collision, one per collider (244–263); sensor, one per hit up to `SensorMaxResults` (`SensorRepeat.cs` 263–298). Empty: listen, land collision, timer, `no_sensor`, link message, control, email, at-target, attach, moving (`XMREvents.cs` 214–380, `LSL_Api.cs` 5824–5826, `ScriptTimer.cs` 139–141).

### Timers

Phlox `llSetTimerEvent` (`LSLSystemAPI.cs` 2786–2819) raises a positive interval to `MinTimerInterval`. Zero and negative stop the timer and are not raised. The code default is 0.1 s (`PhloxEngine.cs` 147, 160, 276). The ini key under `[InWorldz.Phlox]` is commented (`RegionServerDefaults.ini` 2516), so the shipped region uses 0.1. The scheduler stores milliseconds and arms the sleep heap (1231–1254). The next `timer()` is armed when that event is delivered. P4.6 follows this engine. The shipped ini selects Phlox.

YEngine keeps one `ScriptTimer` per script key (`ScriptTimer.cs` 75–106). `llSetTimerEvent` raises any non-zero interval below `m_MinTimerInterval`, and a negative value is non-zero, so `llSetTimerEvent(-1)` runs a timer at the floor (`LSL_Api.cs` 4079–4080). `SetTimerEvent` stops only when the interval is exactly 0 (`ScriptTimer.cs` 75–80). The floor's code default is 0.5 s (`LSL_Api.cs` 113, 518). The shipped `[YEngine] MinTimerInterval = 0.1` (`RegionServerDefaults.ini` 2469) overrides that, so a shipped region also uses 0.1. The code default of 0.5 applies only when the key is absent. `CheckTimerEvents` posts `"timer"` with an empty detect array and re-arms at that post (`ScriptTimer.cs` 122–145, the next interval at 143), which is when the timer fires, not when the script receives the event. The queue holds at most one timer. The async poll thread uses `[YEngine] AsyncLLCommandLoopms`, default 100, clamped to 25–250 (`AsyncCommandManager.cs` 179–182). These YEngine facts are recorded. They are not the evidence P4.6 compares against.

### Listen

Phlox `llListen` is `LSLSystemAPI.cs` 5324–5350. `PhloxListenManager` defaults are 20 events per second (0 or below means no rate limit), 65 listens per script and 1000 per region (`PhloxListenManager.cs` 69–77, 110–117). A per-script cap below 1 means unlimited (205). The shipped `[LL-Functions]` sets `max_listens_per_script = 64` and `max_listens_per_region = 1000` (`RegionServerDefaults.ini` 2159–2165). The rate key is commented, so 20 per second stands. Delivery (485–582) requires an active listener, the same channel, and a prim that is not the speaker (538). When the chat is ranged, distance is tested next (547–557), and then the name, key and message filters (560–574), ordinal-exact. Default ranges are whisper 10, say 20, shout 100 (180–182). Equality is outside the range (`>=` on the squared distance, 557). `PostListenEvent` (751–778) queues `listen` with channel, name, key and message. `listen` is not an overflow event, so it counts toward the 64.

YEngine `llListen` (`LSL_Api.cs` 1390–1397) calls `IWorldComm.Listen`. `WorldCommModule` uses the same ini keys. Its code default per script is 65 and per region 1000, and the shipped ini overrides the per-script cap to 64. `TryEnqueueMessage` (687–743) requires active, same channel, not the speaking prim, an id match when the filter id is not zero, and name and message compared with `InvariantCulture` unless the regex bit is set. Those filters run before the distance test. Empty name, empty message and `UUID.Zero` are wildcards. The queue is per event code, so listen drops when that code's count is already 64. `llMinEventDelay` can drop it as well. `WorldCommModule.AddRegion` (142–147) subscribes to client chat and broadcast. An object say reaches YEngine through `DeliverMessage` (404–436). Heard only when `maxDistanceSQ` is strictly greater than the squared distance (737), so the exact boundary is not heard. Ranges are stored already squared. The two script listeners agree: a speaker exactly at the range is not heard. P4.7 asserts that against both engines.

Chat ranges for viewers are the same 10, 20 and 100 (`ChatModule.cs` 47–49, 73–81; ini `[Chat]` 996–1007). `TrySendChatMessage` (418–460) drops whisper, say and shout when `maxDistSQ` is less than the squared distance, so the exact distance is still sent to the viewer (451). That viewer difference is pin behaviour to keep. It is not a script-listen tolerance.

Channel-0 say and shout use the same distance on both engines. Phlox `llSay` (`LSLSystemAPI.cs` 1539–1545) calls `HostSimChat` (670–677), which calls the string seven-argument `Scene.SimChat` (`Scene.PacketHandlers.cs` 114–118) with `fromAgent` false. The byte overload at 108–112 is the one YEngine calls. Both pass broadcast false and, because `fromAgent` is false, set `SenderObject` from the prim (`Scene.PacketHandlers.cs` 72–76), so the owner id viewers see is the prim's owner. The outcome of the two overloads is the same. `ChatToWorldComm` lets the other engine hear it, then `ChatSleep` runs. `llShout` (1547–1553) is the same call with `ChatTypeEnum.Shout`, so viewers use the 100 m test. YEngine `llSay` (`LSL_Api.cs` 1323–1325) also passes `fromAgent` false. YEngine `llShout` (1342–1345) passes true. That true is `fromAgent`, not a broadcast flag. The seven-argument overload still forces broadcast false, so the shout goes through `OnChatFromWorld` and the 100 m test, the same test Phlox uses. Only the nine-argument overload (51–86) can raise `OnChatBroadcast`. Because `fromAgent` is true, `SenderObject` stays null and `ChatModule.DeliverChatToAvatars` leaves `ownerID` at zero (243–252). On `DEBUG_CHANNEL`, including YEngine `llRegionSay(DEBUG_CHANNEL)` (1362–1365), `debugOwnerOnly` stays zero (288–291) and chat type 6 has no distance test (`maxDistSQ = -1`, 441), so that shout or region-say reaches every avatar. That zero owner id and that debug-channel reach are [TB159](../TRANQUILLITY_BUGS.md). Stage 2 decides whether to reproduce them. Shout reach is not a tolerance. `llRegionSay` on channel 0 is an error in both (`LSLSystemAPI.cs` 1607–1617, `LSL_Api.cs` 1351–1356). `ChatTypeEnum` (`OpenSim.Framework/ChatTypeEnum.cs` 30–42) is Whisper 0, Say 1, Shout 2, DebugChannel 6, Region 7, Owner 8, Direct 9, Broadcast `0xFF`. OpenMetaverse's `ChatType.RegionSay` is 255 and its comment says that value is not sent to the client (`AgentManager.cs` 199–221, the libopenmetaverse revision in [REFERENCES.md](../REFERENCES.md)). The hello compare uses Say, value 1. Region-say's packet type is a stage-2 reading of what `ChatModule` puts on the wire.

Script chat is cut in the script API, before `ChatModule`. Phlox cuts `llSay`, `llShout` and `llWhisper` to 1024 UTF-8 bytes and drops a multibyte character the cut would split (`LSLSystemAPI.cs` 1541–1582, `MaxChatBytes` at 1563, `CapUtf8Bytes` 1572–1581). `llRegionSayTo` uses the same byte cut (1650). `llRegionSay` is cut to 1024 characters (1564, 1614, `CapCharacters` 1584–1591). YEngine cuts `llWhisper`, `llSay`, `llShout` and `llRegionSay` with `Utils.StringToBytesNoTerm(text, 1023)` (`LSL_Api.cs` 1279, 1323, 1342, 1359). Listeners on either engine hear that already-cut text. `llOwnerSay` on Phlox sends its string through `SendChatMessage` (1594–1605) and does not call `CapChatBytes`. `ChatModule`'s cut from 1100 characters to 1000 (260–261) is how agent chat is shortened. A script's say, shout, whisper or region-say never reaches it.

`ChatFromSimulator` is built in `LLClientView.SendChatMessage` (1108–1152): reliable, low frequency, id 139. Body: from-name, source id, owner id, source type, chat type, audible, position, message via `StringToBytes1024`. `ChatSourceType` is System 0, Agent 1, Object 2 (`AgentManager.cs` 227–234). `ChatAudibleLevel.Fully` is 1. Object chat on `DEBUG_CHANNEL` (2147483647) is rewritten to chat type 6. When `SenderObject` is a part, that chat is sent only to the owner (`ChatModule.cs` 281–291). YEngine's debug-channel shout and region-say leave `SenderObject` null, which is the reach in TB159. The first hello compare is the object say on channel 0, where both engines pass `fromAgent` false and the owner id is the prim's. The owner-only debug path for a say is a later row.

### Script state

Three formats travel. They are not the same document.

**YEngine snapshot.** `GetExecutionState` (`XMRInstCapture.cs` 45–217) writes the `.state` file (209–215). The outer wrapper from `GetXMLState` (`XMREngine.cs` 1132–1167) is `<State Engine="YEngine" UUID Asset>`. The method's own comment (1128–1131) names Take, Take Copy and delete-to-trash as callers. The inner `<ScriptState>` carries Engine, Asset, SourceHash, `StateSchemaVersion` (constant 1, `XMRInstMain.cs` 167), `MigrationVersion` (byte 12, line 164), `GlobalsSignature` and `ApiFingerprint`. Children include the base64 snapshot, Running, DoGblInit, script time, minimum event delay, permissions, the detect array, the event queue, plugins, the experience key and heap use (capture 92–192). The binary snapshot is a version byte, an ignored byte 16, then `MigrateOut` (225–231). Detach waits up to 5 seconds (`m_DetachReady.WaitOne(5000)`). `LoadScriptState` (`XMRInstCtor.cs` 591–751) then `MigrateInEventHandler` (1374–1407) reads it back. An asset or source-hash mismatch throws and the script resets (633–643). `StrictStateMigrationVersion` defaults to false (`XMREngine.cs` 216). When it is false a version mismatch is best-effort. `SetXMLState` accepts `Engine="YEngine"` or `Engine="XEngine"` (`XMREngine.cs` 1172–1229).

On region remove, `DoMaintenance` writes a `.state` for every instance whose object is not an attachment (`XMREngine.cs` 700–702, 1970–1986). `OnShutdown` is empty (1695–1698). The maintenance timer defaults to 10 minutes (265–271). Removing a script deletes its `.state` file (1589–1592).

**Foreign `<Variables>` form.** When the inner `<ScriptState>` engine is not YEngine and a `<Variables>` child exists, `processXstate` (`XMRInstCtor.cs` 617–626, 800–1147) reads State, Running, ExperienceKey, Variables (name and type, matched to the compiler's global names), Queue, Plugins, Permissions and MinEventDelay. The branch is chosen on that inner element, at 621. The same child is read again at 890. Keys are stored as strings. It restores globals by name, the state, the running flag, the queue, plugins, permissions, the experience and the minimum delay. It forces global-init off, the current event to none, detect data null, and the extension arrays empty (1103–1124). There is no stack snapshot. A missing `<Variables>` when the engine is wrong throws. Elements the switch does not know are skipped. Nothing at Pin8 writes `<Variables>`. The only references are those two reads. `YEngine.SetXMLState` (`XMREngine.cs` 1172–1229) accepts an outer `<State>` only when `Engine` is `YEngine` or `XEngine`. A document that says anything else never reaches `processXstate`. A document Ferroan writes for this reader therefore says `<State Engine="XEngine">`. `PhloxEngine.SetXMLState` (1723–1762) returns false for every engine other than `InWorldz.Phlox`, so the shipped engine cannot load this form. This XML is the hypergrid form for a YEngine or XEngine destination. It is not the versioned LLSD portable format in [SLUA_TRANQUILLITY.md](../SLUA_TRANQUILLITY.md). That LLSD spec is not in Pin8. It waits on the C# work [D1](../DECISIONS.md) describes. A legacy `<ScriptState>` with no engine is rewritten as `<State Engine="XEngine">` in `SceneObjectPartInventory.RestoreSavedScriptState` (594–625). Object XML leaving Ferroan carries no `<GroupScriptStates>` until a C# reader of the LLSD form exists (P4.22). A document with `Engine="YEngine"` makes `SetXMLState` write the `.state` file and send the script to YEngine (`XMREngine.cs` 1196–1229). A `<Variables>` document is reached only after that method has accepted `Engine="XEngine"`. The writer usually cannot know the destination. Take stores an inventory asset any region may rez, and a crossing's engine is the receiver's default. Saved state (`Scene.Inventory.cs` 177–188) runs only when nothing earlier returned. Step 1, the compile target, comes first (115–128). A saved engine choice (135–142) or a `//Name:` header (146–164) returns only when that engine is loaded. A choice or header that names an engine that is not loaded falls through, and saved state can still place the script.

**Phlox state.** On disk this is protobuf-net `SerializedRuntimeState` in SQLite (`StateManager.cs` around 397–399 and 585). The table is `script_state` under `ScriptEngines/Phlox/state/`. The directory is not per region. `SerializedRuntimeState.cs` 21–80 holds the instruction pointer, LSL state, globals, operands, calls, the top frame, memory info, the event queue, run state, enabled, next wake, capture time, timer interval and last schedule, the running event, permissions, active listens and the start parameter. Halcyon databases are not imported. `StateRowMaxAgeDays` is 0.

[SLUA_TRANQUILLITY.md](../SLUA_TRANQUILLITY.md) defines a second document, the portable state: versioned LLSD, globals by name and LSL type, state name, running, the queue with detect data, the timer interval and time left, listens with their original handles, sensors, permissions, the experience key, the minimum event delay and the start parameter. **Luau thread.** This is not either of those documents. `Script::serializeState` (`Executor/src/Script.cpp` 664, `Script.h` 175) requires `!mInExecution` (666). ### Other limits a script can see

These sit beside the queue cap of 64 and the listen caps. Email has no second cap. The 20 s pause in the sleep table is the whole limit. Another script's dataserver answer is dropped at 32 (`OTHER_ANSWER_LIMIT`, section 1). The rest:

- `llHTTPRequest`. `HttpRequestModule` keeps a per-prim burst of 3 and a per-owner burst of 5 (`HttpRequestModule.cs` 75, 77). `CheckThrottle` (287–350) refuses the call when the bucket is empty. The ini keys are `PrimRequestsBurst` and `PrimOwnerRequestsBurst` under `[ScriptsHttpRequestModule]` (127–129). Phlox adds an in-flight cap while `[InWorldz.Phlox] HttpInFlightThrottle` is on, the default (`PhloxEngine.cs` 311; `Plugins/HttpRequest.cs` 172–189): 10 per object and 200 per region. A request past either cap returns `NULL_KEY` and does not start. P4.S5 carries both. P4.21's worker cap of 6 is the syscall lane, not this burst.
- Format strings and notecards. `[InWorldz.Phlox] NotecardThrottle` and `FormatStringThrottle` default to true (`PhloxEngine.cs` 308 and 310). P4.S1 carries the format-string switch. P4.S6 carries the notecard switch, beside the notecard pauses in the sleep table.
- Grab updates and touch repeat. On the way out of the queue, `FoldGrabUpdate` can turn a grab update into data on an event already waiting, and `CheckAndResetTouchWait` holds a repeated touch (`PhloxExecutionScheduler.cs` 1809–1812). P4.20 includes both.

### What the C# SLua work already replaces

Nothing of the VM. `Docs/PhloxSLua.md` describes SLua as Luau-flavoured source compiled onto the Phlox VM. LSL and SLua emit the same bytecode and share the scheduler and the state store. ## 3. What Ferroan has today, and the boundary

There is no `ferroan-scripting` crate. The workspace members stop at the crates that exist, and `unsafe_code = "forbid"` is the workspace lint (`Cargo.toml`). [ARCHITECTURE.md](../../ARCHITECTURE.md) already names the crate as the only caller of Linden's engine, in phase 4. [NOTICE.md](../../NOTICE.md) already names that engine.

The scene has no script state. [TESTING.md](../TESTING.md) says a loaded group has no script state, so the original XML form does not add one. No script event is posted. Collision contacts from Phase 3 stop at the scene (P3.18a).

The frame thread is `ferroan-scene`, spawned in `with_object_settings` (`crates/ferroan-scene/src/frame.rs` 354–388). `FRAME_TIME` is 0.0909 (96–98), the shipped ini value. The frame owns poses. A caller that needs an answer posts on the request channel and gets a `Pending` back. That channel is an unbounded `std::sync::mpsc` (`frame.rs` 363). Its only bound is one outstanding call per circuit (10–13). The oneshot is the reply, not the request. `chat_positions` (554–564) posts `Request::Places` and returns `Pending<HashMap<Uuid, [f32; 3]>>`. The frame copies each presence position and omits a missing agent (779–786). `ground` (444–449) is the same shape for a height. `Pending::wait` is async (162–166). The receiver inside `Pending` is private, and `blocking_wait` is `#[cfg(test)]` (168–172), so production code cannot call it. P4.1d adds a non-test blocking accessor on `ferroan-scene`. The script thread keeps one call in flight, which is what holds the channel's bound, and blocks on that accessor. It does not await on a tokio worker, and it does not call `blocking_wait`. Circuits post `AgentUpdate` on the bounded inbound queue (`SCENE_INBOUND` 256, lines 100–102) and do not wait.

Viewer chat is avatar-only. `crates/ferroan-client/src/chat.rs` says parcel hide, the god prefix, object chat and instant messages are not ported (35–37). `SOURCE_AGENT` is 1 (66). `publish` drops any channel other than 0 or `DEBUG_CHANNEL` (228). Say, whisper and shout use 10, 20 and 100 m (59–70). `DEBUG_CHANNEL` becomes chat type 6 and reaches every seated avatar with a pose, with no distance cap (45–47, 246–250). A message longer than 1100 UTF-16 code units is cut to 1000 (289–304). The packet sets source type to the agent constant, owner to the speaker, and audible to fully (the builder near 306–325). The outbound queue is 64 per viewer. A full queue drops the newest line and counts `client.chat-queue` ([LIMITS.md](../LIMITS.md)). The circuit accepts `ChatFromViewer` on channel 0 or `DEBUG_CHANNEL` and asks the frame for positions (`circuit.rs`). Nothing in that path has a prim name, an object source type, or an owner id taken from a prim.

### The boundary

`ferroan-scripting` owns the engine thread. That thread is the only caller of a given `IEnvironment` (`Executor.h` 200–202, [D6](../DECISIONS.md), [D8](../DECISIONS.md)). No other crate links the native library.

A host call that needs the scene posts a request on the frame's existing request channel, the way `chat_positions` and `ground` do, and the script thread blocks for the reply. It keeps one call in flight. It does not await on a tokio worker, and it does not call the test-only `blocking_wait`. The frame reads the part pose it already stores and returns it. The script thread does not read scene fields itself. The frame does not call into the VM.

Events the scene wants a script to see (touch, collision, chat, link message) cross onto the script thread through a bounded queue. The pin's cap is 64 on both engines, counted differently (section 1). The counting rule is Phlox's ([D124](../DECISIONS.md), Q1): one queue of 64, and `on_rez`, `state_entry`, `state_exit` and `timer` may pass it. `llMinEventDelay` queues. YEngine's per-code count is recorded and is not the pass rule. The viewer caps `event.queue` and `client.chat-queue` stay what they are. Script caps get their own [LIMITS.md](../LIMITS.md) ids when P4.18 lands. This plan does not add those ids.

Object chat for the hello slice adds source type Object (2, `AgentManager.cs` 227–234), the prim's name, the owner's id, and the prim pose from the frame. The message bytes are the API-cut text from section 1, applied before `chat.rs` shortens a viewer line from 1100 UTF-16 code units to 1000. Listeners hear the API-cut text. Channel 0 is what viewers see. A non-zero channel stays inside the script engine for listeners and is still dropped by `publish` on the way to a viewer. Owner-only `DEBUG_CHANNEL` object chat, for a say whose `SenderObject` is the prim, is a later row, after P4.1d. YEngine's debug-channel shout is [TB159](../TRANQUILLITY_BUGS.md).

## 4. Proving equivalence with C#

### The harness

The oracle is built on `Tests/InWorldz.Phlox.Tests/SchedulerHarness.cs`. That file puts a real `PhloxEngine` on a test scene, rezzes a script the way `OnRezScript` does, and pumps `DoWork` by hand, so a run is deterministic. The directory holds the harness and the test files that use it. The shipped ini selects Phlox, so the harness starts Phlox. YEngine is a second recording when a script that arrived on YEngine must match YEngine. The fifty-two `ll` names in section 2 are proven here, on Phlox, because `ILSL_Api` does not declare them. Rust runs the same source on the bound engine. The compare is return values, events in order, side effects on the scene, and the chat packet. Dropped events are part of the compare, not only the ones that arrive (P4.2).

The oracle has to run Tranquillity, so it is the kind of tool [D13](../DECISIONS.md) already allows once that decision names it. P4.19 is the row that asks for the edit and builds `tools/script-oracle` on this harness. It does not invent the id. Ordinary CI does not start it. The proof runner's PASS, DIVERGENCE and GAP buckets are not this harness. They grade Phlox's subset compiler against itself.

### What compares exactly

Integers, strings, keys, list element types, and the order of events for one script. Listen handles, as numbers a script stores in a global. Permission-denial text, once that row exists.

The hello packet, field for field, once the pose is the scene's pose: source type Object (2), chat type Say (1), audible Fully (1), the message bytes of `Script running` after the API cut in section 1, the prim name, the owner id, the source id, and the position. `llSay` passes `fromAgent` false on both engines, so the owner id is the prim's. The 15 ms Phlox throttle and YEngine's 12th-call sleep of 2000 ms are not part of that compare. Channel-0 shout uses the 100 m test on both engines. A YEngine shout's zero owner id is [TB159](../TRANQUILLITY_BUGS.md), not this packet.

### What needs a tolerance

- Floats in a script result. Compared as a named `libm` ulp, or as the integer a key or a handle actually is. A residual measured from Ferroan is not the tolerance. YEngine stores floats as doubles. Linden's LSL path uses 32-bit floats. That ulp compare is not the `<Variables>` document. A round trip of that document must not change a value a script can observe (Q8). A conversion that does is a failure of P4.13a, not a tolerance.
- Time slices. Phlox counts 8 opcodes. YEngine yields at 60 ms. Linden uses a quanta deadline. A test that needs a slice to end asserts that the script parked and resumed, not that the same opcode fell on the same millisecond.
- Timers. P4.6 follows Phlox, the shipped engine: zero and negative stop the timer, the shipped floor is 0.1 s, and the next arm is when the event is delivered. YEngine raises a negative interval to the floor and re-arms when the timer fires (`ScriptTimer.cs` 143). YEngine's code default floor is 0.5 s when the ini key is absent. The shipped key is 0.1. Wake time follows the scheduler's poll. The compare allows the poll interval of the engine under test. The YEngine facts are recorded and are not the pass rule.
- Function sleeps and the chat throttle. The two tables in section 1. The oracle is Phlox ([D124](../DECISIONS.md), Q2), including 15 ms after every throttled say and the `llHTTPRequest` sleeps. A row that implements a number cites both tables and compares against Phlox. YEngine's numbers are recorded and are not required to match.
- `llGetFreeMemory`. Phlox's `MemoryCalc`, YEngine's 1 MiB heap, and Luau's 128 KiB counter. The script-visible value is Linden's. The other two are recorded, not required to match.

### Script state, both ways

Two documents move script state, and they are not the same.

The `<Variables>` XML is the hypergrid form `processXstate` already reads (`XMRInstCtor.cs` 800–1147). The switch reads eight elements and no others: State, Running, ExperienceKey, Variables, Queue, Plugins, Permissions and MinEventDelay (881–1081). There is no start element. Nothing at Pin8 writes it. The fixture is a document that reader accepts: core OpenSim's XEngine form, which is not this pin, or a document built to the switch at 800–1147. The outer element says `<State Engine="XEngine">`, or YEngine's `SetXMLState` never sees it. Ferroan reads that document. YEngine's `processXstate` reads the document Ferroan wrote. The round trip is globals by name and type, state name, running, the queue with detect data, listens with their original handles, the timer interval and time left, sensors, permissions, the experience key and the minimum event delay. Timers, listens and sensors travel in the Plugins list (`ScriptEngine.Shared/Api/AsyncCommandManager.cs` 391–460, tags `listener`, `timer` and `sensor`). It is taken between events. A value a script can observe is unchanged (Q8). Keys stay keys. List element types stay. A float that becomes a different number, or a key the script can no longer tell from a string, fails the round trip. Phlox's `SetXMLState` refuses the document.

The versioned LLSD portable format in [SLUA_TRANQUILLITY.md](../SLUA_TRANQUILLITY.md) is a separate document. [PLAN.md](../PLAN.md) says Phlox state reaches Ferroan through the format the C# server writes. That spec is not in Pin8. P4.26 waits on it. P4.13a–P4.13d and P4.14 are the XML form, not the LLSD form.

A YEngine base64 snapshot is also in this phase. [PLAN.md](../PLAN.md) names YEngine snapshots in the Phase 4 sentence, and visitor state is still imported. P4.24a through P4.24e read one and P4.25a through P4.25c write one. `MigrateOut` writes globals by slot and writes no names (`XMRInstAbstract.cs` 1495). The names are `globalVarNames` from YEngine's compiler, and P4.24a ports that slot assignment. A snapshot can carry stack frames (1501–1506). P4.24c refuses a snapshot that has them, the way P4.15 refuses a Phlox envelope: the log names the item, and the script is not reset and is not started empty. Ferroan does not require that a visitor's snapshot was taken between events. A Phlox protobuf envelope is not either document. ### Risks

- Capture in the middle of an event. Both C# engines capture between slices. Phlox waits at most 10 seconds and then lets the object travel with no state. YEngine's detach waits 5 seconds. A compare of the portable fields uses a script that is between events. At region stop, P4.27 saves every script into the Luau payload once it is not inside an execute call. Host state travels in `serializeExtra`. A restart reads that payload, for a script that was between events and for one that was asleep inside a handler. P4.22 is not that resume.
- Two engines never both run one script at the pin. The harness must not start Phlox and YEngine on the same item and then average them.
- A script only YEngine can compile does not compile (P4.29, Q9, [D125](../DECISIONS.md)). It counts when Pin8 would route it to YEngine and `slua`'s compile refuses it. Routing is `ResolveScriptEngine` (`Scene.Inventory.cs` 115–164): step 1, the compile target (115–128), then a saved engine choice when that engine is loaded (135–142), then a `//Name:` header when that engine is loaded (146–164). A choice or header that names an engine that is not loaded falls through and does not count. The YEngine signals are a saved choice of YEngine, a `//YEngine:` header, and `yoption` or `yoptions;` (`MMRScriptTokenize.cs` 183–192). A compile failure with none of those is an ordinary error. The report is one `ferroan_diag` line, id `script.yengine-only`, naming the object, the item and the reason. The operator keeps that object on a C# region until it is ported.
- `iw*` and `bot*` are absent from YEngine. The twelve `os*` names in section 2 are absent from Phlox. Fifty-two `ll` names are on Phlox and absent from `ILSL_Api`, so a YEngine recording cannot cover them. Those `ll` names are proven on the Phlox harness. A single expected-output file cannot cover both engines for either set.
- Phlox SLua (`--!slua` compiled to Phlox bytecode) and Linden Luau are different compilers. The conformance suite is the one the gate names: the pinned `slua` tests, plus what [SLUA_TRANQUILLITY.md](../SLUA_TRANQUILLITY.md) S4 adds. The Phlox proof runner is not a substitute. The scripts under `tests/conformance/` do not carry their expected results. P4.28a1 through P4.28a5 and P4.28b do. P4.28a1 through P4.28a5 run on `Executor` through the shim. P4.28b is `slua`'s own file, unchanged, and it tests that build rather than Ferroan's host.
- A viewer compile target of `luau` or `lsl-luau` skips step 1 at the pin, and the later steps of `ResolveScriptEngine` still apply (section 1). No loaded engine accepts the target. `GetDefaultScriptAsset` drops the Lua subtype and serves the LSL default (`Scene.Inventory.cs` 211–231). `SetScriptEngine` with a Lua target returns `NotSwitched` (418–425). The region does not send the LSL-on-Lua flag (`Tests/OpenSim.Region.ClientStack.LindenCaps.Tests/Tests/LslOnLuauFlagNotSentTests.cs`). Ferroan does what that pin does (Q7). The harness does not treat the flag as a Phlox script.
- A `<Variables>` round trip that changes a value a script can observe fails P4.13a (Q8). The document is a compatibility format. A lossy conversion is not a tolerance. The ulp rule above is for script results, not for this document.
- An object XML file that contains `<GroupScriptStates>` can send the script to YEngine on a C# region (section 1, `XMREngine.cs` 1196–1229). Saved state (`Scene.Inventory.cs` 177–188) runs only when nothing earlier returned. Step 1 is the compile target (115–128). A saved engine choice (135–142) or a `//Name:` header (146–164) returns only when that engine is loaded. A choice or header that names an engine that is not loaded falls through, and saved state can still place the script. P4.22 writes no `<GroupScriptStates>` at all, because the writer usually cannot know the destination.
- An IAR rewrite drops `GroupScriptStates` (section 1). That drop is [TB161](../TRANQUILLITY_BUGS.md). A compare of archive load does not expect the state the archive carried.
- Phlox cannot load the `<Variables>` form. A document written for YEngine is not a Phlox resume.
- Listen handles must survive a save. A script that stored the handle in a global is the test, not a fresh `llListen` after load.
- The hello packet's position is only exact when both sides read the same pose. The frame is the source on the Rust side. The oracle records the pose it passed to `SimChat`.

## 6. Answers

Each label below is the id the rows cite. The list is not a Markdown numbered list, so a renderer cannot renumber it. Nothing here is still open.

YEngine snapshots stay in this phase, because [PLAN.md](../PLAN.md) already puts them there, and Phlox state arrives through the portable format the C# server writes. Both script engines ignore a speaker exactly at the listen range. Neither of those was a question.

**Q1. Event queue accounting.** Decided by the maintainer on 26 November 2026. [D124](../DECISIONS.md). Phlox is the reference: one queue of 64. `on_rez`, `state_entry`, `state_exit` and `timer` may pass it. Another script's answer is dropped at 32. `llMinEventDelay` queues. YEngine keeps 64 per event code, at most one `timer`, and drops a named set, including a scale or position `changed`, while the delay is in force. Those differences are recorded and are not reproduced. Rows: P4.2, P4.10, and the queue paragraph in section 3. The viewer caps in [LIMITS.md](../LIMITS.md) are not this queue.

**Q2. Sleeps and the chat throttle.** Decided by the maintainer on 26 November 2026. [D124](../DECISIONS.md). Phlox is the reference, including 15 ms after every throttled say and the `llHTTPRequest` sleeps in section 1. YEngine's window, the 12th-call sleep of 2000 ms (`LSL_Api.cs` 1287–1297, 1311–1315, 1335–1340), and a throttle refusal that returns `NULL_KEY` with no sleep (`LSL_Api.cs` 15110–15111) are recorded and are not reproduced. Rows: P4.9, P4.23, P4.S3, P4.S5, and the sleep paragraphs in sections 1 and 4. P4.1d does not wait on the 15 ms. Timer evidence was already Phlox.

**Q5. How the crate calls `slua`.** Decided by the maintainer on 26 November 2026. [D123](../DECISIONS.md). Option (b): a small C interface over Linden's executor, in `ferroan-scripting`, with a `SAFETY`-reviewed C boundary. The C++ shim is a [D13](../DECISIONS.md) exception. The reason is the cost of option (a), which was the earlier recommendation and is not the work. `Executor` is about 3,100 lines (`Executor/src` and its headers), not three pieces. Event dispatch (`Script::callEventHandler`, `Script.cpp` 333 onward) is a fourth piece and had no row. Parts of `Executor` read VM internals the C API does not expose: GC parking through `global_State::GCthreshold` and `luaC_step` (`Script.cpp` 293–316), and the unbreakable-depth test `L->unbreakable` and `nCcalls` (1120). The public substitutes are `luaSL_may_interrupt` (`llsl.h` 121) and `lua_gc` (`lua.h` 426). `luau_lsl_compile_asset` returns a `BytecodeHeader` plus bytecode, and that codec is C++ only (`Bytecode/include/Luau/BytecodeHeader.h` 16–40, `Bytecode/src/BytecodeHeader.cpp`, 70 lines, MIT). Under (a), P4.1c's compile step would include a Rust port of that header and its state-handler masks, and that row would be more than a day, so it would be split. Option (b) leaves the codec in the library. P4.1b and P4.1c are about a day each. The shim is GPL-3.0-or-later ([D4](../DECISIONS.md)) and links the MIT engine. The same C signatures could later serve the C# work [D1](../DECISIONS.md) describes. The GPL file does not go back into that tree. Option (c), waiting for that C# interface, is not taken: the interface is not in Pin8. Rows: P4.1b, P4.1c, P4.3, P4.27.

**Q6. The 85 `iw*` functions.** Decided by the maintainer on 26 November 2026. [D124](../DECISIONS.md) amends [D10](../DECISIONS.md). Stage 2 includes them, on the SLua `iw` table. P4.S27 is the family. `ls*` and `mod*` stay out under D10.

**Q7. Viewer compile targets.** Manager default, 26 November 2026. The maintainer may override. No decision id. Ferroan does what Pin8 does with the viewer's Lua and LSL-on-Lua targets: what it advertises and what it serves. No loaded engine accepts `luau` or `lsl-luau`, so step 1 of `ResolveScriptEngine` is skipped. `GetDefaultScriptAsset` drops the Lua subtype and serves the LSL default (`Scene.Inventory.cs` 211–231). `SetScriptEngine` with a Lua target returns `NotSwitched` (418–425). The region does not send the LSL-on-Lua flag. `Tests/OpenSim.Region.ClientStack.LindenCaps.Tests/Tests/LslOnLuauFlagNotSentTests.cs` is the evidence. The pin's only mention of `LuaScriptsEnabled` is a comment at `Scene.Inventory.cs` 206. Ferroan does not advertise that feature. Rows: the compile-target paragraph in section 1, and the risk bullet in section 4.

**Q8. `<Variables>` values.** Manager default, 26 November 2026. The maintainer may override. No decision id. A `<Variables>` round trip must not change any value a script can observe. The document is a compatibility format. A lossy conversion, including a double narrowed to 32 bits or a string substituted for a key when the script can tell, is a failure of the row. It is not a tolerance. The ulp rule in section 4 is for script results. Rows: P4.13a, P4.14, and the round-trip paragraph in section 4.

**Q9. A script only YEngine can compile.** Decided by the maintainer on 26 November 2026. [D125](../DECISIONS.md). Ferroan refuses it when Pin8 would route it to YEngine and `slua`'s compile refuses it. Routing is `Scene.Inventory.cs` 115–164, including step 1 and the not-loaded fall-through. The signals are a saved engine choice of YEngine, a `//YEngine:` header, and `yoption` or `yoptions;`. The report is one `ferroan_diag` line, id `script.yengine-only`, naming the object, the item and the reason. The operator keeps that object on a C# region until it is ported. P4.29 does this and can start now. P4.26 still waits on the C# LLSD spec and does not carry the refusal. Rows: P4.29, and the risk bullet in section 4.

The old question about OSSL with the shipped file omitted is answered by the pin, not left open. With the include removed, `[OSSL]` at `RegionServer.ini.example` 1373 still exists and is empty. `AllowOSFunctions` stays true (`OsslGate.cs` 94). A function with no `Allow_` or `Creators_` line uses the `VeryLow` threat test (96, 138–142, 208–212). With no `[OSSL]` section at all, the gate reads `[InWorldz.Phlox]` (93). The comment at 1375, which says the functions are disabled, is [TB160](../TRANQUILLITY_BUGS.md). P4.16 records that behaviour.
