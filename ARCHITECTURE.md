# Architecture

Ferroan is a Cargo workspace. Crates move from Planned to Implemented when their code lands.

The harness controller records launch intent and process identity before waiting for standalone, grid or asset startup, allowing `live down` to recover interrupted launches. Each grid region owns its SQLite files; published standalone databases and sidecars are excluded from its linked runtime tree. Rust executable paths come from Cargo artifact messages, including custom target directories. Grid and asset capture proxies bound replies at 70 seconds to cover C#'s 58-second event polls, skip interim responses, and explicitly close their single-exchange connections. A failed exchange fails the run; shutdown drains accepted exchanges before checking the result. Grid shutdown marks each server's proxies just before stopping it, so a request that reaches a stopped region afterwards (the C# neighbour's CloseAgent to home after the bot logs out of it) is kept and reported, not failed; the same errors while that server is meant to be up still fail. Bot return teleports require fresh region evidence; diagnostic log tails redact secrets before truncation. Shared harness construction, example copying, redaction and run-root helpers keep standalone and grid behavior aligned. The bot retains at most 4096 exhausted-send notifications for `Circuit::take_dropped`; when a caller does not drain them, the oldest notification is evicted. This notification bound does not change retry accounting or stop new sends.

Grid parity and root-arrival fixture generation requires the configured Tranquillity revision in the probe report and its short commit in the C# arrival packet. The standalone two-login comparator verifies retransmissions within each circuit before it normalizes fields across circuits.

The bot and region circuit share bounded sequence, duplicate-history and retry-window accounting in `ferroan-protocol::reliability`; each keeps its own ACK timing and retry policy. The region starts at a 1000 ms retransmission timeout, samples ping round trips using C#'s filter, and retains unacked packets until ACK or circuit inactivity. Defaults are 60 seconds of silence, or 300 seconds while paused; active traffic can keep a circuit alive indefinitely. The bot retains its count-limited retry policy. The region's immediate `UseCircuitCode` ACK has sequence zero; established ACKs use ordinary sequence numbers. Its handshake announces configured region name/type/owner and typed region settings matching C#'s fresh-region defaults. A valid `CompleteAgentMovement` triggers reliable `AgentMovementComplete`, using the accepted login position and region identity. Bot readiness requires a fresh arrival on the current circuit alongside handshake and seed completion. Terrain adjustment remains planned. Datagram errors do not tear down the listener. Same-agent re-login cancels the old serving future and replaces its generation-scoped CAPS lease; a different agent still encounters the one-login bound. Logout sends C#'s reliable, zero-coded reply without waiting for an ACK.

Ferrobot is the external second test client from [D17](docs/DECISIONS.md). The harness builds its pinned revision in scratch, starts it with isolated test credentials, drives its signed loopback HTTP API, and records region UDP and HTTP. Its dedicated standalone and grid scenarios require fresh arrival, a 120-second session with ping replies and completed event-queue polls, chat both ways, an incoming IM and SIGTERM logout. The Ferroan-region variant checks arrival, the session and logout; chat and IM remain pending. Ferrobot is tracked for interrupted-run cleanup and is not a dependency of any Ferroan crate. Validation results are recorded in [TASKS.md](TASKS.md).

`cargo xtask live up grid --region ferroan` leaves C# Robust and the C# neighbour
running with the Ferroan home region for informal viewer checks. It uses direct
listeners rather than capture proxies, defaults to loopback, and retains the
same process identity records for `live down` and interrupted-launch recovery.
The CI smoke check starts this command, uses its printed login URL for two
strict bot sessions, and verifies process and listener cleanup after shutdown.
It runs in the grid services job. Region traffic and asset backends run on two
other hosted runners, each with its own port block and scratch tree. The
[required live check](docs/LIVE.md#what-ci-runs) depends on all three.

Limit hits and handled errors go through one helper in `ferroan-diag`. Each report names a stable id, whether the bound is soft or hard, the configured and observed values, and the action taken. The counter uses that id directly. Soft queues warn once at 80 percent. The first hit in a minute is logged on `ferroan::limit`; later hits in that minute are counted and then summarised. `ferroan_limit_hits_total` is appended to the region and Robust metrics pages. A 1000-line ring, `diag dump`, `GET /diag` and `cargo xtask live diag` show the recent warnings, and a panic hook writes that snapshot before exit. The ids and the pin comparison are in [docs/LIMITS.md](docs/LIMITS.md).

XAsset metadata ids can share one immutable data row. MySQL checks its content
hash before the write transaction, then commits the metadata if another store
has already inserted the same hash. This also works under MariaDB snapshot
isolation with SELECT and INSERT on the data table ([D43](docs/DECISIONS.md)).

The grid harness captures riderless object crossings on two separate C# simulators. Each viewer edits the linkset from its own circuit. The [object-crossing fixtures](fixtures/object-cross/README.md) correlate the local IDs in the outbound XML with the viewer packets on the sending region.

`ferroan-scene` writes coalesced inventory assets as ordered original-format linksets. The wrapper records the combined world bounds and each root's offset from the minimum. The member reader follows `TryFromXml` and restores positions from the parts. Rez must also parse the wrapper sizes and offsets and refuse invalid values, as `GetObjectsToRez` does (3185–3208). The member reader alone cannot place these groups for rez. Crossings carry the source inventory item UUID separately in `ExtraFromItemID`.

The region configuration supplies a read-only Groups V2 remote connector for parcel decisions. One lookup returns the viewer's complete group IDs and their unsigned power masks, including memberships with zero powers. Overlay delivery consumes it in Q60c3.

The parcel arrival harness correlates the region's Land datagrams with its initial-data log and seed exchange on each circuit. The [Pin8 recording](fixtures/parcel-timing/README.md) supplies the timing reference for Q60c3.

## Where code comes from

The grid harness schedules scenarios individually and waits for bounded
GridUser/Presence logout state between them. This separates receipt of the
viewer's LogoutReply from completion of asynchronous service cleanup before
the account is reused; standalone scenario scheduling is unchanged.

Revisions are pinned in [REFERENCES.md](docs/REFERENCES.md). The template differences are listed in [docs/PROTOCOL.md](docs/PROTOCOL.md).

## Vectors and quaternions

`ferroan-types` stores vectors and quaternions as `glam` 0.34 values (`Vec2`, `Vec3`, `DVec3`, `Vec4`, `Quat`), the same major version Aurora's `aurora-prim` uses. A `glam` value is not copied onto the wire: each field is written little-endian, which is what OpenMetaverse's `GetBytes` does. `Color4` is a plain struct. Its packet form is four quantized bytes, not a vector.

## Rules that shape the code

- **Wire compatibility.** Every crate that talks to the outside speaks exactly what the C# server speaks, so Rust and C# pieces can share a grid ([D2](docs/DECISIONS.md)).
- **Unsafe code in two places.** The workspace forbids unsafe code; only `ferroan-physics` and `ferroan-scripting` will be allowed it, each wrapping one native library.
- **Threads.** tokio runs networking and services. The region frame loop, Jolt and the SLua engine each get their own thread ([D6](docs/DECISIONS.md)). Linden's engine requires that each VM environment be used by one thread at a time.
- **No plug-in loading.** Region modules are compiled in. Third-party C# modules cannot load into Ferroan.
