# Region store oracle

A .NET 10 console program that loads one region's prims from a SQLite, MySQL or PostgreSQL region store through the pinned region store. Rust tests compare those groups. The program is a C# exception in [D13](../../docs/DECISIONS.md): it has to run Tranquillity's own types. Nothing from that checkout is copied into this repository.

`cargo xtask regionstore generate` builds it against a task-owned clone of the pin and writes [fixtures/regionstore/objects.db](../../fixtures/regionstore/objects.db) and [objects.json](../../fixtures/regionstore/objects.json). `cargo xtask regionstore settings` writes [settings.db](../../fixtures/regionstore/settings.db) and [settings.json](../../fixtures/regionstore/settings.json). `cargo xtask regionstore serialize` writes [objects-xml.json](../../fixtures/regionstore/objects-xml.json), XML2 and original XML for each group in the object fixture. `cargo xtask regionstore read` reads that file back through the pin and writes [objects-xml-read.json](../../fixtures/regionstore/objects-xml-read.json), including one part with an unknown element. The oracle command `probe <probe-json> <pin>` reads the review probes and writes [objects-xml-probes.json](../../fixtures/regionstore/objects-xml-probes.json). `cargo xtask regionstore verify` rebuilds it and reloads the object file, and the settings reload runs with the other `regionstore_` tests. `cargo xtask regionstore cross` rebuilds it, reloads the SQLite fixture, starts a throwaway MySQL container, runs `mysql-seed` and `mysql-load`, compares stdout with [objects-mysql.json](../../fixtures/regionstore/objects-mysql.json), starts a throwaway PostgreSQL container, runs `postgres-seed` and `postgres-load`, compares stdout with [objects-postgres.json](../../fixtures/regionstore/objects-postgres.json), runs the gated `regionstore_` tests, and removes both containers. Build products go under `.scratch/regionstore-oracle/`, not into the reference checkout. The commands need the .NET SDK and the pin checkout. They do not start a server or the live harness. Ordinary tests replay the committed SQLite dump and do not start the oracle or Docker.

```sh
cargo xtask regionstore generate
cargo xtask regionstore settings
cargo xtask regionstore serialize
cargo xtask regionstore coalesced
cargo xtask regionstore verify
cargo xtask regionstore cross
```

`seed <db>` creates the file and inserts the fixture rows. `load <db> <region-uuid> <pin>` writes one JSON object to stdout and records that pin. `settings-seed <db>` creates a RegionStore 48 file and inserts one `regionsettings` row and two spawn points. `settings-load <db> <region-uuid> <pin>` writes that region's handshake fields, the other loaded settings, and the spawn points. `terrain-load <db> <region-uuid> <pin>` loads the `terrain` and `bakedterrain` rows through the pin's `LoadTerrain` and `LoadBakedTerrain` for a 256 m region and writes, for each, the cells as float bits (Y outer, X inner), the stored revision and size, and whether the pin's own `GetDatabaseBlob` of that map gives the stored bytes. `regionstore_terrain_rows_load_in_csharp` (run by `verify` and `cross`) gives it a store whose rows Ferroan wrote. `mysql-terrain-load <ado> <region-uuid> <pin>` and `postgres-terrain-load <ado> <region-uuid> <pin>` write the same dump through `MySQLSimulationData` and `PGSQLSimulationData`. `mysql-terrain-seed <ado> <region-uuid>` and `postgres-terrain-seed <ado> <region-uuid>` store a new 256 m `pinhead-island` with that backend's own `StoreTerrain` and `StoreBakedTerrain` (MySQL's fire-and-forget store runs inline). `cross` runs `regionstore_mysql_terrain_matches_the_pin`, `regionstore_mysql_baked_terrain_is_the_last_row` and `regionstore_postgres_terrain_matches_the_pin` against its containers. `serialize <db> <region-uuid> <pin>` writes one JSON object whose groups carry that pin's XML2 and original XML. A loaded group has no script state, so the original form does not add one. The writer probe captures special characters, all extra-param kinds, nondefault sit flags and double-format sound gains. The settings probe observes the empty PBR set at the scene save callback and compares cache ids across two SQLite plugin instances. The `fixed_sun` property in the settings dump stays false. `fixed_sun_column` is the stored cell. `mysql-seed <ado>` migrates a MySQL region store to version 71 and inserts the same rows, plus one prim whose nullable columns are NULL and one orphan child. `mysql-load <ado> <region-uuid> <pin>` writes that region's groups. The MySQL seed stores the zero id where the SQLite seed stores an experience id that does not parse, and it omits the prim whose dynamic attributes are not a map and the row whose id is not a UUID. Either of those rows stops the MySQL load. `postgres-seed <ado>` migrates a PostgreSQL region store to version 62 and inserts the same rows, plus one linkset whose root id differs from the group id. `postgres-load <ado> <region-uuid> <pin>` writes that region's groups. The PostgreSQL seed stores the zero id in the experience uuid column and stores false for an omitted pass-collisions cell. A null required number or text, an inventory row that cannot be built, and a dynamic-attribute document whose top value is an integer each stop the PostgreSQL load, so the seed omits them. `cross` names the MySQL container `ferroan-regionstore-mysql-<base>` on `127.0.0.1:<base>` and the PostgreSQL container `ferroan-regionstore-postgres-<base>` on `127.0.0.1:<base plus 1>`. `<base>` is `FERROAN_LIVE_PORT_BASE` when that value is a port at or above 1024 with room for the next port, and otherwise a port taken from the process id. `cross` removes both containers it starts. `bulk <db> <region-uuid> <count>` creates a store of that many single-prim groups, with no shape row, for a memory measurement. `cargo xtask regionstore bulk` runs it. It does not start a server. A row that cannot be built is absent. Texture entries and extra params of a stored shape stay the stored bytes. The eight structured payloads are dumped both as the stored cell and as the value the load produced. An animation sequence number is a clock and is absent. Each part's `items` list is the task inventory the load restored, in stored order, including an empty list. A null description is an empty string. The creator field is the identification string the load stores. An experience id that does not parse is the zero id. Items stay data.

`cargo xtask regionstore prim-seed` runs `prim-seed <db> <region-uuid> <owner-uuid>`. It persists the Q65a linkset and tree plus Q65b's rotated vegetation, particle emitter, looping sound and animated mesh through Pin8 `SQLiteSimulationData.StoreObject` in a fresh scratch database. The [prim capture guide](../../fixtures/prim-updates/README.md) describes reopening it on C#.

`coalesced <xml-dump> <pin>` reads two of the original-format groups in the serializer dump. It gives the linked root and child distinct rotations and positions, then records the coalesced XML, the result of reading it back, and the extra-field probes from `SceneObjectGroup`. The capture uses the source inventory item UUID separately from the embedded original XML.
