# Live harness

`cargo xtask live run login grid --region ferroan` uses the Rust home-region process with C# Robust and a C# neighbour. It requires fresh arrival and an actual `LogoutReply`, and compares registration and agent-creation traffic with the C# fixtures. The dedicated login baseline disables map generation in both implementations. The CAPS probe and Ferrobot login/session/logout subset also support the Rust home region; other scenario behavior uses C# regions. `cargo xtask live run uploads grid --region ferroan` logs both harness accounts into the Ferroan home region together. Each uploads one texture and fetches those bytes back. The pass line is `uploads: pass (N bytes, two avatars)`. It is a dedicated scenario, so `all` leaves it out. The same run compares both accounts' QueryAccess and CreateAgent replies with the C# login fixtures. `cargo xtask live login-fixtures <capture-dir>` extracts scrubbed control-plane fixtures from a local C# login run. See [the region guide](../../crates/ferroan-region/README.md) for the current limits.

`cargo xtask live build` builds Tranquillity in `.scratch/live/`; `cargo xtask live up` or `cargo xtask live run <scenario>` starts it. The scratch tree is never a reference checkout.

The shared reference is KanikaBreed/OpenSim-Tranquillity `dev-build` at Pin8 `c401bceecd1684832ae8ba86a31b5ee01a4ded7b`. It can supply the scratch build without `FERROAN_REF`; that variable selects an alternate clean reference root. The exact repository and pin remain in [docs/REFERENCES.md](../../docs/REFERENCES.md).

`live build` also builds pinned Ferrobot with `cargo build --locked` in `.scratch/`, using a clean matching `FERROAN_REF/Ferrobot` checkout as the source of a scratch clone when available, otherwise the public repository. `live run ferrobot`, `live run ferrobot grid` and `live run ferrobot grid --region ferroan` drive that separate client through its signed loopback HTTP API. Each checks fresh arrival, 120 seconds with captured ping replies and completed event polls, and matching captured `LogoutRequest`/`LogoutReply` after SIGTERM, with no server-log fallback. C# runs also check chat both ways and IM with `ferroan-bot`; Rust chat and IM remain pending. Generated account credentials and the API secret stay in private scratch files. See [the Ferrobot checks](../../docs/LIVE.md#ferrobot).

One patch is applied only to the Tranquillity scratch tree, at the revision in [docs/REFERENCES.md](../../docs/REFERENCES.md):

- [../capture/tranquillity-capture.patch](../capture/tranquillity-capture.patch) records raw UDP when `[ClientStack.LindenUDP] CaptureFile` is set. `live build` applies it. `live run` sets `CaptureFile`, records the bot's HTTP beside it, then runs `check`, `redact` and `replay`. `live up` does not set `CaptureFile`. The same patch adds `ServiceProbeConnectorModule`, off unless `[ClientStack.LindenUDP] ServiceProbe` is true. Standalone harness inis set that, including `live up`, so the region HTTP server hosts the in-process Presence and GridUser handlers the login probe reads. Grid inis leave it unset. The pin checkout is not modified.

Ferrobot's HTTP is captured by proxies, including a standalone region proxy. C# records its UDP through the same patch; the Rust-region run uses a bounded loopback UDP relay. Both paths preserve the raw datagrams for `check`, then `redact` and `replay`. Ferrobot's process identity is saved for interrupted-run cleanup with `live down`.

The region ini normally sets `[Network] bind_ip_address = "127.0.0.1"`; proxied runs bind the server to another loopback address and advertise the proxy. An empty value means every interface, which is Tranquillity's default. The harness does not alter SQLite. At this pin, `UserAccount.migrations` version 4 adds `DisplayName` and `NameChanged`, and the region is started once. The manual recipe is in [docs/LIVE.md](../../docs/LIVE.md).

`live build` also publishes GridServer, self-contained, because that project references `Microsoft.AspNetCore.App` and the harness machine has only `Microsoft.NETCore.App`. `cargo xtask live compare assets` starts that server, and `ferroan-robust`, behind `ferroan-capture http-proxy`, and compares the texture and inventory HTTP. `cargo xtask live assets` is the same comparison. `cargo xtask live compare accounts` starts that server with only the user-account connector, and `ferroan-robust`, and compares the account HTTP directly. `cargo xtask live accounts` is that same comparison. `cargo xtask live compare auth` compares authentication HTTP the same way, and `cargo xtask live auth` is that comparison. `cargo xtask live run assets grid --rust assets` points both regions' `AssetServerURI` at `ferroan-robust` on `127.0.0.1` and leaves the other Robust services in C#. `cargo xtask live run login grid --rust accounts` points `UserAccountServerURI` and Robust login's account connector at that process, on a separate UserAccount file. `cargo xtask live run login grid --rust auth` points `AuthenticationServerURI` at that process. Robust login stays on `PasswordAuthenticationService` and opens the same AuthStore file. `--rust assets,accounts` serves both. Its C# asset-service ini sets `[Network] bind_ip_address = "127.0.0.1"`, so the service passes the loopback socket check.

`cargo xtask live up --assets ferroan` prepares a seeded copy of the asset store, starts `ferroan-robust`, and starts the C# region with the same `Include-Asset` override used by the comparison. Both stay up, with the login URL and region and asset ports printed. `cargo xtask live run assets --running` drives texture and inventory against that existing region, reads the generated password privately, and leaves both processes running. `cargo xtask live down` stops both. This is the setup for [the G0 viewer check](../../docs/MANUAL_CHECKS.md).

`cargo xtask live run <scenario>|all` starts that region in the foreground with `--console basic` (the default `local` console reads keys and rejects a pipe, and the option is applied after the ini). After logins are enabled it creates the second account `Chat Bot` on that console, runs the bot scenarios, and stops the region it started. It refuses to run when a region from `live up` is already up; the explicit `live run assets --running` check uses that region instead and needs no second account. The chat password stays in memory. `live up` does not create the second account. `cargo xtask live record-twice` runs standalone `login` twice and compares those UDP captures per message type.

`cargo xtask live run <scenario>|all|neighbour grid` starts GridServer and two regions. Accounts are created on the Robust console before the regions start, because a grid region cannot create the estate owner itself. The regions are `--background`. Their HTTP listeners are on `127.0.0.2` and `127.0.0.3`. Proxies on `127.0.0.1` record region-to-Robust and region-to-region HTTP. The bot logs in on Robust's address, `127.0.0.4`. Home-region UDP is the only datagram capture. The guide is [docs/LIVE.md](../../docs/LIVE.md).
