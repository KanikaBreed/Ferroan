# OAR parcel fixtures

Run `cargo xtask oar-parcels generate` to write [parcels.json](../../fixtures/oar-parcels/parcels.json). Run `cargo xtask oar-parcels verify` to repeat the observations and require the same file. The runner builds the pinned `OpenSim.Region.CoreModules` from a clean scratch checkout at the revision in [REFERENCES.md](../../docs/REFERENCES.md). It does not start a region. A run takes about three minutes, two of them the 60-second stalls of the `bad-last-value` and `bad-environment` cases (TB203).

The oracle writes most parcel files with `LandDataSerializer.Serialize` and stores their text in the fixture. Each case passes its files, in order, to the private `ArchiveReadRequest.LoadParcels` by reflection, which reads them with `LandDataSerializer.Deserialize`. The request is built with the console constructor on an empty file, with the four options the console always passes (`displacement`, `rotation`, `bounding-origin`, `bounding-size`) and, for the merge cases, `merge` and `merge-parcels`. The process runs in the region server's culture, `en-US` (`Culture.SetCurrentCulture`).

The scene's `LandChannel` is a stand-in: `AllParcels` answers the merge cases' region parcels as `LandObject`s, and `Clear` records its argument. The fixture records what `LoadParcels` hands `TriggerIncomingLandDataFromStorage`: every field of each `LandData`, its bitmap in base64 and its access list. A global id that is neither a file's nor a region parcel's is recorded as `random`. The user account service holds `users` in `scope`, and the groups module holds `groups`; each call is logged in order. A case without a groups module does not register one. An exception is recorded by its type name.

The files are a parcel owned by an account with access entries for an account, a stranger and the zero id; parcels owned by a stranger with an unknown group, by a group, by an unknown group and by nobody; a parcel with no land; a hand-written file with an XML declaration, a comment, unknown elements, `Dwell`, no `GlobalID`, values in every conversion's edge forms (spaces, signs, `-0`, a thousands separator, a 32-digit id with leading spaces, an upper-case id, overflow, `0x`, a bad vector, `true` for a `"1"` flag), a line-wrapped bitmap, empty and start-and-end access entries and a bad environment; a parcel with an environment; a 128-cell bitmap from a 512 m region; a one-byte bitmap; a bitmap with bits past its square; a file whose root is not `LandData`; ten bad values before and at the end; and the four TB203 inputs, among them a serializer-written file whose last element is an `Environment` Pin8 cannot read.

The 24 cases are the default, a displacement out of the region and a negative one, turns of 90, 180, −90, 45 and −30 degrees, a bounding box clipped to the region, a small bounding box with a displacement, a 512 m region, a merge with three region parcels (one trimmed, two covered), a merge whose parcel has no land, no groups module, a zero estate owner, no parcel files, only a parcel with no land, a file that is not `LandData`, the two ten-error files, and the four TB203 files.

The scene test `every_parcel_load_matches_pin8` reads the same files with Ferroan's `load_parcels` and compares every parcel, the clear, the kept count and the call list. In the four TB203 cases Ferroan reads the file as the `local` file it was made from, the unreadable environment cleared (D139), and the test checks that Pin8 still differs.
